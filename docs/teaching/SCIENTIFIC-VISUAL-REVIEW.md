## Visual contracts

**NumPy shape comparison.** Question: does the same output shape mean the same organization? Example: the existing (3,2) Celsius array `[18,20,24,26,30,32]`. Columns/rows encode coordinates; amber/solid and green/dashed cells track sensors, with text labels independent of color. Read the source top-to-bottom, then compare the two output branches; mobile stacks the branches. Interpret 24 at transpose [0,1] versus reshape [0,2]. Limits: logical C-order regrouping and axis swapping, not physical memory movement or arbitrary reshape copy decisions. No controls are needed because the value of this figure is simultaneous comparison while reading.

**CSV boundary comparison.** Question: which commas separate fields? One exact source record is displayed above correct parsed fields and naive split fragments. Boundaries/field boxes expose the difference; strings and quote fragments are shown as actual characters rather than escaped programming-language representations. The caption distinguishes CSV structural quotes from the surviving room comma, and parsing from numeric conversion. Limits: one fixed ordinary CSV dialect/record, not a general parser or decoding demonstration. Existing parser practice supplies native execution.

**File publication artifacts.** Question: what can a fresh reader open while an update is incomplete? Existing local-file state produces the record-slot pictures and exact text simultaneously. Destination/staging names, 001/002, old 18/20 and new 22/24, absent file, empty file, one-record prefix and complete content remain distinct. Predict, change strategy/outcome, step/back/reset, inspect exact text, repeat the same failure. Slot counts describe this two-record fixture, not validation for arbitrary CSV. Existing limitations for power loss, open handles, multiple writers and remote storage remain visible.

**SQL relations.** Question: why can A repeat in readings but not in sensors? Sensor entities occupy the left; observation entities branch on the right; arrows refer back by sensor_id. IDs, minute and Celsius/NULL are readable. Separate sensor and reading keys are named before this picture. B has a source row with unknown value; C has no source observation row. Limits: a logical relation illustration, not an execution-order/physical query plan, history model or general database engine simulation. The later join lab explores transformations, so extra controls here would duplicate it.

**Pandas pivot inspector.** Starting state: the four existing region/month amounts, unique cells, ordinary pivot and North/Jan selected. Question/prediction: where does each source record land, and what if another wants the same address? Controls: three source variations, pivot/sum/mean, four output-cell buttons and reset. Input changes apply immediately; selected cell, linked row IDs, output, source count, blocked state and equation come from one bounded model. A duplicate selects North/Jan; the missing case selects South/Feb so the changed cell is visible. Investigate sum=20 versus mean=10 for duplicated North/Jan, then the unknown South/Feb cell. Exact values/text and aria-pressed accompany visual highlighting. Limits: fixed numeric fixtures, explicit region/month ordering, no arbitrary Pandas runtime or general missing-value aggregation. A blocked pivot shows requested coordinates and sources, not a partial computed table. Practice and native program follow the lab.

**Matplotlib ownership.** Question: which object do I manipulate or save? Nesting encodes containment, not time or measured magnitude. Side-specific x/y objects and a drawable line schematic provide a visual vocabulary for the similarly named API classes. The caption supplies the broader Artist inheritance relationship and distinguishes panel operations from whole-Figure saving. No numeric axes or invented measurements are shown. This is a static API ownership schematic; the next lab separately teaches quantitative coordinate mapping.
