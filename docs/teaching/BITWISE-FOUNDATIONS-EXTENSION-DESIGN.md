## Teaching progression and exact contracts

1. **A small set can be stored as places in an integer.** Begin with six experiment flags labelled0…5 and the set{0,2,5}; its mask is1+4+32=37, displayed100101 with bit0on the right. Unlike an ordinary list of values, one bit records presence, not order or frequency. Explain nonnegative binary place values with an actual sum before symbols. Define a finite universe of width w, full mask `(1 << w)-1`, empty0 and membership `(mask & (1 << i)) != 0`. A bitset uses w logical bits; a Python integer still has object/limb overhead. A sparse huge universe may favor a hash set. No memory/time benchmark claim.

2. **Derive operations one bit at a time.** The four pairs00,01,10,11 define AND, OR and XOR; link them to intersection, union and symmetric difference. `|` adds idempotently, `& ~(1<<i)` clears, and `^` toggles. Clearing differs from subtraction when the element is absent; adding differs from arithmetic addition when already present. A complement is relative to the universe: `(~mask) & full` or `mask ^ full`, never unrestricted `~mask` as a nonnegative finite set. Explain Boolean `and/or/not` versus integer bitwise operators with concrete12and10examples; Python `and` returns an operand. Parenthesize membership tests. Prove set operations by equality of every membership bit.

   **Packed-set investigation:** switch membership in two labelled finite universes, showing the actual selected flags, aligned bit columns and the chosen result. Changing union/intersection/difference/XOR/complement changes the operation contract; colors supplement0/1and text. Show `A={0,2,5}`, `B={1,2,4}`, intersection{2}, union{0,1,2,4,5}, difference{0,5}, XOR{0,1,4,5}. Universe width is explicit and bounded; changing it resets or explicitly masks out-of-range flags with visible feedback. Native bitset helpers accept arbitrary validated nonnegative widths under a documented resource bound.

3. **A word and an integer are different objects.** For a w-bit pattern with unsigned value u, the two's-complement signed value is u if u<2^(w-1), otherwise u-2^w. Derive this by the top bit's negative weight, not a sign-plus-magnitude claim. The pattern11110110 has unsigned246and signed−10at8bits. Arithmetic right shift keeps the sign: −10>>2=−3; logical shift of its8-bit pattern gives61. A bounded left shift is `((u << k) & full)` and may discard top bits; Python's integer `u << k` has no implicit fixed-width truncation. Negative Python right shift is floor division, so −3>>1=−2. `~x=-x-1` follows from infinite sign extension; `(-1).bit_count()` counts ones in its absolute magnitude, so it is1rather than8. To count an explicitly8-bit word, mask first. Negative shifts are errors. Do not generalize these Python contracts to C++, Java or JavaScript, or present arbitrary signed overflow as portable wraparound.

   **Word interpretation investigation:** labelled weighted columns on one fixed-width pattern, with unsigned and signed sums side by side. Allow4/8bits and a bit toggle or valid pattern entry; select a nonnegative bounded shift. Draw source-to-destination positions, dropped bits and zero/sign-filled positions; show arithmetic versus logical results together. Native complete example uses explicit encode/decode and validates a signed value's range instead of silently truncating input. The JS model may use arithmetic on small declared words, avoiding accidental32-bit coercion as an explanation of Python.

4. **XOR remembers parity, not counts.** Prove per bit that `a ^ a = 0`, `a ^ 0 = a`, associativity and commutativity; odd/even contributions determine each result bit. In a finite nonempty sequence with one singleton and every other distinct integer appearing exactly twice, a streaming XOR returns that singleton. State the prefix-XOR invariant and why the multiplicity promise is essential. Example[12,5,12,9,5] gives9. In[6,6,6,2,2], XOR gives6although no element appears exactly once; in[1,2,3], XOR gives0despite no zero input. The earlier first-unique-event problem needs exact counts and order, so XOR does not replace it. The native helper assumes the promise; a demonstration frequency audit is separately labelled and uses extra space. Include zero and negative singleton cases in actual tests.

   **Parity-stream investigation:** process one event at a time, retaining a per-bit parity column and visible accumulator; repeated equal events cancel their contribution. Separate one-singleton, two-singleton and invalid-promise presets. A compact frequency ledger may explain whether the input promise holds, but the UI explicitly identifies it as diagnostic storage, outside the constant-workspace algorithm. Manual stepping/reset and bounded input length/width keep browser work small. No universal data-corruption guarantee: XOR checks can miss cancelling changes and are not cryptographic integrity.

5. **Clearing the lowest one counts a sparse set.** For positive x, write its suffix as a1followed by trailing zeroes. Subtracting1flips that1to0and the zeroes to1; AND with the original leaves higher bits and removes only the lowest1. Repeating `x &= x-1` reaches0after exactly the original population count. Invariant: removed count plus remaining ones equals initial ones. Define zero's count as0; reject negative input unless a width is explicitly supplied, because sign extension invalidates the termination argument. Derive the positive power-of-two test and why zero needs a separate guard. Independently compare a simple shift-and-test loop and `bit_count`, without promising that the clearing loop is always faster in a real runtime.

   **Sparse-bit trace:** show x, x−1and x&(x−1)as aligned words, mark the single disappearing one and the changed borrow suffix, and retain count/remaining state. Connect XOR plus population count to differing flag positions/Hamming distance. The representation is the same bit alphabet because that is the mechanism; it need not imitate the more narrative parity-stream layout.

6. **Two singletons need a second decision.** Optional after the parity and lowest-bit arguments. Under exactly two distinct singletons and all other values paired, total XOR is a^b≠0. A set bit in that XOR differs between a and b. Isolate the lowest set bit with `total & -total`, deriving it from two's-complement/infinite-sign arithmetic. Partition input by that bit; a and b go to different buckets, while identical pairs stay together and cancel. Each bucket's XOR gives one answer. Use[4,9,4,12,9,7]→{12,7}, explain order is not part of the contract, and include negative/zero changed cases. A zero total means the promise cannot hold, but nonzero alone does not validate it. The two-pass helper accepts a reusable sequence; a one-shot iterator cannot silently be reused. O(n) bounded-word operations and O(1)words differ from bit complexity for unbounded integer sizes.

7. **Use the representation in the original application.** Revisit posting sets in the small inverted index: stable document IDs0…w−1become bitmap membership, AND answers a conjunction, `.bit_count()` counts matches, and decoding positions recovers IDs. This application connects the branch to existing content instead of adding unrelated trivia. An availability mask can likewise track which named checks passed; counting differing bits detects how many flags changed, not which transition was authorized. Include full changed native outputs. Retain stable-ID/universe/update limitations and explain why sparse dynamic IDs do not automatically justify a dense bitmap.

8. **Independent transfer and cost boundary.** Ask learners to reconstruct a changed finite-set query, fix duplicate-add/absent-clear arithmetic, decode a different negative word/shift, refute an invalid XOR claim, prove the positive power test, compare one/two-singleton assumptions, and produce a bitmap-versus-set report for a changed corpus. Give closed hints then complete reasoning and outputs. The width Bof values matters: a generic Python bitwise operation can inspect O(B)bits or O(ceil(B/limb_bits))limbs, so constant-space means a bounded number of integers, not constant bits for unbounded inputs. Enumerating set members/output has a cost; no unexplained O(1)large-integer claim.
