# Optical digits teaching data

- **Source:** E. Alpaydin and C. Kaynak (1998), *Optical Recognition of Handwritten Digits*, UCI Machine Learning Repository, DOI [10.24432/C50P49](https://doi.org/10.24432/C50P49). [Dataset page](https://archive.ics.uci.edu/dataset/80/optical+recognition+of+handwritten+digits), retrieved12September2026.
- **License:** [Creative Commons Attribution4.0 International](https://creativecommons.org/licenses/by/4.0/), explicitly stated by UCI on retrieval. This document supplies attribution and documents the subset/change. Retain it with exported CSVs and derived coordinate files. There is no endorsement by the original collectors.
- **Scientific question:** handwritten digit recognition. The original preprocessing divides normalized handwritten bitmaps into4×4 blocks and counts foreground pixels, producing an8×8 array of integers0…16. A CSV feature is one block count, not one original raw camera pixel. “Pixel” is the lesson's short name for a cell of that8×8 representation.
- **Distribution used:** the1797-row optical digits collection bundled in scikit-learn1.9.1 `load_digits()`. [Scikit-learn dataset description](https://scikit-learn.org/stable/datasets/toy_dataset.html#optical-recognition-of-handwritten-digits-dataset) identifies this as the original test-set portion. No network fetch is required to read the supplied CSV or regenerate it from that bundled version. This is not the MNIST dataset.
- **Selection:** for each target0…9, take its first30 rows by original zero-based loader index, concatenate those indices, then sort them ascending. Labels therefore participate in constructing the balanced collection; they are not passed into any embedding model. There are300 rows, exactly30 of each label. The complete source-row index list is `calculated-inputs.json: rows`; the CSV preserves each source row in its first column. Selection favors early available rows and is not a random or population-representative sample.
- **CSV schema:** `source_row`, `digit`, then `pixel_0`…`pixel_63` in row-major8×8 order. Raw integers are unmodified. For Euclidean analysis, divide all64 numeric features by16. Do not use source_row or digit as a feature. No per-pixel centering/scaling is applied before t-SNE; PCA centers as part of its fit. No observations are missing or imputed in this supplied subset.
- **File SHA-256:** `digits-300.csv` = `d93f963c4b2610eb07122a312eec3ddceac18a031477370d71e33835eced728e` (CSV writer's recorded bytes). Root binds all final packet files separately in the delivery checkpoint.
- **Generator and exact fitted inputs:** [content-calculations.py](content-calculations.py), executed with Python3.12.14, NumPy2.3.5, scikit-learn1.9.1. [calculated-inputs.json](calculated-inputs.json) contains actual native PCA/t-SNE coordinates, metrics and selected exact-fixture results. This is content evidence and reproducible offline input, not a production model/browser verifier. A future different-version fit may have different coordinate bytes; never silently overwrite the recorded result and call it the same execution.
- **Fitted settings:** PCA2 uses full SVD; t-SNE2 uses common-scale64-feature input, p∈{5,30,80}, PCA initialization, seeds7/19, auto learning rate, early_exaggeration12(default), max_iter1000, Barnes–Hut angle.5,n_jobs1. Additional p30 random-init fits use seeds7/19. All output coordinates retain CSV row order. Every recorded k is5,10or20. R uses stable source-row tie order; native trustworthiness and reversed-argument continuity use scikit-learn's own sorting semantics.
- **Purpose and evaluation scope:** the maps describe the selected collection. Labels can be revealed as a diagnostic overlay. No measured recognition accuracy, scientific population claim, density estimate, topology inference about digits, speed benchmark or UMAP coordinates are provided. The separate train/validation teaching program is an unexecuted UMAP pipeline illustration with complete offline input.
