Status: content-only specification, not implemented. Stable owner gaussian-processes-gp. Read [lesson](lesson.md), [design](design.md), [checked values](checked-results.json), and [provenance](data-provenance.md) together. Build only when implementation is requested. Retain the numerical failure in the real experiment.

## Shared visual conventions

Use code-native semantic HTML and SVG for this small one-dimensional content; do not create raster approximations of exact curves. Plot position, function value, covariance, and uncertainty in their natural forms. Colors reinforce directly labeled entities; they never carry the sole meaning. Observation markers have a shape different from target and candidate markers. Latent band uses a filled region; observation band has a distinct boundary pattern. Caption the bands as pointwise, conditional on the displayed model.

Numerical pipe fixtures use dimensionless x/output values, following the exact instructional calculation. Their motivating pipe temperature story is an analogy; do not silently attach °C units to normalized numeric outputs. The real experiment uses years and ppm, covariance in ppm². The monthly model coordinate is not a precise measurement timestamp.

Read covariance diagonals as variances, take square roots before plotting standard-deviation widths, and use 1.96 for the hand example and 1.959963984540054 for the recorded NOAA counts. Preserve full-precision calculations; round text to six decimals where useful. No timing/performance curves are requested: the complexity discussion is derived work/storage, not a benchmark.

All investigations start with **no selected prediction**. A choice or short reason must be committed before results/feedback unlock. Prediction state is keyed to the full experiment inputs listed below; input edits invalidate it, close the outcome panel, and clear the previous score. A remembered answer for another state cannot complete the new one. Keep a neutral label such as “Make a prediction for these inputs.” Guidance may describe the mechanism without selecting the winning answer.

After reveal, show actual numerical reasoning and a focused next variation. Feedback describes evidence, including unchanged/null results. Reset restores the documented initial state and removes prediction, result, error, pending computation, and comparison history. A “new example” operation, if added, creates a valid unsolved state and clears the same evidence.

Each control has a visible label and accessible name. Editable entities also have a keyboard-operable numeric table; dragging is optional. Do not rely on hover. Results have a text table and a short textual explanation. Use nonintrusive result announcements, visible focus, and buttons stating their action. Narrow layout stacks plots/controls; preserve axes and units, allow a horizontally scrollable matrix/table rather than clipping entries, and keep targets reachable at 320 CSS px. Reduced-motion mode uses immediate state changes. Nothing auto-plays or repeatedly samples.

### F1 — sampled vector to function points, lesson §1

On the left show three labeled input slots x=0, 1, 2; in the center the associated three-component vector; on the right plot each coordinate at its input. Thin connections are explicitly labeled “connecting finite plotted values.” Use the first three recorded length=1 prior paths at indices 16, 32, 48 of tiny.prior_samples["1.0"] (grid−1 to 4, 81 points), with the same labels in all views. These are actual finite draws generated by the retained calculation, not independent marginal samples.

The prose's [1.0, 0.6, −0.2] and [−0.5, 0.1, 0.4] are hypothetical possible vectors illustrating indexing, not asserted seeded outputs. Either use those as separately labeled constructed examples or use the recorded samples consistently; never attribute hypothetical values to the seeded run. Keep one unobscured vector-to-points mapping visible initially. Text equivalent lists the three x/value pairs and explains dependence. Verify index correspondence and that joining segments do not claim an exact continuous realization.

### F2 — conditioning is a slice, lesson §2

Render the bivariate normal of (y0, f*) with covariance [[1.25, 0.5], [0.5, 1]], mean zero. Axes y0 horizontally and f* vertically, both dimensionless; contour lines are constant joint density, not sample paths. Vertical slice at y0=2 connects to the conditional density N(.8, .8). Plot the marginal N(0, 1) in a separate aligned panel. State that a normalized slice is the conditional density. The null companion has off-diagonal zero, so conditioning at the same y0 leaves N(0, 1).

Density formula is the ordinary bivariate normal with determinant and quadratic form; verify covariance positive definite (det 1), marginal variances, conditional mean .8, variance .8, and standard deviation sqrt(.8). Caption latent interval [−.953077, 2.553077] and separate future-observation interval [−1.208402, 2.808402]. A text table suffices when geometry is unavailable. Do not use variance as an ellipse axis length.

## I1 — editable observations and conditional bands

Placement: brief one-reading mode at §2, full editor at §3 after conditioning. One mounted progressive investigation can be linked earlier if its initial figure is visible there; do not hide the first explanation in a tab.

Inputs: observation table of 0–12 rows {id, x, y}, x∈[−1, 4], y∈[−4, 4]; target x∈[−1, 4]; RBF length∈[.1, 4]; latent amplitude 1; observation noise variance∈[.01, 2]; independent-value kernel option k(x, z)=1 if x=z, otherwise 0 for exact null. Plot grid 81 points. Zero observations is a valid prior. Duplicate x values are valid independent noisy readings under positive noise, with a label distinguishing duplicate readings from one reused reading.

Initial one-reading fixture uses a direct two-location covariance representation with rho=.5, observed y=2, prior variances 1/noise .25. Keep this mode separate from spatial RBF so the UI does not imply an arbitrary rho matches fixed distance. Inputs rho∈[−.95, .95], observed value[−4, 4], noise[.01, 2]. Initial full state x=[0, 2], y=[1, −1], target 1, length 1, noise .25.

Meaningful actions: edit/add/remove a measured value; change a location; choose a new target; compare noise assumptions. Before reveal ask whether an edit changes mean, variance, both, or neither and request one sentence. Prediction key contains mode, ordered observation values/IDs/locations, target, kernel parameters, noise, and comparison baseline. Choosing a fixture does not prefill an answer.

Implement the written Cholesky/triangular solves in a topic-owned pure model. Calculate joint covariance for displayed targets, cache factorization by observation locations/kernel/noise, and reuse for value-only edits. Debounce edits; no fitting loop on animation frames. Bound 12 observations/81 targets; no general ML runtime imported into the page. Negative diagonal below−1e−9 is a visible calculation failure, not clipped success; values within that absolute tolerance under amplitude 1 may clamp to 0 with an internal diagnostic.

Checked comparisons:

- Length 1→.3: midpoint variance .468894721→.999976087; mean remains 0. To 3: variance .127299950; mean remains 0. These contrast information range and give a meaningful mean-null.
- Values[1, −1]→[3, −2], otherwise fixed: target 1 mean 0→.43782228537164825, **all covariance entries unchanged**. Full four-target mean exists in tiny.changed_y. This is the principal null invariant.
- Direct rho .5→0: mean .8→0, latent variance .8→1. Rho 0, y2→−2: no target mean/variance change.
- Noise-free interpolation is discussed but zero noise is outside editor bounds. Phase 2 native model tests can use distinct noise-free inputs and explicit duplicate-input failure.

Reveal shows target calculation, both interval types, and covariance-row detail. Explain why a null follows the formula. Prompt the learner to construct an edit whose mean stays zero but variance changes. Reset restores state and clears commitments/results. Accessible table and readable point labels are required.

## I2 — historical forecast decisions

Placement §6. This is a calendar forecast workspace. The editable entity is a forecast request: conditioning cutoff, future horizon, target months, and kernel family. Real observations remain immutable and attributed.

Two explicitly separated modes:

1. **Reported experiment:** exact predeclared train/dev/test process and optimized/refitted outputs from real.development/real.final_test. Start before development reveal. Commit which family will continue trend/seasonality; inspect dev; predict whether lower error validates intervals before test reveal. Never silently change fitted results.
2. **Explore a new forecast:** kernels retain full-precision log hyperparameters learned on 1990–95, stored as real.development.<family>.fitted_log_theta; optimization disabled. Edit cutoff among 72..96 observed months and horizon 1..24, constrained cutoff+horizon≤120. Center on chosen conditioning prefix. Recondition on that prefix under frozen historical kernel settings. Label “Kernel settings from 1990–95; condition on selected prefix.” These are new exploratory decisions, not untouched test claims or MLL refits.

Prediction key: mode, kernel family/full theta, cutoff, horizon, target indices, noise .09, centering convention, source-data revision. Commit forecast direction/seasonality and expected effect of horizon on a fixed target. For additional agency, choose a future month and enter a point estimate or interval before reveal; do not generate a solved estimate for the learner.

Exact fixtures use lesson table: dev MAEs 5.432943098339017 and .3206008845277874; chosen test 1.2337751646145232, 13/24 coverage; baseline 3.813333333333342. Explorer fixtures are real.explorer["72"|"84"|"96"], both kernels with 24 outputs. Null: horizon 24→6 with same cutoff/kernel must leave the first six means/SDs unchanged; author calculation asserts this for all six cases. Cutoff changes genuinely change available data; compare stored contrasts without promising monotonically improving coverage.

Use bounded exact regression up to 96 conditioning rows/24 targets, cached factor per cutoff/kernel; no browser hyperparameter optimization. Compute on explicit reveal; cancel/ignore stale work on input edit. If a worker is warranted, load it only for this topic. On failure show the error/data, never stale successful output.

Reset returns reported pre-development state. Text outcomes include month errors and observation-interval tests. Explain denominator/units/correlated period once in the caption. On narrow screens stack comparisons with shared axis extent/calendar bounds. Native checks compare library outputs, exact fixture identity, cutoff exclusion, prefix-only centering, horizon-prefix invariance and invalid bounds. Browser checks cover hidden future outcomes before commit, invalidation, keyboard flow, scales, and visible test misses.

## I3 — choose the next probe

Placement §8 after reduction formula. Edit target location, 2–5 candidate locations/candidate noise variances, and observed table; same spatial bounds as I1, ≤12 observations. Observed noise .25 initially; candidate noise[.01, 2]. RBF length 1 initially, with independent-value kernel option for exact no-information construction. Initial target 1/candidates 1, 4, observed[0, 2]/[1, −1].

Require candidate choice/reason before reveal. Key contains complete observed state, kernel, target, candidates/noise, and objective “reduce variance at this target.” Compute joint current covariance at target/candidates, then c(t, z)²/(c(z, z)+noise_z). A candidate at the target is a new noisy measurement, not access to an already-known exact value.

Checked contrast: default reductions .3058337373384466 vs .0018879732313112655. Mathematical null: independent-value kernel with target 1, candidate 4 and neither equal to observations gives c(t, z)=0/reduction 0; candidate 1 gives reduction 1/(1+.25)=.8. Changing only a prospective unknown measurement value cannot alter the reduction, so do not ask for a fabricated future reading. Increasing candidate noise reduces gain when the other terms stay fixed.

Show target variance before this new measurement, reduction, and remaining variance. “Prior” here must mean current posterior before the new reading, not original GP prior. A next prompt moves target toward 4 and requires a new prediction. EI stays a separate worked application, with original/changed values in the manuscript; do not score it as the same objective.

Reset restores initial state and clears commitment. Bounds, factorization handling, keyboard table, stale-result invalidation, text equivalents, and narrow layout inherit I1. Phase 2 native verification independently conditions to check reduction/null cases; browser verification checks target/candidate semantics and edit invalidation.
