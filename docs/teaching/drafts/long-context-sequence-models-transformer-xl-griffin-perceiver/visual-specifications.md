# Long-context sequence models — visual and investigation contracts

Content-first specification, 13 September 2026. These are implementation inputs, not rendered figures or reviewed browser behavior. The complete learner text is in `lesson.md`; native inputs and checked outputs are retained beside this file. Use the subject's memory records, temporal gates and asymmetric attention geometry rather than a common generic experiment box.

## Shared interaction and evidence contract

Each investigation starts with an unanswered prediction. Store the submitted prediction with a canonical snapshot of the active inputs, mask, parameters, selected query/model and operation. Editing any of those invalidates the old answer and hides the prior feedback until the learner predicts again. A stored answer is not a default preselection. Show the before-state while asking; reveal actual consequences after a deliberate commit. Retain an explicit explanation prompt and a changed-input transfer task.

Inputs remain genuinely editable within the stated bounds. Named starting examples are shortcuts, not the only operations. Do not display their solved result next to the initial unanswered prediction control. Feedback should identify the changed contribution or dependency, not say merely “correct.” Numeric answers need a stated tolerance; set/label predictions can be checked exactly.

Use independent labels, line patterns and text in addition to color. All editable graph/strip entities have keyboard and numeric/table equivalents. Keep focus on the active control after updates, and announce committed results through a concise live status. Do not announce every pointer movement. Respect reduced motion; arrows can be static. Reset restores original inputs, clears predictions/results/history and preserves no hidden tuned state. If a learner has exposed assessment labels, never imply reset makes the assessment unseen again.

All small mechanisms are exact calculations apart from float rounding. `checked-results.json` comes from `sequence_mechanisms.py`. Real model values come from the actual PyTorch run in `trajectory-results.json`/`small-fits.npz`, with additional edits/nulls in `investigation-checks.json`. Do not interpolate performance or infer a new architecture's output from a diagram. Phase two independently checks model agreement and actual desktop/narrow rendering.

## Investigation 1: which context is actually retained?

**Question and start.** Determine how segmentation, memory and causal legality change a particular weighted read. Start with five positions, keys[ln9,0,0,0,0], scalar values[6,1,8,2,0], queries1, segment length2, memory2, beta0, selected query4. Show inputs and empty cache slots before revealing that query's answer.

**Prediction.** Record an exact selected set of legal position IDs and a numeric output prediction. The learner can request a hint to compute exponentials; do not silently fill the set or result. The answer binds to all input arrays, segment length, memory length, selected query and beta.

**Meaningful edits.** Add/remove up to16 records, change keys in[−4,4] and values in[−10,10], choose segment length1–8, memory0–16, selected query and beta0–1. Keys are scalar scores from a q1/d1 teaching model. Allow moving a value/key record to a different global position, updating that record's identity and ordering transparently. Hold all other inputs fixed until explicit commit.

**Computation.** For segment start s and end e, eligible storage IDs are[max(0,s−M),…,e−1]. Query i permits j≤i. Score is kⱼ−beta(i−j), row-softmax over legal keys, outputΣweight·value. The within-segment eligible span is not a fixed sliding window; visualize the actual retained segment tail. Retain per-query legal IDs, scores, denominator, weights and contributions.

**Feedback.** Compare the selected set exactly and numeric result within1e−6 absolute+relative tolerance. Mark separately an evicted old record, an available legal record and an available but future record. Explain changes by changed terms and normalization. The visible cache should agree with the score table at every step.

**Checked contrast and null.** At selected query4, M0→0,M2→10/3,M4→5. M4 reproduces full causal outputs in this fixed-projection five-record case. Editing value4 to9 leaves outputs0–3 unchanged. Shifting query/key global coordinates equally leaves all distance biases unchanged. Equal values across all legal keys give that common value regardless of weighting, an algebraic null also checked numerically in investigation-checks.json. Phase two must check the translated implementation.

**Transfer/reset/access.** Ask the learner to move the most informative key just outside the cache and recover it without revealing a future key. Reset all defaults and unanswered state. Give an input table and checkbox legal-set editor beside the strip. At most16×16score cells; calculate after commit, not an ongoing animation. Reject nonfinite inputs and an empty sequence. Phase two checks lengths/remainders, memory0/oversized, boundary queries, beta, nulls, set grading, invalidation and keyboard/narrow clarity.
