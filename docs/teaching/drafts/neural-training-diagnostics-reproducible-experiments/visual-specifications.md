## Lab B. Module mode and graph mode are independent

**Placement:** section 5 after the fresh-layer BatchNorm table. **Question:** which switch changes normalization behavior and which changes autograd recording?

**Editable entities:** two finite scalar inputs `a,b` in `[-10,10]`, stored mean in `[-5,5]`, stored variance in `[0,25]`; fixed epsilon1e−5, BatchNorm momentum0.1, affine gamma1/beta0 with both affine parameters trainable. Choose module mode train/eval and graph mode enabled/no-grad independently. An explicit module selector BatchNorm/linear provides the stated mode-insensitive null; linear rule is `2x+1`, with its weight/bias trainable. This is a scalar mathematical teaching model of the declared PyTorch behavior, not a general autograd engine.

**Fresh start per Run:** default `[1,3]`, stored mean0, variance1, BatchNorm, train/no-grad. Each Run starts from the edited saved buffers, rather than cumulatively mutating them. UI labels say “stored state before this forward.” A “Use resulting buffers as next starting state” action performs that actual state transition and recomputes the next forward pass. Ordinary input edits update all dependent views immediately.

**Live observation:** display whether stored mean/variance changed, whether the output carries an autograd graph, and the actual normalized outputs. Mode and graph-recording controls are independent. Each edit recomputes the mathematical result and state transition; there is no categorical or numeric answer field.

**Equations:** BatchNorm training uses `batchMean=(a+b)/2`, `populationVariance=((a-b)^2)/4`, `sampleVariance=2*populationVariance`; outputs `(x-batchMean)/sqrt(populationVariance+eps)`. New stored mean is `.9*storedMean+.1*batchMean`, new stored variance `.9*storedVariance+.1*sampleVariance`. Evaluation uses `(x-storedMean)/sqrt(storedVariance+eps)` and keeps buffers unchanged. The linear alternative outputs `2x+1` and has no normalization buffers. No-grad does not alter any of these values; it alters graph recording only.

**Feedback:** show operands in the active denominator, arrows to buffer updates, and a separate “graph recorded” status. For `[1,3]`, all four mode combinations are executed in `calculation-results.json.mode_probe`: train outputs±0.999995, buffers0.2/1.1; eval outputs0.999995/2.999985, buffers0/1. Use numeric tolerance `5e−6` for six-decimal predictions. The new-input transfer is `[-2,6]` with stored mean1/variance4; show whether larger batch variance changes the forward denominator or just the buffer. Check against a fresh Torch layer before acceptance. The linear alternative's equal values across modes and a BatchNorm matching-statistics null are required fixture checks.

**State, accessibility and cost:** invalid variance below0 gets a meaningful inline message; equal a/b are allowed and train outputs0. Keyboard controls and side-by-side mode labels replace a spatially ambiguous switch alone. Phone layout separates normalization operands from graph status; retain before/after state labels.
