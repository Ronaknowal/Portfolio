# Evaluation metrics — visual and investigation contracts

Prepared content only. No production widget, SVG, route, browser check, or completed implementation is claimed. Every visual is tied to a specific passage in lesson.md. The complete programs and JSON receipts in this directory supply reproducible values, not a license to replace the visual with raw JSON.

## Common behavior and numerical conventions

Use four distinct mechanisms: cards moving through a decision gate, sorted score blocks and pair comparisons, residual lengths/squared areas, and a reorderable ranked shelf. Preserve visual language within a mechanism; do not turn all four into a generic slider plus output paragraph. Small inline figures explain a concept before the corresponding investigation. Figures require caption, text summary, labels, units, accessible data table, and keyboard equivalent for every editable object. Use labels and shape/position as well as color.

Each investigation opens with an unsolved task and **no prediction selected**. A prediction consists of a direction/metric choice or numerical response plus a short reason, committed explicitly for a fingerprint of all active entities, scores/labels/targets/grades, threshold/cutoff/cost/unit/operation and fixture version. Commit before Reveal. Result and comparison remain hidden until reveal. Editing an entity or changing the proposed operation invalidates the old prediction and clears the old result; it never silently reuses a correct answer. Keep an optional labeled history of attempts, bound to its old inputs. Reset restores the named fixture and clears edits, predictions, feedback, and history. A visual hover alone must not invalidate a mathematical prediction.

Learners edit actual rows, scores, labels, predictions, grades and ranks, not just select a solved preset. Presets offer exact reference cases and nulls. Separate input validation from mathematical undefinedness: invalid input gets a localized error and keeps the last valid table; a valid one-class dataset gets an explanatory undefined metric. No epsilon added to denominators. Use full precision internally, six decimal places for display where appropriate, exact fractions/counts for small examples. Store undefined as null and print the reason, never NaN, fabricated zero, or a broken axis.

Bound teaching arrays to 4–16 classification items, 3–12 regression rows and 3–10 retrieval documents. Score editing: finite values in [-10,10]; probability-loss views require [0,1]. Regression values [-100,100] in base minutes, no hidden clipping of negative predictions; flag physical duration violations while retaining mathematically valid error calculations. Grades integers 0–5; costs finite 0–20 with at least one positive. Cutoff 1..document count. Calculations are small synchronous pure operations; do not load Python, a model, or a graphing framework to render eight points. Lazy-load topic interactions and optional real-data detail on demand. No timer or autoplay.

At narrow widths stack source entities, graphic and explanation in reading order; do not squeeze two plots until their labels disappear. Provide an overflow-contained table when necessary. Move Up/Down and numeric fields duplicate dragging. Focus stays on the edited entity or the explicit reveal result heading; announce compact result changes in a polite live region, not every pointer move. Reduced motion uses immediate relocation. All phase-two verification below is deferred, not already run.

## Investigation 1: a decision gate whose denominators can be inspected

**Placement:** after §2, extended by the cost explanation in §3. Inputs: editable classification table, current threshold, proposed threshold, positive/negative costs, optional β after F1 is introduced. Start at .8 with a proposed move to .5 and an empty prediction of precision/recall direction plus IDs expected to move. Do not show the destination counts before commitment. Proposed thresholds can be entered numerically or chosen from distinct score boundaries; “above maximum” is a first-class endpoint rather than assuming 1 excludes all scores.

**Mechanism:** predict positive iff score ≥ threshold. Compute TP/FP/FN/TN from each ID. Precision TP/(TP+FP), recall TP/(TP+FN), specificity TN/(TN+FP), FPR FP/(TN+FP), accuracy (TP+TN)/n, F1 2TP/(2TP+FP+FN), Fβ as manuscript, cost C_FP×FP+C_FN×FN. No differentiable model or retraining occurs. A selected metric highlights its denominator population and numerator subset.

**Reveal and explanation:** cards relocate into labeled cells; feedback compares recorded directions and actual changed IDs, then explains the new denominator. At .8→.5, D becomes TP and E becomes FP; precision 2/3→.6, recall .5→.75. At .5→.3, F becomes TP: both precision and recall rise. Ask the learner to explain why recall is monotone on fixed labels while precision is not.

**Checked fixtures:** core thresholds .8=(TP2,FP1,FN2,TN3), .5=(3,2,1,2), .3=(4,2,0,2), 1.1=(0,0,4,4). With costs (1,3), totals 7,5,2,12. **Null:** .70→.75 leaves the same A,B,C cards positive, exactly identical counts/rates/cost. This null is asserted in the calculation program. Editable label changes require a new prediction, because even a fixed threshold can then change the evaluation outcome. Empty predictions precision undefined with explanation; no actual positives recall undefined.

**Phase two:** verify card membership/count conservation; equality at tied score .8; no-score interval null; cost and β updates; all-negative/positive labels; endpoint choices with scores outside [0,1]; state invalidation; keyboard gate/input operation; no color-only correctness; reset. Assert deterministic fixtures against JSON and a separately implemented reference, not screenshot colors.

## Investigation 2: ranking blocks, pair credit, and the PR contribution

**Placement:** after §4's complete construction. The same named cards begin unsolved at the first grouped step. User predicts the next TP/FP increment, ROC coordinates and whether recall changes; requires a reason before revealing the next block. Editable scores and binary labels, plus display reorder of tied IDs, are distinct controls. Show which controls change ranking and which only change presentation. The eight-item limit makes the full pair grid readable; 16 is the maximum.

**Mechanism:** stable descending score sort for display; emit a threshold point only after the full equal-score block. Accumulate TP/FP. ROC-AUC = mean pairwise credits with ties .5 = trapezoidal area over grouped ROC. AP = sum of recall increments times precision after each block. Display AP rectangles/contributions, with a separately labeled optional trapezoidal PR overlay; they are different conventions. Positive fraction is an exact constant-score AP reference, not an asserted AP for every random permutation. Missing either class suppresses ROC/AUC; missing positives suppresses recall/AP. When all items are positive AP is 1 under this convention, but ROC-AUC is undefined.

**Checked main:** core curve arrays are retained in metric-fixtures.json. Initial ROC-AUC .78125, AP .7708333333333333, trapezoidal PR area .79375. **Contrast:** set C score from .8 to .45. Recompute nine grouped states: AUC .6875, AP .7333333333333333, full coordinates in contrasts/edited_C_score045. The changed positive loses its tie credit versus B and moves below E; feedback identifies the exact pair changes. A second selectable area-comparison fixture has stable positives P1,P2,P3 and negatives N1..N5, ranked A=[N1,P1,P2,N2,P3,N3,N4,N5], B=[P1,P2,N1,N2,N3,N4,N5,P3], distinct scores 8..1 in each order. Its AUC/AP values (.7333333333,.5888888889) versus (.6666666667,.7916666667) refute the area-ordering misconception without changing observed labels.

**Nulls:** reorder B/C display while both retain .8 → all curve/area values exactly identical (asserted). All scores .5 → only no-alert and all-alert grouped states, AUC .5/AP .5. Optional probability comparison p→p² preserves ranking/ties and AUC/AP but changes log/Brier as inline figure6. Moving only a decision threshold leaves probability losses and the entire score curve unchanged; highlight just an operating point.

**Feedback/reset/access:** label selected pair contributions in words “positive higher,” “tie,” “negative higher.” On Reveal, compare predicted increment before showing the full explanation; next-step predictions reset. At narrow widths show sorted rows then one plot at a time with an explicit tab switch, retaining the coordinate table. No screen-reader traversal of unlabeled plotted points. Optional full-curve reveal requires a new commitment and explains it skips remaining prediction steps.

**Phase two:** grouped ties/permutations, constant-score AP, no-class states, AP integration direction, ROC endpoints, precise pair/area equality, C-edit contrast and independent tied practice fixture. Confirm the curve is generated from editable data, not merely replaying a fixed animation. Compare readable table and graphic values; check fingerprint includes edited labels and scores.

## Investigation 3: choose an error pattern and inspect what survives averaging

**Placement:** §6 after R². Editable rows contain observed y and predictions A/B, with stable task IDs. Initial question asks which predictor MAE and RMSE prefer, with two independent unset choices and a reason. User can change any target or prediction, add/delete within bounds, and choose minutes or seconds. Prediction values may be negative; display a duration-domain flag without changing the mathematical result. The unit switch transforms all targets and predictions, not merely axis labels.

**Mechanism:** signed residual, absolute/squared residual; means and square root as equations in the manuscript. Median absolute error from the sorted magnitudes. R²=1−SSE/SST, with SST=sum(y−evaluation mean)², undefined for fewer than two targets or SST=0. Include a train-mean baseline input separately named “fitted training constant”; never substitute it into SST. Optional construction controls “copy targets” and “make all values 4” require fresh predictions.

**Checked main:** y=[1,2,3,4,10], A=[1,2,3,4,4], B=[−1,0,1,2,8]. A MAE1.2/MSE7.2/RMSE2.683281573/MedAE0/R².28; B 2/4/2/2/.6. SST50. **Edit contrast:** A's last prediction4→8 gives MAE.4/MSE.8/RMSE.894427191/R².92. **Reference:** fitted constant3 SSE55/R²−.1; evaluation constant4 SSE50/R²0, explicitly an evaluation reference. **Unit null:** A in seconds MAE72/MSE25920/RMSE160.99689438/SST180000/R².28; preference and R² unchanged. **Zero-error null:** predictions=nonconstant y gives all errors0/R²1. All targets/predictions4 gives errors0/R²undefined. Each is computed in the retained JSON.

**Feedback:** highlight the residuals that explain the learner's predicted score preference and show the sum before division. Incorrect answers get an explanation of length versus area, not a generic red error. The constant-target case explicitly says the reference has no variation; it does not call perfect predictions bad. Edits invalidate both score-preference and numerical predictions.

**Phase two:** all exact fixtures, unit conversion, negative residual sign, square-area scaling, zero/constant domains, n bounds, full keyboard row editing, accessible segmented tables, invalidation after changing baseline/unit/rows, no clipped labels at narrow widths. Do not use floating-point exact equality for calculated R²; reference tolerance 1e−10 for these fixtures.

## Investigation 4: reorder a search result, not a generic numeric slider

**Placement:** §7 optional retrieval branch. Use stable IDs with editable grades and keyboard/drag rank movement. Before the proposed swap, learner predicts which of P@K, reciprocal rank, AP and NDCG changes, plus direction and reason. Cutoff K defaults3, adjustable1..n. Choosing a grade edit is another proposed action requiring its own prediction. Identity is retained throughout a reorder, so the candidate set stays fixed.

**Mechanism:** relevant iff grade>0. P@K=positive count in first K/K; R@K=count/total relevant in declared complete candidates. RR=1/first relevant rank, convention0 if none. AP=sum(precision at relevant ranks)/total relevant across this complete candidate list. Exponential gain 2^grade−1; DCG=sum through K gain/log2(rank+1); IDCG sorts the same candidates' gains; NDCG=DCG/IDCG, undefined if IDCG0. The optional API comparison explicitly switches to linear gain and recalculates **both** actual and ideal sums, not just a label.

**Checked main/contrast:** initial D1..D5 grades[0,3,1,2,0], K3: P/R2/3, RR.5, AP.638888888889, DCG4.916508275, IDCG9.392789261,NDCG.523434321641. Swap D1/D2 → [3,0,1,2,0]: P/R unchanged, RR1,AP.805555555556,DCG7.5,NDCG.798484858099. **Null:** swap original D1/D5 (both grade0): every metric/contribution grade sequence unchanged, asserted in the program. **No relevance:** all grades0: P@K0,RR0, AP/R@K/NDCG undefined with their denominator reasons. Linear-gain API value .502490520169 differs from exponential .523434321641; direct supplied raw grades are gains in that API.

**Feedback:** animate only the two moving cards if motion is enabled; show rank-contribution deltas and fixed ideal list until a grade changes. Explain why P@K is insensitive to order inside an unchanged top-K set while RR and discounted gain may change. Changing K changes the question and invalidates the recorded prediction. Narrow layout is a vertical list with contribution labels, not tiny horizontal tokens.

**Phase two:** same-candidate normalization, grade edits, K changes, zero-grade/nulls, stable IDs, keyboard reorder/focus retention, alternative gain convention and independent three-document practice. Ensure a tied predicted-score import is not silently treated as a unique ranking: this investigation edits explicit ranks; a future score-input feature needs a declared tie rule.

## Measured experiment and downloadable instructional programs

Render the experiment as a bounded evidence reader, not a fifth forced lab. It may expose development threshold details and per-item test errors after the procedure is explained; it must not suggest test-score tuning. Input data/result JSON stays topic-local and lazy-loaded. No browser fitting is needed: these are frozen measured predictions with a downloadable full reproducible program. If phase two chooses to add an exploratory development-only threshold control, it must label its data role, retain the frozen authored comparison, and require an initially unset prediction; test labels cannot be used to optimize it.

Required download assets: metrics-calculations.py, banknote-evaluation.py, banknote-subset.csv, provenance. Preserve the full programs, their setup/run instructions and deterministic result expectations. Translation to a browser must be checked against the independent Python calculations; embedded source code is not itself a lab. Keep exercises independent, with all hints/solutions initially closed. Phase two verifies asset URLs, exact CSV provenance, all documented outputs, accessibility, narrow layouts, rendering performance and production loading without mistaking content-author probes for these checks.
