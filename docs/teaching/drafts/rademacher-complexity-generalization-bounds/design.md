## Learner model and explanatory design

The learner may remember PAC/VC definitions but need local refreshers for dot products, supremum, expectation, norms, loss composition and margins. Start with an operation they can perform without those terms: choose the best matching prediction row for one coin pattern. Introduce the symbols only after computing the complete example.

Observable outcomes are to compute exact small complexity; distinguish max-then-average from average-then-max; preserve conventions; construct the loss class; explain the uniform theorem's data and range assumptions; derive a closed-form norm-ball best response; use finite, kernel and L1 bounds; calculate a bounded margin loss; account for predeclared selection and Monte Carlo failure probabilities; and diagnose a misleading certificate using actual evidence.

| Hurdle | Treatment and observable action |
|---|---|
| A supremum feels abstract | Editable prediction matrix; identify and justify a winning row for each sign pattern |
| Different randomness gets conflated | Separate sample draw, ghost sample and sign-draw lanes; distinguish empirical from expected complexity |
| Predictor quality is mistaken for capacity | Singleton-zero example and rich-class counterargument; retain the training loss term |
| The loss disappears in a theorem | Convert binary predictions to actual mistake vectors; exact factor1/2 calculation |
| The proof looks like symbol manipulation | Pair swapping and the split from one shared winner into two independent winners |
| Norm bounds seem unrelated to data | Signed vector sum and supporting point; same-energy duplicate/perpendicular contrast |
| Margins look like arbitrary scores | Ramp loss and simultaneous scale null; explicit B/rho and data-role accounting |
| A Monte Carlo result is treated as a guarantee | Checked finite estimate trajectories, one-sided correction and the wrong direction of imperfect optimization |
| Theory is forced onto a familiar empirical curve | Real fixed budget sweep where validation improves and all simple bound expressions remain vacuous |

Four focused investigations are specified, with static explanations at first use: best-response construction, signed geometry, editable margin evidence, and a real predictor workbench. The real workbench allows bounded coefficient edits and actual row calculations; it does not require a costly live optimizer or repeat a generic text panel. The manuscript's first eight sections form the core route; optional advanced sections are clearly separated. Every numerical exercise changes the worked inputs and has a closed hint and solution.

2. **The first version of that repair deleted the whole screenshots directory**, which is shared with every other lesson in the repository. It now removes only `rademacher-*.png`. (An earlier draft of this record said "709 other captures"; that figure is not reproducible from the tree and was a count taken at some intermediate moment. Measured on 20 September 2026 the shared directory holds 724 non-`rademacher` captures, and the independent reviewer counted the same.)
3. **"Restore failed" conflated two different events.** A file whose bytes differ from the snapshot afterwards can mean the restore did not land, or that something edited the file *while the harness held it* — in which case the restore silently overwrites that edit. The harness now distinguishes them and reports `concurrent-edit` with the consequence spelled out.

The third was found the hard way: I edited two figure sources while a harness run was in flight, which produced one misattributed verdict and one spurious restore failure. Both were artefacts of my own concurrency, not of the guards; every edit survived and all four offline verifiers passed immediately afterwards. **An interruption mid-phase, and what it cost.** A spend limit and then a low-memory kill stopped the preview and a harness run part-way through. Because the harness writes source files, the first thing checked on resuming was whether any breakage had been left applied: all five offline targets and all three browser targets were in their correct state, and all four offline verifiers passed, so no breakage survived the kill. The build directory was treated as untrusted — it may have been produced from a broken source mid-harness — and was deleted and rebuilt, and all 29 captures were deleted before re-capturing so that nothing could survive from an earlier state.

**The three deferred falsification classes came due and all three fire.** The harness gained a `--browser` mode that rebuilds the bundle for each breakage and runs the browser verifier against the live preview: an investigation revealing its graded value before a prediction is caught by the graded-string guard, a label placement reverted to a fixed offset is caught by the curve sampler, and a CSS `fill` overriding `fill="none"` is caught by the painted-versus-attribute comparison. The full harness now applies **25 breakages, all 25 caught and named** in a clean run with nothing else touching the tree, every file restored byte for byte, and it re-captures the evidence against the repaired build before it reports. It also caught one of its own anchors going stale after the geometry repair — reported as `unanchored` rather than silently breaking the wrong function.

**On the claim discipline this topic is most at risk of.** The rendered page was checked for eleven statements that must be present and three phrasings that must not. The empirical complexity, the expectation and the 1−δ bound are named and separated in one callout; the bound is stated to hold over the draw of the sample, simultaneously over the class, and explicitly not as a deterministic promise nor as a confidence in any individual prediction; the vacuous result is stated plainly, beside a classifier that measurably works; the stacked bars are drawn past the ceiling rather than clipped at it, with the caption saying why; and the fixed-corpus design is distinguished from an iid population model. Everything above is green as of this record, `dist-rad` is deleted and the preview is stopped. What remains open is independent review.

## Disposition of the independent review, 20 September 2026

Reviewed against `docs/teaching/RADEMACHER-INDEPENDENT-REVIEW.md`: two blocking findings, seven should-fix findings, twelve observations. All nine findings are resolved; the observations are dispositioned individually. ### Collapsed radicals — reported separately, fixed first

**What was wrong.** This file's stylesheet opened with `.rad-lesson svg { display: block; width: 100%; height: auto; margin-inline: auto; }`. As a bare descendant selector under the lesson root it matched KaTeX's own inline SVGs as well as this lesson's drawings, and KaTeX radicals take `height: inherit`. Measured live: **all 24 radical signs rendered between 0.05 px and 0.72 px tall, and nine stretchy accents between 0.02 px and 0.08 px.** Every square root on the page was invisible, so the confidence term read as `ln(2K/δ)/(2n)` where the text means its square root — the radius squared rather than the radius — and a collapsed `\widehat` turns `R̂` into `R`, which on this topic converts an empirical Rademacher complexity into the population quantity the lesson exists to distinguish it from. The page carries 25 `\sqrt`, 18 `\widehat` and 3 `\underbrace` constructs that KaTeX draws as SVG. This was wrong mathematics on the page, not a layout blemish.

**Resolution.** The shared `Drawing` component now applies a `rad-drawing` class itself, so a new figure cannot forget it, and all 41 stylesheet selectors target `svg.rad-drawing`. Measured the same way after the fix: **0 of 24 radicals under 1 px (16.98–59.63 px) and 0 of 29 other KaTeX SVGs under 1 px**, the nine formerly-collapsed accents now at 10.59 px. This lesson's seventeen drawings are unchanged in size and all carry the class.

**Why nothing caught it, which is the part worth keeping.** The browser verifier did measure KaTeX accent SVGs — but only their *width*, looking for one too wide for its column. A collapsed SVG is also narrow, so the guard passed while the defect was live: the guard's domain excluded the defect. Worse, the source-hygiene checker reported "the SVG text rule scoped at the lesson root" as a *passing* condition while the geometry rule two lines above it was the cause. Both are closed. The browser verifier now asserts every `.katex svg` has non-trivial rendered height at 1366, 390 and 320 px with practice solutions opened, and requires at least twenty radicals to be found so it cannot pass by looking at nothing. The hygiene checker refuses any bare descendant `svg` selector under the lesson root, requires the text rule to be scoped to `svg.rad-drawing`, requires `Drawing` to apply the class, and refuses a raw `<svg>` in either component. Two falsification cases drive them.

### Blocking

**B1 — a graded comparison tighter than the precision it prints.** Investigation 2 decided a three-way comparison at `1e-12` while printing both operands to six decimals, so a learner one keystroke from a shipped preset was told their category was wrong by a verdict that printed both "different" values as `0.707107` and in its next clause told them their number was right. The numeric field had been fixed for exactly this in phase C; the categorical comparison one line above had not. The earlier fix addressed a site; this one addresses the class.

*Resolution.* One exported `gapOutcome` grades every three-way comparison at the precision its operands are printed with, and investigation 1's tie thresholds route through `displayValue` at the same six decimals. Feasibility slack — a question about representability, not about grading — became an exported constant, which leaves **no hand-written tolerance literal anywhere in `RademacherLabs.jsx`**, so the hygiene checker bans them outright rather than maintaining an allow-list of blessed exceptions. The models verifier sweeps the enterable three-decimal grid at both printed precisions and requires `gapOutcome` to return "equal" exactly when the operands print the same, with both sides of the equivalence exercised so it cannot pass vacuously; the reviewer's exact reachable input is pinned by value; and the browser verifier drives that input on the live page and asserts the verdict is a match. A falsification case tightens the threshold below the printed precision and the sweep goes red. O4's latent twin is fixed by the same change.

**B2 — a small-multiple figure drawn at two scales.** Figure 8, captioned "Same lengths, same upper bound, different exact answers", drew the same unit vector at 26.5 px in panel 1 and 53 px in panels 2 and 3, because each panel autoscaled to a signed sum it never draws. The natural reading of the one smaller circle was that it showed the smaller answer; it is the budget, identical in all three.

*Resolution.* `ballGeometry` accepts a `sharedExtent`, `figureExtent` computes one extent for a whole small-multiple figure, and figure 8 passes it to all three panels. The models verifier asserts every panel's scale, ball radius and drawn unit length are identical — after first asserting that autoscaling genuinely disagrees by about a factor of two, so the guard is not vacuous. The browser verifier measures the three painted ball widths from the DOM and requires them within half a pixel. A falsification case removes the shared extent. Separately (O5), panel 1's two coincident inputs now carry a `×2` annotation, since the panel that exists to show the duplicate case otherwise showed one arrow.

**S1 — evidence written before the final assertions.** Both Python verifiers wrote their evidence and then kept asserting, so recorded totals were permanently short of printed ones (5,782 against 5,785; 75 against 76) and — the serious half — a failed byte-identity check exited non-zero while leaving `"passed": true` on disk.
