# Rademacher complexity — visual and investigation contracts

Prepared content only. The manuscript, two complete instructional programs, real offline data and author results exist. No React, SVG, browser lab, production download route or independent implementation verification has been performed. Preserve the distinct forms below: a best-response matrix, signed-vector geometry, a margin-loss construction and a real constrained-predictor workbench. They teach different operations.

## Shared interaction and accuracy contract

Every investigation begins with **prediction unset** and an unsolved editable problem. Hide its destination quantities until the learner records a prediction and reasoning. Commit the answer against all relevant entity IDs, values, selected class, convention, data version and operation. Reveal computes the result and explains the agreement or discrepancy. Editing a dependency invalidates the attempt and result; scrolling, focus and hover do not. Reset restores the named unsolved fixture, clears attempts and cancels any pending calculation. Reset never claims that previously viewed assessment data become statistically unseen.

Use counts, positions, shapes and text as well as color. All drag operations require numeric/keyboard alternatives. Expose real tables with headers and accessible names; announce revealed results without moving focus. Keep hints and independent solutions closed. Stack inputs, view and interpretation on narrow screens; scroll a table when necessary rather than shrink its text. Respect reduced motion and do not autoplay sign draws.

Label exact enumeration, numerical optimization, Monte Carlo estimates and real measured quantities distinctly. Captions name the output range, class and normalization. Every sign is ±1 and the default expression has no absolute value. Use rational arithmetic for editable rational prediction rows where practical. Preserve full-precision numeric authority in the JSON files and calculate percentages from counts. No unexplained hierarchy heatmaps, invented runtime plots or assumed monotonically improving measurements.

Load only this topic's data on demand. Tiny sign enumeration has explicit limits; real-data interactions use bounded dot products and recorded fitted objects, not in-browser sklearn or model training. Avoid storing every matrix cell for a large simulation. Any future live optimization extension requires an independently validated solver, bounded inputs, cancellation and responsiveness; it is not required for this design.

## Investigation 1 — choose before averaging

**Initial problem:** The four threshold rows on x=[−1,0,1], with σ=[1,−1,1]. Ask the learner to select a winning row, record its normalized correlation and explain any tie. Winners and aggregate complexity are initially hidden. After revealing one pattern, continue to the other seven, then predict the average of the maxima.

**Editable entities:** 1–8 distinct observation columns with stable IDs, 1–24 prediction rows with entries from {−1,+1} or finite decimals in[−2,2], and individual sign bits. Class presets insert explicit rows; the user may add, remove or edit rows independently. Duplicate rows remain visibly duplicate if retained but do not increase the effective distinct count. A cutoff-editing mode uses scalar inputs and derives the valid threshold rows rather than permitting inconsistent “thresholds.”

**Calculation:** For each sign pattern, compute every Σσᵢfᵢ/n, choose the maximum, then average over all2ⁿ patterns. Retain all maximizing rows for feedback, although a deterministic first row may be highlighted. Never initialize the numerical maximum to0 for arbitrary nonsymmetric classes: some per-draw maxima can be negative. Show the wrong-order diagnostic max_f Eσ correlation separately, labeled as a different expression.

**Contrasts:** Default thresholds2/3; adding the opposite orientations gives5/6; all eight rows gives1. Singleton all-positive gives0, while enabling the explicitly named absolute-value convention gives1/2. The latter must change the displayed definition and compatible explanatory text, not silently the calculation.

**Nulls:** Duplicate an existing threshold row; reorder hypotheses; permute observation columns together with their sign/target attachments; add a convex average of existing rows. Complexity is unchanged. Adding a fixed7 to every output is another exact null in the author program, although the basic editor's[-2,2] bounds need an explicit advanced-offset control to reproduce it. Scaling all outputs by2 doubles complexity and may exceed1 legitimately.

**Feedback:** Explain the best-response reason and which sign patterns benefited from a new row. A high average is available flexibility, not a claim about inevitable overfitting. The singleton-zero case should ask whether the fixed predictor is accurate before allowing “low complexity means good model” to go unchallenged.

**Reset/access/bounds:** Restore the four rows, original IDs and unresolvedσ; clear all pattern answers and their aggregate. Maximum 256 patterns × 24 rows × 8 columns. Compute only after commit/reveal, not on every pointer move. Text table and arrow-key controls replace drag. Phase two verifies all exact averages, ties, negative maxima, duplicate/permutation/convex nulls, score-range scaling, absolute convention, input rejection, lost-label prevention, prediction invalidation and narrow rendering.

## Investigation 2 — align a bounded vector with noise

**Initial problem:** x₁=(1,0), x₂=(1,0), B1 and signs(+1,−1). Ask for the signed sum, maximum correlation and whether the maximizing coefficient is unique. None is preselected. Revealv0 and value0; every allowed coefficient is optimal. Then predict the average over all four sign patterns.

**Editable entities:** 1–8 two-dimensional input vectors with coordinates[-3,3], radiusB[0,3], sign bits and an optional candidate coefficient vector constrained to the displayed ball. A learner can propose a coefficient, see its achieved correlation, then compare it with the exact support value. Numeric coordinates and radius fields are authoritative; dragging is an alternative. Inputs are real score features, not necessarily probabilities.

**Equation:** v=Σσᵢxᵢ, achieved=wᵀv/n, optimum=B‖v‖/n, optimizerBv/‖v‖ when v≠0. Exact empirical quantity averages this over2ⁿ signs. Energyupper=B√Σ‖xᵢ‖²/n. For B=0, optimizer0; forv0, optimal coefficient is nonunique except when B=0.

**Checked contrast:** Duplicate unit vectors→complexity.5. Editing x₂ to(0,1)→1/√2 with unchanged energyupper. Doubling B→√2. **Null:** rotate both inputs90 degrees to(0,1),(−1,0) in the orthogonal fixture→same 1/√2; row permutation and reversing a single input vector also preserve the sign-averaged result. The current-pattern optimizer may change under these actions; label which quantity is invariant.

**Kernel branch:** Two-by-two PSDGram with diagonal1, edit r∈[−1,1]. Authorchecked r=0/.9/1. A sign pattern's optimum isB√(σᵀKσ)/2; average four patterns. Show constant trace bound. r→−r is a null for the sign-averaged result, although individual quadratic forms interchange. This branch is a feature-space computation, not a new trained SVM.

**Feedback:** Use the supporting point and dot-product projection to show why a proposed coefficient is suboptimal. Differentiate the exact geometry from its upper bound. Show that globalrotation is a coordinate change while moving only one input changes geometry. For an ℓ₁ extension, replace the ball with a diamond and derive the largest-coordinate solution; don't reuse the Euclidean optimizer.

**Reset/access/phase two:** Numeric alternatives for vectors, selected-sign list, textual signed-sum table and optimum explanation. At most 256 signed sums; no background Monte Carlo. Test zero vectors/radius zero, rotation/permutation/null, singular Gram, PSD rejection and tiny negative roundoff policy, exact-versus-bound ordering, candidate feasibility, input invalidation and stacked layout.

## Investigation 3 — construct a margin bound from actual score inputs

**Initial problem:** Use the one-dimensional score f(x)=wx with w=1, B=1, four scalar inputs x=[−.2,.1,.4,1.2], labels y=[1,1,1,1], rho=.5 and delta=.05. Ask for the four margins, ramp losses and effect of raising rho before revealing. These are constructed scalar-feature observations. Calculate the energy term from the same inputs; never hold it fixed after an input edit.

**Editable entities:** 3–20 scalar input rows x in [−3,3], labels ±1, w in [−B,B], budget B in [0,4], rho in [.1,3], delta in [.01,.2], and an optional predeclared comparison count K in [1,20]. Changes define the named problem. A declared tuning grid can be compared; reducing K after viewing results must not make discarded comparisons disappear from the selection explanation.

**Calculations:** mᵢ=yᵢwxᵢ; ramp=clip(1−mᵢ/rho,0,1); feature energy=√Σxᵢ²/n; complexity addend=2B×energy/rho; confidence=3√(ln(2K/delta)/(2n)). Show the raw sum and the trivial ceiling 1. For these tiny samples, a vacuous result is expected and should remain visible.

**Checked contrasts:** Default ramp [1,.8,.2,0] has mean .5. Changing rho from .5 to .25 yields [1,.6,0,0], mean .4, while doubling the complexity multiplier. Changing the first input from −.2 to .2 changes its margin and its ramp from 1 to .6 at rho=.5, with unchanged squared feature energy. These fixtures are retained in checked-results/scalar_margin_fixture.

**Nulls:** Multiply w, B and rho by 3, within the bounds for the default case. Predictions, ramp losses and B/rho stay unchanged. Permuting attached (x,y) rows is another null. Changing delta changes only confidence, not margins or empirical complexity.

**Feedback:** Explain the competing ramp and complexity terms. A bigger raw margin accompanied by an equal budget/rho scale does not improve the normalized evidence. Highlight fixed-rho contraction versus choosing rho using data. Accepting w outside B would invalidate the displayed class; reject that input with its norm calculation.

**Reset, access and phase two:** Use an editable table and a number-line ramp with text equivalents. Reset the default rows, unset answers and comparison history. Verify the knots m=0 and m=rho, tie policy, all-positive labels, finite positive parameters, scale/permutation nulls, energy dependence and raw sums above 1. Use exact fixtures before adding rounded labels. Explain that a theorem's population assumptions are not established by the toy interface.

## Investigation 4 — examine a fitted norm budget on real observations

**Initial task:** Present five declared budgets and fixed representation, training and validation evidence. Assessment is hidden. Before showing the selected candidate or bound comparison, ask the learner to record a chosen B under the stated selection rule and predict which candidate has the smallest bound expression at rho=1. These answers differ: selection chooses B=4, while the smallest expression belongs to B=2. Ask for the reason.

**Meaningful editable extension:** A candidate has five explicit coefficient values and a selected predeclared ball B. Initialize an unsolved manual candidate w=0 rather than silently selecting a trained solution. The learner may edit the coefficients, respecting ‖w‖≤B, and predict effects on named fit observations before computing their scores. Loading a fitted candidate is an explicit action with its provenance. There is no automatic refit. Local dot products permit real predictor changes without a preset-only parameter display.

**Data and calculations:** Read the retained 480-row CSV and frozen means/scales from experiment-results. Reconstruct clip((x−mean)/scale/3,−1,1) and append 1. Respect source IDs and roles. Calculate bounded fit/validation scores, margins, ramp losses and classification counts. Fitted preset values must match retained results. Use the selected class budget B in the bound, not the manual candidate's observed norm as an unaccounted new class. Both fixed rho choices use K=10 and delta=.05.

**Checked contrasts:** Fitted B=2 has 19 fit errors, 6 validation errors and 5 assessment errors; B=4 has 8, 4 and 2. At rho=1 their raw sums are 1.129848... and 1.198469.... The zero-coefficient candidate produces zero margins and ramp loss 1 on every row, with fixed tie prediction +1: 134/240 fit errors, 41/80 validation errors and 51/80 assessment errors. `author-checks.json` retains this check and the actual row-reversal and matching feature/coefficient permutation nulls. Coefficient edits must recompute actual outputs; never interpolate accuracy between fitted budgets.

**Nulls:** Reordering fit rows preserves every aggregate. Permuting feature coordinates together with coefficients and representation parameters preserves every prediction. Role labels are fixed; moving an assessment row into fit is not an allowed edit.

**Assessment and interpretation:** Reveal assessment after recorded selection, with its 80-observation counts and majority baseline's 29 errors. If weights change afterward, indicate that assessment has already been viewed; resetting cannot make it a new independent test. Repeated validation use is tuning, so final practical evidence needs untouched assessment. The uniform ball bound concerns all class members under its assumptions. It does not certify those population assumptions for randomized rows from this source corpus.

**Bounds, access, reset and phase two:** At most 480 rows × 5 coefficients, five stored fits and two rho values. Load the CSV only when opening this investigation or downloading it. No autoplay, remote API, sklearn or large optimizer. Provide coefficient names, a norm calculation, readable missed-row tables, keyboard commit/reveal and a narrow stacked layout. Reset clears the manual candidate and attempts while retaining an accurate assessment-seen indicator. Independently validate source IDs, frozen transformations, norms, ties, all stored counts/margins, the zero candidate, permutation nulls, disclosure order, absence of hidden fitting and browser performance.
