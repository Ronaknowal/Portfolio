# Gradient Boosted Trees: teaching design

Canonical ID: `gradient-boosted-trees-xgboost-lightgbm-catboost`. Module `classical-ml`, Supervised Learning, position 4. Design prepared 2026-09-11 before production edits. This is the first of this author's two assigned topics; SVM follows after this topic's author verification. No shared catalogue or publication files are owned here.

## Outcome and scope decision

Keep **Gradient Boosted Trees (XGBoost, LightGBM, CatBoost)**. The title accurately owns an additive tree predictor, its loss-driven training, the consequential differences among these three libraries, and a reproducible validation-to-inference workflow. The learner should be able to calculate a correction tree, derive a regularized split, diagnose categorical or validation leakage, run each library with a stated objective and stopping rule, and explain what evidence would justify choosing one. A list of package reputations cannot achieve that outcome.

The registered conceptual prerequisites are **Decision Trees & Random Forests** and **Linear & Logistic Regression**, verified against the inventory. The optional executable branch also uses basic Python; its setup and operations are explained locally. Locally reintroduce a row, a feature, a regression leaf, mean squared error, a derivative as sensitivity, and a logit. The finite regression investigation needs averages and a small tree only. The derivative branch assumes elementary differentiation but derives the needed derivatives. No need to complete a later model-selection lesson first.

A learner's running question is: can a small sequence of corrections predict a numeric target without giving every row its own rule? Use the six-row teaching dataset `x=[1,2,3,4,5,6], y=[2,2,3,7,8,8]`, with explicit invented units (a scalar feature and a numeric response), then separately a reproducible synthetic regression experiment. These are teaching fixtures, not measured business or benchmark datasets. Give a concrete use such as predicting a machine's energy consumption from tabular operating measurements; make clear that the worked fixture is constructed and not operational evidence.

## Teaching flow and local derivations

1. **One useful correction.** Define prediction before target availability and why tabular interactions can defeat a straight-line fit. Establish the mean baseline and compute its error. Show a new point travelling through all saved trees and adding leaf values; inference never recomputes residuals using its unknown label.
2. **A tree fits the errors.** For a fixed partition minimize the sum of squared residual errors in each leaf, derive the mean by completing the square, then derive `SSE(after)=SSE(before)-eta(2-eta) sum_leaf n_leaf rbar_leaf²`. The guarantee applies to exact unregularized leaf means on the training partition, eta in [0,2], and not held-out performance. Explain why interaction capacity is controlled by leaves/depth and why greedily choosing a tree is not globally optimizing the ensemble. Present a complete small stump learner before the deeper recursive implementation.
3. **What changes with the loss?** Derive half-square `g=F-y,h=1`; binary log-loss `log(1+exp(F))-yF`, stable evaluation, `p=sigmoid(F),g=p-y,h=p(1-p)`. Scores add; probabilities do not. Mean/log-odds intercept optimum needs nondegenerate binary prevalence; finite smoothing is an explicit modeling choice. Briefly derive pinball loss's one-sided gradients and optimal quantile leaf as a useful planning application; no false generic second-order differentiability promise.
4. **Choose a leaf and a split.** Expand a twice-differentiable loss locally, collect `(G,H)` in each leaf, complete the quadratic, then compare children with their parent and charge one extra gamma. Derive `soft_threshold(G,alpha)` from the piecewise derivative; assume `H+lambda>0`. Hessian mass differs from row count except special losses/weights. A positive net surrogate gain is compared with zero (do not subtract/compare gamma twice). A Newton direction is approximate for logistic loss; shrinkage and actual loss inspection matter. Explain how scalar Hessian rules differ for multiclass and custom nonconvex objectives without promising the formula covers every objective unchanged.
5. **Make split search affordable.** Raw sorted values become candidate boundaries and prefix sums. Histograms collect current gradients/Hessians and restrict thresholds; they can change the chosen partition. Handle repeated values without illegal splits, choose missing-left/missing-right from training gain, and state sparse absence versus explicit zero. Show best-leaf growth and symmetric shared tests using actual tree geometry. Derive cost as sums over visited nodes and rounds rather than one universal package big-O; give bounded count examples and profile-versus-benchmark distinction.
6. **Keep some rows without pretending to keep all information.** GOSS retains `k` high-|g| rows and samples `s` of `r` remaining rows; inclusion `s/r`, weight `r/s`. Prove an individual weighted indicator and sum are unbiased conditional on current gradients, then show by enumeration why squaring changes expectation. EFB packs mutually exclusive bin IDs with nonoverlapping ranges; a conflict visibly destroys reversibility and is not silently accepted. Local algorithm examples do not claim production-library internal bit-for-bit equivalence.
7. **Categoricals and whose target is allowed.** A category is a group label, not an ordinal distance. Compare one-hot/partition splits with target statistics. Derive smoothed prefix numerator/denominator; flip the current row's target to expose naive own-target dependence and its absence from the fixed-prior prefix statistic. New categories receive the documented fallback; train-time prefixes and inference statistics differ. Separately show a model trained on earlier rows producing the current row's gradient. Explain CatBoost Plain versus Ordered and symmetric trees; avoid zero-expected-gradient claims. Time/entity leakage still needs the appropriate split.
8. **Stop and compare honestly.** Train affects parameters, validation selects iterations/settings, test estimates the locked workflow. An actual small same-data curve shows training improvements can accompany worsening validation. Explain learning-rate/round interaction, patience, best versus final iteration, and hyperparameter search using the same validation information repeatedly. Provide complete pinned CPU XGBoost native +wrapper, LightGBM, CatBoost regression and mixed categorical classification routes, including a mean baseline, shapes, untouched test evaluation and exact executed output. These are demonstrations, not fair-speed or universal-quality benchmarks. Monotone constraints encode a domain assumption; save/reload retains feature schema and best-round inference.
9. **Use, diagnose and transfer.** Add a model-failure table connecting observation to discriminating check: extrapolation of constant leaves, unseen categories, identifier leakage, shifted missingness, loss/metric mismatch, weighted probability interpretation, insufficient capacity versus noise fitting, serial rounds and memory. Explain split count/gain/permutation importance as different questions and correlated-feature caveats; route full attribution to its actual owner. Include a unique useful example (quantile maintenance stock or constrained operating response) with an actual loss/assumption rather than a decorative anecdote. Close changed-data practice, a reproducible report task and actual next-topic SVM bridge.

## Representations: each has a different job

All calculations are bounded deterministic teaching models. Every plot reports fixture/algorithm assumptions, axes/units and whether a quantity is training loss, surrogate gain or validation error. No hand-authored benchmark series. Labels remain readable at 320px; short views wrap/stack, dense tables may scroll locally with focus and a caption. Color is redundant with signs, labels and shapes. No auto-playing loop.

| Form | Learning hurdle and representation contract | Interaction / independent evidence |
| --- | --- | --- |
| Additive prediction figure | One feature row branches through small score trees, then sums baseline and scaled corrections. Ordinary reading makes inference visible before controls. | Static computed six-row first-round values; no extra controls. Verify sum against predictor. |
| Correction lab | Aligned target/current prediction, residual stems with shared leaf bands, and before/after points distinguish what a tree fits from what is finally predicted. | Step actual rounds, rate, bounded target draft; selected row links all views. Changing training inputs resets the trace explicitly. Verify all legal splits by independent enumeration and exact projection identity. |
| Newton split lab | Sorted row chips accumulate G/H into two leaf bowls and a parent-versus-children objective balance; classification additionally shows score→probability and actual loss change. | Candidate split, squared/logistic fixture, alpha/lambda/gamma/rate; zero/negative net gain stays visible without falsely growing a tree. Verify fixed-leaf optimum with independent scalar minimization and derivative/finite-difference checks. |
| Histogram/missing lab | Raw points map into labeled bins; only available boundaries remain active; missing rows have a separately drawn route. | Coarse/fine cut sets and missing-left/right; show candidate counts, computed best gain and lost fine threshold. Compare all partitions independently. |
| Growth figure | A specified hypothetical frontier-gain fixture yields distinct level-wise and best-first topology; an adjacent explanation distinguishes the additional symmetric-test constraint. Leaf count, depth and repeated predicates are visible. | Static shapes avoid turning a policy comparison into another plain stepper. | Ordered categorical lab | Rows on an ordered strip with a visible prefix boundary; only same-category earlier labels flow to the numerator. Separate own-label and later-label exclusions, prior and inference view. | Choose row/permutation/current label and smoothing from bounded options. Own-target flip changes naive encoding but not that row's fixed-prior prefix; later rows may change. Independent prefix enumeration includes singleton/unseen category. |
| Validation lab | Actual train/validation curves, selected snapshot predictor, best versus current markers and information-role strip. | Rate/depth/round cursor on a bounded fixture; expensive fits memoized when only the cursor moves. | Extrapolation/importance reading figures | A piecewise-constant prediction stays constant outside outer splits; importance definitions describe different operations instead of mismatched heatmap magnitudes. | The computed validation predictor also supplies exact horizontal extrapolation pieces. An extra unsupported heatmap is unnecessary. Advanced SHAP remains with its owner. |

Implementation may combine views that help one investigation or replace a proposed static form if actual reading shows redundancy; it may not replace an essential mechanism with generic text readouts. Final verification will state the actual forms, not merely this plan.

## Complete programs and changed practice contracts

Every program is self-contained with imports/data/setup, an explicit question before code, exact executed stdout and interpretation immediately after. Stdlib/NumPy routes precede optional library setup; pin tested versions and report CPU/thread settings. Keep numeric displays at meaningful precision, not misleading cross-platform bitwise promises. Native helpers must have input contracts and changed-input tests; no hidden fixture-only implementation.

Planned executable mechanisms: a complete stump boosting trace; the retained repaired depth-2 recursive learner and original 100-row fixture; half-square/logistic derivatives and stable loss; L1/L2/gamma split enumeration including the old valid five-row calculation; restricted histogram boundaries and learned missing route; finite GOSS expectation versus squared score; reversible EFB with rejected conflict; prefix target statistics and inference fallback; an ordered-prefix-model miniature; actual held-out stopping; pinned XGBoost native/sklearn/monotone/save-reload, LightGBM and CatBoost regression/categorical workflows; a pinball-quantile planning task if it remains locally useful. Program count follows these mechanisms, not a target.

Changed tasks include: a different response vector and shrinkage prediction; equal-feature unsplittable nodes and refit state; a logistic leaf with different prevalence; gamma exactly at net-gain boundary and an L1 zero leaf; a coarsening that removes the best split; a missing row whose best route changes; GOSS sampling stated as counts versus ambiguous fractions; own-target/earlier-target perturbations; a category occurring only in validation; an off-by-one XGBoost best iteration; a `(n,1)` versus `(n,)` accuracy bug; time/entity split choice; an extrapolation request; an honest speed measurement plan. Each has an optional hint before its explained acceptance result. The larger report task requires a changed seed/noise or depth and a baseline, fixed validation choice and untouched test evaluation; no promised winner or score.

Enumeration/rational arithmetic independently checks tree partitions, shrinkage, split gain and threshold boundaries; SciPy scalar minimization/finite derivatives check logistic approximations; actual Python implementations generate comparison fixtures. ## Final implementation and research disposition

The design has been implemented. See [the author verification](GRADIENT-BOOSTED-TREES-VERIFICATION.md) and its exact-source evidence packet for current status; independent review and production integration remain parent-owned. The original plan above is retained as rationale, not a claim that every initially proposed form was necessary.

- The finished lesson contains six distinct investigations and three ordinary-reading figures.
