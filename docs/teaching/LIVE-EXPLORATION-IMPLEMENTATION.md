Authorized 21 September 2026. The user wants interactive playable investigations that explain how inputs change mechanisms, outputs and practical decisions. Their correction explicitly removes prediction entry even as an optional feature. This supersedes the older predict/commit/reveal lab contract; scientific predictions produced by a model and separate independent practice remain part of teaching.

## Interaction contract

Start with a useful visible state. Expose meaningful input variables using sliders, toggles, selectors, direct manipulation, editable examples and topic-specific process controls. Recompute valid inexpensive edits immediately. Keep diagrams, formulas, tables, metrics and explanatory text on the same state. Show how a change travels through the process and what decision it informs; before/after comparisons and deterministic reset should make contrasts easy to inspect.

Use step/run controls when the action itself is the concept or an expensive operation needs an explicit request. An incomplete text draft may retain a clearly labeled last valid result; never relabel an old result as belonging to invalid new input. A computational Run/Apply control is not a quiz gate. Preserve actual data-access and evaluation boundaries such as development versus held-out data; distinguish those domain constraints from arbitrary pedagogical concealment.

Do not replace varied diagrams with a generic result box, invent slider-dependent data, introduce fake grades or prefill a correct answer behind a hidden prediction form. Remove the obsolete quiz state and dependencies. Mathematical models, native examples and existing depth are retained unless a separate confirmed defect requires correction.

## Review boundary

Reuse numerical evidence when its inputs and model sources are unchanged. Verify the changed input-to-output wiring, valid/invalid states, resets, meaningful unchanged outcomes, keyboard controls and responsive informative states. Current checks must test the new behavior rather than preserve old assertions that an answer must be hidden. Preserve earlier receipts as dated evidence. Record actual opened images separately from automated scans.

## Limits and continuation

This is a scoped interaction migration, not a new mathematical audit of the entire curriculum or proof of every control combination. Unchanged numerical evidence was reused where applicable; full-page smoke checks are distinguished from actual control tests. Rendering was checked in one Chromium-family engine. Exact existing font fixtures were used because the sandbox blocks the remote font service. User acceptance is separate from these checks.

Retain the source-bound reports, original prepared-text archive, purposeful verifiers and referenced font fixtures. Task-owned transforms, transient source scans, disposable cache and the ledger-update utility were removed after use; unrelated scratch work was preserved. Continue only from the user’s next request. A prepared topic still requires an authorized finish phase; a later revision should preserve these frozen aggregate reports and write its own current topic contract.
