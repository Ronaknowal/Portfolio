## Material corrections for the rewrite

### Optimization, initialization and returned state

1. **Strict decrease and termination:** line 49 claims every half-step strictly decreases and a lower bound proves termination; lines 179/884 repeat an incomplete finite-partition argument. Assignment is nonincreasing; a mean update is strictly improving only when a nonempty cluster's center moves. A bounded decreasing numerical sequence need not terminate. State exact arithmetic, consistent tie handling, empty-cluster policy and stopping criterion. The original k-means++ paper explicitly requires consistent assignment ties (§2.1) and supplies the mean identity (Lemma 2.1). Show why a changed nonempty mean gives a strict reduction, then use finitely many means/partitions under the stated convention. A finite tolerance/iteration cap is a separate implementation stop. [Arthur–Vassilvitskii, §§2.1–2.2](https://theory.stanford.edu/~sergei/papers/kMeansPP-soda.pdf#page=2).
2. **Fixed point versus optimum:** an assignment/mean fixed point is not a global certificate. Avoid an unqualified strict-local-minimum statement for degenerate tied configurations. Line 329's agreement with sklearn does not establish a global optimum. Initialization stability is empirical evidence, not proof of optimality.
3. **Vanilla versus greedy seeding:** the original theorem is an expectation over **vanilla** uniform-first, D²-sampled seeding, with `E[Φ] ≤ 8(ln k + 2)Φ*`; it is not a per-run or ground-truth-recovery promise. Subsequent nonincreasing Lloyd steps retain that bound for that procedure. sklearn's greedy multi-trial seeding is different; do not assign the original theorem to it without another theorem. The original helper divides by zero after all distinct locations are represented. Specify zero total D², duplicate points, accepted k and finite inputs before producing probabilities.
4. **Returned-state coherence:** the original loop retains an empty center. At an iteration cap its returned updated centers and assignment labels need not describe the same nearest-center assignment; `n_iter=0` also leaves labels undefined. Choose and explain a coherent API. sklearn itself reassigns final labels to agree with prediction on the training data, but capped/tolerance-stopped centers may not be those labels' means. Its current defaults are greedy seeding and `n_init='auto'`, with one run for `init='k-means++'`, ten for random/callable initialization. Pin explicit choices. [KMeans 1.9.1 parameters/Notes](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html).
5. **Empty clusters:** line 786's claim that sklearn simply keeps the old center is false for the inspected version. Installed `_k_means_common.pyx:167–212` selects farthest assigned observations and transfers their weighted contribution; it skips relocation when all distances vanish. `_average_centers:276–295` places any remaining empty center at the largest-weight cluster. The teaching policy may differ, but must be identified as such. Read directly from the installed sklearn **1.9.1** Cython source; the documentation's GitHub source fetch was unavailable during this review, so no remote-source inspection is claimed.

### Ward, linkage and cuts

The mathematical definition and the library representation must use different names:

`Δ(A,B) = |A||B|/(|A|+|B|) · ||mean(A) − mean(B)||²` is the **increase in SSE**.

SciPy's Euclidean Ward height is `h = sqrt(2Δ)`. Thus **`Δ = h²/2`**, not `h²`. Line 223 drops the factor two, while lines 546–548 incorrectly identify SciPy's height as plain centroid distance. Only two singleton clusters have that simpler equality. A plot may use Δ or h if clearly labeled; cut thresholds must use its chosen scale.

One checked reproduction retained the original six-point fixture and independently subtracted the three directly calculated SSEs:

| Merge IDs | Δ SSE | SciPy height h | Merged observation count |
| --- | ---: | ---: | ---: |
| 2, 3 | 0.125 | 0.5 | 2 |
| 0, 1 | 0.25 | 0.7071067812 | 2 |
| 4, 5 | 0.25 | 0.7071067812 | 2 |
| 6, 7 | 7.0625 | 3.7583240946 | 4 |
| 8, 9 | 56.0208333333 | 10.5849736262 | 6 |

The equal-cost second/third merge order is one tie convention. A hierarchy is **one greedy nested family**, not every possible partition or a globally optimal k-partition. Specify cut intervals rather than “above 7” indefinitely. Leaf order is not a horizontal distance axis.

SciPy's linkage matrix fourth column is observation **count**, not the newly allocated cluster ID. Single, complete and average use min, max and average cross-cluster dissimilarities; average is not the unweighted average of previous cluster distances. Ward requires Euclidean geometry. SciPy's documented exact implementations are O(n²) time for single/complete/average/weighted/Ward, O(n²) memory, not a universal O(n² log n) priority-queue implementation. [SciPy linkage definitions, Warning and Notes](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.linkage.html).

`fcluster(..., criterion='maxclust')` produces **at most** the requested number. For the square `(0,0),(0,1),(1,0),(1,1)`, Ward heights are `1,1,sqrt(2)`: `maxclust=3` yields two clusters, whereas cutting the binary merge sequence with `cut_tree(n_clusters=3)` yields three. An exact merge-count cut can resolve a tied level that no single horizontal threshold separates. [fcluster criterion](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.fcluster.html). The finite check used NumPy 2.3.5, SciPy 1.18.1 and sklearn 1.9.1; it checked this distinction and the five SSE/height identities without new scratch files.

### Diagnostics, representation and unsupported claims

- The first plot says “150-point” but contains **45 hardcoded points**. Its displayed centroids are from another calculation. Either use the actual generated observations or label an explicitly selected subset; do not imply the image is a full execution trace.
- The hardcoded elbow values give a **53.3609%** reduction from k=3 to k=8, not line 621's 14%. The roughly 14% reduction is k=3 to k=4. Generate the whole curve from a named fixture/seed/restarts. The globally optimal SSE is nonincreasing with k; separately fitted local solutions need not be. Two adjacent k values cannot establish an elbow.
- Silhouette uses average own-cluster distance excluding self and the smallest average distance to another cluster. Handle singleton/zero-distance cases explicitly; sklearn requires `2 ≤ number of labels ≤ n−1`. A negative value is a geometry warning, not an independently observed misclassification. The score does not certify semantic truth or universally select the right k. [Silhouette API definition](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.silhouette_score.html).
- Scaling is a choice of geometry. “Always standardize” is wrong: changing feature units without corresponding weights changes the objective; whitening adds another choice. Fit preprocessing only on the intended training portion when evaluating future assignment/downstream prediction. PCA reduces feature dimension, **not** the n×n pairwise-matrix size. A 2D embedding can distort the grouping question; it is not validation.
- Replace the “ring into two halves is impossible” claim: two halves can be linearly separated. Concentric inner/outer rings give the intended contrast with one convex Voronoi cell per ring. Shape/size preferences are tendencies of the objective, not requirements that all fitted clusters are equal-sized spheres. RBF kernels do not guarantee useful spherical clusters after mapping.
- Remove unsupported 0.3 silhouette cutoffs, 5–10% restart-spread diagnoses, dimensional/sample-count thresholds, GPU runtime claims and universal HDBSCAN O(n log n) claims. A “poorly conditioned problem” is not defined by restart spread. Density methods and mixtures solve different modeling problems; a fitted GMM posterior is not automatically calibrated against external outcomes.
- Means can be strongly affected by extreme observations, but medoids and complete/average linkage are not universally outlier-proof. Avoid automatic 3σ removal. Keep arbitrary-label invariance; matching labels across months requires a justified geometry and population correspondence, not a blanket centroid-cosine rule.
- The equal-isotropic-variance GMM limit needs a **unique nearest mean** and fixed positive mixture weights for a one-hot limit. Exact nearest-mean ties retain relative mixture weights; the tie is not resolved by taking variance to zero.

## Scale and alternative-objective boundaries

- **Mini-batch:** teach cumulative counts/running-center updates and stochastic full-data objective behavior. `MiniBatchKMeans.n_init` chooses a best initialization before **one** optimization run; it does not perform that many full runs. `compute_labels=False` exposes an approximate inertia based on smoothed batch values. Avoid asserting that every mini-batch result must be worse than every Lloyd run. [MiniBatchKMeans parameters/Notes](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.MiniBatchKMeans.html).
- **BIRCH:** CF summaries store count, linear sum and squared sum. This supports a useful exact identity: for fixed microclusters, original SSE equals within-microcluster SSE plus **count-weighted** centroid distortion. That does not permit splitting a compressed microcluster later. Current sklearn `_birch.py:688–732` globally calls `fit_predict(subcluster_centers_)` without original counts; do not describe this as exact weighted full-data k-means. [Birch parameters/Notes](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.Birch.html). Both the docs and the installed 1.9.1 implementation were inspected.
- **Spherical/cosine:** normalizing observations once is not ordinary k-means equivalence. A unit query `(1,0)` has squared Euclidean distances `0.81,0.4` to centers `(0.1,0),(0.8,0.6)` but cosine similarities `1,0.8`; assignments reverse. Spherical updates normalize each nonzero cluster resultant and assign by dot product. Define zero-vector and zero-resultant behavior. [FAISS FAQ, cosine subsection](https://github.com/facebookresearch/faiss/wiki/FAQ#k-means-for-the-cosine-similarity). Only this local objective derivation, not the page's unrelated complexity heuristics, is used.
- **Medoids:** select representatives from observations and minimize the sum of the chosen dissimilarity, not necessarily squared distance. Initialization, optimization and robustness are separate properties. The inspected sklearn-extra implementation stores an O(n²) distance matrix; that is a library contract, not the complexity of every medoid algorithm. Its docs even warn that BUILD initialization can be non-robust. [KMedoids 0.3.0 API](https://scikit-learn-extra.readthedocs.io/en/stable/generated/sklearn_extra.cluster.KMedoids.html). Package compatibility/execution was not tested; use a small native example rather than an unverified installation promise.
- **Memory accounting:** O(nkdI) describes straightforward feature-distance work, not an exact FLOP count. Materializing n×k distances is avoidable; sklearn's Elkan variant specifically allocates an extra n×k array. Distinguish full from condensed n×n storage and label any measured benchmark with its actual execution conditions.
