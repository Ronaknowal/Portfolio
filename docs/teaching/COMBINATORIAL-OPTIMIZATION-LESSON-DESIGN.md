## Technical contracts to preserve

- Approximation algorithms need a polynomial-time guarantee under the stated input representation; a bounded browser brute-force reference is a small oracle, not that algorithm. A heuristic can have any runtime contract; do not repeat the old source's blanket polynomial-heuristic description.
- General exact NP-hard optimization has no known polynomial algorithm under P≠NP, but a particular instance or structured subclass may solve quickly. Ordinary decision reductions do not preserve multiplicative approximation. A short gap-TSP argument can illustrate the difference without a survey of unverified hardness constants.
- Compare costs without silently adding constants when cardinality varies; adding a constant to every chosen item preserves only objectives with the same number of items. Ratios can change under objective shifts even when the optimizer does not.
- Matroid greedy assumes access to a correct independence test. Reject cycles for a graphic matroid, not every graph with a loop-shaped drawing. Signed weights require the explicit base/unrestricted distinction.
- Knapsack uses positive weights, nonnegative values and a nonnegative capacity. Remove infeasible items before choosing Vmax or the best singleton; handle empty/all-zero-value cases. A naive density prefix alone does not have the stated1/2 guarantee; compare a legal prefix with the best feasible singleton.
- Assignment uses an explicit required cardinality, missing edges and integer costs. Its initial source→worker→job→sink network is acyclic, so signed costs do not create an initial negative cycle. Successive shortest residual paths preserve minimum cost for each attained size. Explain its O(FVE) Bellman-Ford runtime and O(V+E) working space, plus stored trace; do not call this the optimized O(n³) Hungarian implementation.
- For a general finite-capacity network with initial negative cycles, zero flow need not minimize cost even at value0; cycle cancellation or an appropriate initialization is required. Local reverse-edge cost negation is essential. Native algorithm rejects an unsupported negative-cycle contract rather than returning a claimed optimum.
- Weighted bipartite vertex cover reduces to an s–t cut using vertex costs on source/left and right/sink arcs and crossing capacity greater than the sum of all vertex costs. General weighted vertex cover does not inherit this exact reduction.
- Cover rounding includes x=.5, not only greater than. Nonnegative costs are necessary for the simple inequality. Dual lower bounds stay feasible at each step; an uncovered zero-cost endpoint should be selected without a stalled positive update.
- Set-cover charging uses actual harmonic numbers with the≤1+ln n estimate for n≥1; do not copy a shorthand “≤ln n” that fails at n=1. Zero-cost useful sets are selected safely; an uncovered element in no candidate yields explicit infeasibility.
- Submodular guarantees require normalization, monotonicity, nonnegative values, cardinality constraints and exact/good-enough marginal access with any additional approximation accounted for. A set-cover minimum-cost theorem is a different objective and factor.
- FPTAS default convention here is maximization value≥(1−ε)OPT for0<ε<1. Translate to a1/(1+δ) convention by ε=δ/(1+δ). Rounding values does not round weights; DP recovery must retain each item at most once.
- Christofides requires a complete undirected metric and nonnegative edge costs. A general graph metric closure preserves walk cost, not arbitrary original Hamiltonian-tour constraints. No “best known today” approximation claim will be inferred from a2008 lecture.
- Every plotted point, state or bound is derived from a named finite fixture/model. No invented benchmark arrays or empirical solver rankings.
