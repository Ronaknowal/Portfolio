## Finish line and teaching contracts

### A. One successor, two traversal speeds

Begin with repeated values versus the same node object. Keep the visited-identity baseline: the first repeated identity is the reachable cycle entry, with expected linear set work and O(n) stored identities. The stronger contract returns that same object without rewriting links, using O(1) working references. It assumes a finite, unchanging reachable Node/None successor chain; this is not a general branching-graph cycle algorithm or concurrent-mutation detector.

Draw the distinct prefix followed by the cycle, define μ as edges from head to entry and λ as cycle length. Both pointers start at head; compare only after slow advances one link and fast two. Guard fast and fast.next before following two links; no-cycle/empty cases return None. At iteration t they reach f^t(head) and f^(2t)(head). Once both are inside, their cycle offsets differ by t modulo λ. Increasing t by one visits every residue, so a positive meeting occurs within O(μ+λ) rounds. Equality at initialization is not evidence of a cycle.

At a meeting, λ divides t, but the meeting need not be the entry. Reset one pointer to head and advance both one edge. After μ steps the reset pointer reaches the entry; the old meeting pointer has traveled t+μ overall, with cycle offset t modulo λ = 0. They cannot meet earlier because the reset pointer is still in the noncyclic prefix. μ=0 works immediately after reset. Count one loop from the entry to obtain λ if requested. A self-loop has λ=1. More general speed ratios can meet yet fail this particular reset proof: do not suggest arbitrary speeds can be substituted blindly.

Worked fixture: seven nodes n0→…→n6→n2, all values allowed to equal 7. μ=2, λ=5, first positive meeting t=5 at n5; reset pairs (n0,n5),(n1,n6),(n2,n2). Changed task uses μ=4,λ=3: meeting t=6 at n6, entry n4. The browser's stored trace is diagnostic storage, not the constant-space algorithm itself.

**Investigation:** a literal successor path with a curved last-to-entry arrow or self-loop, two separately labeled pointer positions, intermediate fast hop, trace counts and a meeting/entry phase change. Controls choose bounded length/tail link, including empty, acyclic and self-loop presets; edits reset the trace. Distinct identity/value labels and a repeated-value toggle expose the equality mistake. Prev/next/reset are manual and keyboard accessible. Preserve readable native geometry with local keyboard scrolling where necessary, never shrink nine node labels to unreadable text.

### B. A middle node is a policy, and a split is a mutation

On an acyclic length-n chain, slow=head and fast=head with the two-link guard yields index floor(n/2): the second middle for even n. For the first-middle/split convention, after the empty check, continue while fast.next and fast.next.next exist; slow stops at index floor((n−1)/2). Prove using slow index k and fast index 2k and the corresponding guard; do not memorize a starting offset without stating its result. A left-heavy split cuts after that first middle, producing sizes ceil(n/2) and floor(n/2), preserving original identities/order. Save right=slow.next before assigning slow.next=None. Empty returns two None references, singleton stays entirely left. The complete split helper first checks acyclicity in constant working space and rejects a cycle before changing links.

**Investigation:** one acyclic chain with both middle choices labeled, a length slider and first/second policy; a separate cut toggle illustrates the single changed link and both returned heads. The cut always uses the stated left-heavy boundary, regardless of the selected middle query. Explain aliases and why a caller must retain both heads. This supports merge/reorder readiness without introducing their full algorithms or recursion here.

### C. Let a new value settle earlier unresolved questions

Start with the correct nested-search baseline: for each position i, find the first j>i with a[j]>a[i], returning j−i or zero if absent. Worst-case decreasing input takes quadratic comparisons. Then scan left to right with a stack of unresolved indices, increasing by position and nonincreasing by value. On a new j, repeatedly pop indices with smaller values; each receives j−i. No earlier processed position could have answered an unresolved index. Anything hidden below a top value at least a[j] is also at least a[j], so stopping is safe. Equal values stay for strictly-greater queries; `>=` would answer a different problem. Pop removes the stored index, not data from the input.

Worked readings [6,6,4,7,5,8] have strict distances [3,2,1,2,1,0]; at index3/value7, one arrival resolves indices2,1,0 in that order. A counterexample [5,5,6] yields [2,1,0], whereas greater-or-equal gives [1,1,0]. Empty gives []; arbitrary integer readings are allowed in native code, while browser bounds are explicit. Store indices to preserve duplicates and distances. Each index is pushed once and popped at most once: at most 2n stack modifications, hence linear total work despite a potentially linear single arrival. Output and worst-case working stack are each O(n). This is different from the expiring/dominance deques owned by Range Queries.

**Investigation:** aligned reading bars with their exact positions, a current-arrival cursor and a literal unresolved-index stack (bottom→top), each pop shown as an arrow to its first qualifying future index and a difference calculation. Step separate pops and push; compare strict versus greater-or-equal with an explicit changed-contract label. Editable bounded integers apply transactionally; invalid input preserves the active trace. Presets include equal, decreasing, multi-pop, empty. Results distinguish unresolved from the final no-future zero.

### D. Nearest smaller boundaries turn a stack into geometry

For each histogram bar, find the nearest strictly smaller index on the left and on the right. In each directional scan, pop heights greater than or equal to the current height. The remaining stack is strictly increasing by height. Why a popped candidate is never needed: the new index is nearer to future queries and no taller, so any future value for which the old candidate qualifies also accepts the new one. This is candidate dominance, not answering an earlier next-greater question; spell out that difference. Mirror the scan for the right boundary, using −1/n as absent boundaries.

Every bar between L_i+1 and R_i−1 is at least h_i; the rectangle has width R_i−L_i−1 and area h_i times width. Boundaries themselves are excluded. Equal bars are not blockers; removing them in both scans lets each equal-height minimum see the full valid plateau. To prove maximality, choose a minimum bar in any candidate rectangle; its canonical boundary rectangle contains that interval and has at least its area. Taking the largest computed candidate therefore reaches an optimum. Unit-width/nonnegative-height conditions remain beside the claim; unequal widths require prefix coordinates and a changed width formula.

Use a two-pass implementation and explicit boundaries rather than adding a second compact one-pass histogram trick. Fixture [2,2,1,4,4,3] has L=[−1,−1,−1,2,2,2], R=[2,2,6,5,5,6], candidate areas [4,4,6,8,8,9], maximum9 over indices3..5 at height3. [2,2] exposes equal-bar blocking; [0,0] returns area0 and no positive rectangle witness. Independent changed [3,1,3,3,2] has maximum6 (width3 at height2 or width2 at height3); explain ties rather than promising a unique optimum.

**Investigation:** actual unit-width bars and a selected candidate rectangle, its excluded smaller boundary bars, exact width/height multiplication and both boundary tables. A scan trace exposes the candidate stack and each dominance pop; direction/selected-bar controls make the left/right reasoning inspectable. Height edits/reset are deterministic; zero-height/empty states remain meaningful. Histogram is optional depth, after the next-greater mechanism, not a prerequisite for continuing to Trees.
