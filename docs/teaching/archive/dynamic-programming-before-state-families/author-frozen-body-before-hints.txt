    <H2>1. Solve a smaller question and reuse its answer</H2>
    <Prose>A device has four experiment sessions in order, with rewards [4,7,2,9]. It needs one session of recovery after any session you run, so you cannot select adjacent positions. You may select none. Which legal selection gives the largest total reward? Running sessions 1 and 3, using zero-based indices, earns 7+9=16.</Prose>
    <Prose>Backtracking gives a correct baseline: decide whether to take each position, reject adjacent selections and compare totals. But different prefixes repeatedly ask the same remaining question. After earlier decisions are settled, does the whole history matter—or just where the next free part begins?</Prose>
    <H3>Define the answer before the table</H3>
    <Prose>Let <Code>F(i)</Code> mean “the largest additional reward obtainable from positions i through n−1, when position i is free to choose.” Here n is the number of sessions. This is a <strong>subproblem</strong>: a smaller version of the original task. Its <strong>state</strong> is the information identifying that question, currently the index i under a fixed reward list and a fixed entry contract.</Prose>
    <Prose>At position i there are two exhaustive possibilities. Skip it, leaving the free suffix at i+1. Or take it, earn reward[i], skip its recovery neighbor and continue with the free suffix at i+2. We do not commit greedily to the larger immediate reward; we compare the full consequences.</Prose>
    <Prose><Code>F(i) = max(F(i+1), reward[i] + F(i+2))</Code>. In words: choose the better of skipping now and taking now plus the best permitted future. When i is at or beyond n, there is nothing left, so F(i)=0. The original answer is F(0).</Prose>
    <LessonTable caption="Work backward on the same four sessions" headers={['State', 'Skip', 'Take', 'Best']} rows={[
      ['F(4), F(5)', 'No sessions remain', 'No selection', '0'],
      ['F(3), reward 9', 'F(4)=0', '9+F(5)=9', '9'],
      ['F(2), reward 2', 'F(3)=9', '2+F(4)=2', '9'],
      ['F(1), reward 7', 'F(2)=9', '7+F(3)=16', '16'],
      ['F(0), reward 4', 'F(1)=16', '4+F(2)=13', '16'],
    ]} />
    <Prose>A <strong>recurrence</strong> is this rule expressing an answer through smaller answers. It is justified, not guessed: every legal selection either omits i or contains i and omits i+1. Each category is legal when combined with the stated smaller problem, and no other category exists. Replacing its remaining suffix by a better legal suffix would improve the full selection, so an optimum can use optimal suffix answers. This property is often called <strong>optimal substructure</strong>.</Prose>
    <Prose>The proof proceeds from smaller suffixes to larger ones. Empty suffixes are correct. Assuming the required smaller answers are correct, the exhaustive skip/take rule gives a correct answer for i. Each recursive call increases i, reducing the remaining length until a base case. That establishes both correctness and termination.</Prose>
    <H3>One recurrence, two evaluation strategies</H3>
    <Prose>A plain recursive implementation expands the same F(i) repeatedly. <strong>Memoization</strong> records each completed answer under its state key and returns it on later requests. <strong>Tabulation</strong> schedules the states explicitly so each dependency is already available. Both are forms of <strong>dynamic programming</strong>: organize reusable subproblem answers instead of solving the same complete question repeatedly.</Prose>
    <RewardDependencyLab />
    <Prose>A call tree gives each invocation its own node. A dependency graph merges invocations of the same state into one node. It is a directed acyclic graph here: arrows advance the index and cannot return to an earlier state. The lab's arrows point from a question to the answers it needs; evaluate dependencies before their users. Other books reverse arrow direction, so always read the legend.</Prose>

The decorator <Code>@cache</Code> is available from Python 3.9 and stores results by hashable arguments. The local function creates a fresh cache for each fixed tuple of rewards.</Prose></RunnableExample>
    <Prose>There are n non-base suffix states, at most two empty-suffix indices, and constant arithmetic/lookup work per evaluated state. Under the usual unit-cost arithmetic and expected dictionary-access model, memoization takes O(n) work and O(n) cache plus stack space. It still uses O(n) recursive depth, so long inputs can exceed Python's recursion limit. Tabulation avoids recursive frames.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.rewardWitness}><Prose>Bottom-up does not mean increasing the index: this recurrence reads i+1 and i+2, so its loop runs backward. The second pass follows choices whose value equals the optimum. Skipping on a tie gives a deterministic witness; [2,2] therefore chooses position 1. It does not promise the earliest index or the largest number of selected sessions.</Prose></RunnableExample>
    <Prose><strong>A score is not a plan.</strong> Storing the scalar value at each state is enough to recompute a winning branch during reconstruction. Alternatively, record a chosen branch or predecessor when writing the state. Each reconstructed transition must obey the original constraints and account for the recorded value. Enumerating all tied plans can have exponentially large output even when computing the best score is linear.</Prose>

    <H2>2. What must a state remember?</H2>
    <Prose>A cache can make a wrong function return its wrong answer faster. Two histories may share a key only when that key and the fixed input determine the same remaining choices and the same meaning of their result. The exact past can differ; the relevant consequences of the past cannot be discarded.</Prose>
    <StateHistoryFigure />
    <Prose>Suppose a generic search moves forward by one session after every choice. At index 3, a previous selection may block the last reward 9 or leave it free. <Code>solve(3)</Code> cannot represent both questions. Use <Code>solve(index, blocked)</Code>, where blocked tells whether the preceding session was selected. Taking sets the next state's flag; skipping clears it.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.state}><Prose>The first two calls operate on the same suffix [9] but have different entry permissions, producing 9 and 0. The earlier F(i) avoided this extra dimension by jumping two positions after a take, guaranteeing every entered suffix was free. A stronger function contract can remove a state variable; omitting the variable without maintaining that contract cannot.</Prose></RunnableExample>
    <H3>Ask for the future contribution, not the whole history</H3>
    <Prose>Accumulated reward need not be in the suffix key because solve returns only the best <em>additional</em> reward. The caller adds the reward already earned. If instead a function returns an absolute total depending on a mutable outer accumulator, caching only index and blocked becomes invalid. Define the returned quantity so irrelevant history can be factored out.</Prose>
    <Prose>The Backtracking lesson's word-path counterexample shows the same principle: two prefixes can reach the same cell and letter index with different cells already used. The visited subset affects legal next moves. Later in this lesson we encode such finite subsets explicitly. The number of complete states may still be exponential; caching does not promise a small state space.</Prose>
    <LessonTable caption="Specify a dynamic program before implementation" headers={['Question', 'What a precise answer contains']} rows={[

    <Prose><strong>Fixed input is part of the contract.</strong> A cached function closing over a changed grid or price list can reuse stale results even with perfect state parameters. Use an immutable problem snapshot and a fresh cache, or an explicit version/key that captures the change. Lists cannot directly be cache keys; converting a large list to a tuple for every call also costs time. State encoding and cache lifetime are algorithmic choices.</Prose>
    <Prose><strong>Unknown, impossible and zero are different.</strong> Testing <Code>if memo[key]</Code> misses legitimate zeros. Test whether the key exists or use an explicit sentinel. A recursive call that re-enters the same unresolved state is not a cache hit: no answer exists yet. A cyclic dependency needs a different formulation or algorithm, such as an added step-budget dimension; a decorator alone does not solve it.</Prose>

      <Prose>Add the number of required remaining selections: F(i,k). Skip uses F(i+1,k); take uses reward[i]+F(i+2,k−1). F(i,0)=0. An empty suffix with k&gt;0 is impossible, represented by a sentinel or negative infinity under maximization. Zero would invent an unearned successful selection. This is a new constraint dimension, not merely a different final loop.</Prose>

    <H3>Repair the weighted scheduling choice from Greedy</H3>
    <Prose>The previous lesson's earliest-finish rule maximized the <em>number</em> of nonoverlapping jobs. It cannot automatically maximize their values. Job A occupies [0,5) and is worth 10; B occupies [0,2) and C occupies [2,5), each worth 4. Half-open intervals permit B and C to touch at time 2. Earliest finish selects two jobs worth 8; selecting only A gives 10.</Prose>
    <WeightedIntervalFigure />
    <Prose>Sort jobs by finish time. Let W(i) be the largest total value obtainable from the first i finish-ordered jobs, allowing an empty selection. For the current job at zero-based sorted position i−1, let p be the number of earlier jobs finishing no later than its start. Those compatible earlier jobs form a prefix because finishes are sorted.</Prose>
    <Prose>Skip the current job and keep W(i−1), or take its value v plus W(p). Thus W(i)=max(W(i−1),v+W(p)), with W(0)=0. Positive duration ensures p≤i−1; both candidates use completed earlier states. The prefix definition removes the need to retain every selected earlier job in the key.</Prose>
    <Prose>The proof partitions schedules by whether they contain the final finish-ordered job. If they contain it, every other selected earlier job must finish by its start. Conversely, every compatible-prefix schedule can be extended by it. Taking the best candidate in both exhaustive categories is safe; an unconditional earliest-finish exchange failed precisely because it could lose value.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.weightedIntervals}><Prose><Code>bisect_right(finishes,start,0,index)</Code> returns a compatible <em>prefix length</em>, not a job index: all earlier finishes equal to the start are included. A full finish sort and these boundary queries take O(n log(n+1)) time, followed by O(n) DP/reconstruction work, using O(n) storage. Original indices preserve job identity, even with tied finishes. Reconstruction skips on tied values; empty and all-negative-value cases can return no jobs.</Prose></RunnableExample>
    <Prose>If C's value increases from 4 to 7, B+C becomes worth 11 and the same recurrence switches to those two jobs. This is a useful transition from “choose locally and prove the exchange” to “retain complete smaller alternatives and compare their total consequences.” It is the problem's objective and constraints—not the word scheduling—that determine the algorithm.</Prose>

    <H2>3. Grow an answer across a grid</H2>
    <Prose>A small route planner moves only right or down through a rectangular cost grid. It pays the cost of every visited cell, including start and finish. Some cells may be blocked. Find the cheapest route from the upper-left to the lower-right and return its coordinates. This models a constrained staged route, not unrestricted movement on a real map.</Prose>
    <Prose>Let <Code>C(r,c)</Code> be the cheapest total for a route ending at cell (r,c). Every non-start path arrives from above (r−1,c) or left (r,c−1). For an open reachable cell, add its cost to the minimum of those available predecessor totals. A blocked cell, or one with no reachable predecessor, is unreachable. The start's value is its own cost if it is open.</Prose>
    <GridDependencyLab />
    <Prose>On the displayed grid, C(1,1)=1+min(7,3)=4. Later C(2,3)=1+min(11,6)=7. The witness follows costs 1→2→1→1→1→1. The choice is based on full prefix totals, so a cheap next cell alone does not establish a cheap entire route.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.grid}><Prose><Code>None</Code> means blocked in the input and unreachable in the result table; zero remains a real cost. Constructing rows with a comprehension gives independent row lists. <Code>[[None]*columns]*rows</Code> would alias one shared row. The function preserves its input and chooses the upper predecessor on equal costs.</Prose></RunnableExample>
    <Prose>The row-major loop solves above and left before using them. Induct on r+c: the start is correct, and every other legal path ends with one of the two listed moves. Replacing its prefix by a cheaper valid prefix preserves the endpoint and improves or preserves the total. Both predecessor coordinates have smaller r+c, so dependencies cannot cycle. Reconstruction repeatedly follows a predecessor and therefore reaches the start.</Prose>
    <Prose>This proof still works with negative cell costs: a path cannot loop because it only moves right/down. Allowing all four directions changes the dependency graph and may introduce cycles; with suitable negative cycles, an unrestricted cheapest walk may not even have a finite minimum. Do not transplant this recurrence or Dijkstra's assumptions without revisiting the movement and cost contract.</Prose>
    <H3>Same geometry, different question</H3>
    <Prose>To count all valid right/down paths, store <Code>ways(r,c)</Code>. The open start has one zero-move path; blocked/unreachable cells have zero. Add the counts from above and left because the final-move categories are disjoint. Taking min would answer the wrong question. The lab displays both counts and minimum costs from the same cells; its path count is <em>all</em> valid paths, not the number tied at the minimum.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.gridCount}><Prose>While updating left-to-right, ways[column] still represents the cell above, but ways[column−1] already represents the current row's left neighbor. That mixture is exactly what the recurrence needs. Setting a blocked cell to zero erases a stale route that cannot pass through it.</Prose></RunnableExample>
    <Prose>For R rows and C columns, full tables require O(RC) arithmetic operations and storage, plus O(R+C) output coordinates for one path. The count-only program uses O(C) entries. Counts may become large integers, so these are arithmetic-operation/entry bounds, not constant bit costs. If a route is required, discarding the parent information requires a separately justified reconstruction method.</Prose>
    <Checkpoint prompt="A one-cell open grid has cost −3. What are its minimum cost, path count and witness? What changes if that cell is blocked?">
      <Prose>Cost −3, one path and witness [(0,0)]. No move is required, but the start is still visited and paid. Blocking it makes the route impossible: None, zero paths and no witness. A zero-length move sequence and no valid route are different objects.</Prose>
    </Checkpoint>

    <H2>4. Align two sequences</H2>
    <Prose>A <strong>subsequence</strong> keeps elements in their original order while allowing gaps. A <strong>substring</strong> must be contiguous. In CABAC and ABC, the subsequence ABC occurs in both, although the first input skips its first C and later A. Comparing sequences requires a state describing how far we have considered <em>each</em> input.</Prose>
    <Prose>Let <Code>L(i,j)</Code> be the longest common subsequence length of first[:i] and second[:j]. These are prefixes of lengths i and j, so their last characters are at i−1 and j−1. If either prefix is empty, the answer is zero. For equal final characters, retain one matching pair and add one to L(i−1,j−1). For different final characters, the pair cannot be matched: at least one must be excluded, giving max(L(i−1,j),L(i,j−1)).</Prose>
    <Prose>Why can equal final characters be used safely? A best common sequence can align its final occurrence of that character to these later positions without disrupting earlier matches. More generally, removing the final characters from both prefixes can remove at most one matched pair from any alignment; adding their common character to an optimum for the shorter prefixes attains that upper bound. For unequal characters, excluding at least one endpoint covers every alignment. Induction on i+j then establishes the recurrence.</Prose>
    <SequenceAlignmentLab />
    <RunnableExample example={dynamicProgrammingExamples.lcs}><Prose>The table has an extra initial row and column for empty prefixes. Backtracking through equal final characters copies a match; moving up or left skips a character. Build the answer in reverse, then reverse it once. Preferring up on a mismatch tie gives a reproducible answer, not every answer or a lexicographically minimal answer.</Prose></RunnableExample>
    <Prose>For positive input lengths m and n, filling the table costs O(mn) fixed-size comparisons/updates and entries. Including empty inputs and initialized boundaries, write O((m+1)(n+1)). Recovering one sequence takes at most m+n steps and O(min(m,n)) output characters. A value-only version can keep two rows, or one row plus the old diagonal, but then this direct traceback is unavailable. Reconstructing in small memory is an additional algorithm, not a free consequence of compressing values.</Prose>
    <H3>Change the objective, keep the prefix idea</H3>
    <Prose><strong>Edit distance</strong> asks for the fewest insertions, deletions and replacements that transform one sequence into another, with each operation costing one here. Let E(i,j) be the minimum cost to transform first[:i] into second[:j]. The empty-prefix bases are E(0,j)=j insertions and E(i,0)=i deletions.</Prose>
    <LessonTable caption="Every edit predecessor has an operation meaning" headers={['Candidate', 'What it means']} rows={[
      ['E(i−1,j)+1', 'Delete the final character of the first prefix'],
      ['E(i,j−1)+1', 'Insert the required final character of the second prefix'],
      ['E(i−1,j−1) + mismatch', 'Keep an equal pair at cost 0, otherwise replace at cost 1'],
    ]} />
    <Prose>Take the minimum of these legal final operations. Each reduces i or j, so the prefix order is acyclic. CAT→CUT costs one replacement, even though a delete-only/insert-only transformation would cost two. Changing the allowed operations or their weights changes the objective and sometimes the state.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.edit}><Prose>The two-row implementation reads the previous row for deletion/diagonal and the current row for insertion. It returns a distance only. It costs O((m+1)(n+1)) operations and O(n+1) entries, including empty-prefix initialization; for positive lengths the familiar time bound is O(mn). Swapping inputs can minimize row width for this symmetric unit-cost distance.</Prose></RunnableExample>
    <Prose>These alignments explain a useful connection: with only insertions and deletions, preserving a common subsequence of length L requires m−L deletions and n−L insertions, totaling m+n−2L. Maximizing L minimizes that cost. This can model comparing token streams or simple text revisions, but production diff tools may optimize readability, use different algorithms or align lines rather than characters. Likewise, biological alignment requires a stated symbol alphabet and scoring/gap model; this tiny character example is not a validated biological scoring system.</Prose>
    <Checkpoint prompt="For AB and BA, why is one a valid LCS length? If the task changes to a longest common contiguous substring, what local information must the table remember?">
      <Prose>A or B is common, but AB cannot appear in BA without reversing order. For substrings, define a length ending exactly at both current positions. Equal characters extend the diagonal; a mismatch resets that ending-length to zero. The answer is the maximum over all cells, not necessarily the bottom-right cell. State meaning determines both recurrence and final extraction.</Prose>
    </Checkpoint>

    <H2>5. Spend a capacity budget</H2>
    <Prose>You can run selected offline experiments within an integer resource budget. Item 0 costs 2 units and provides value 3; item 1 costs 3 units and provides value 4. With capacity 6, taking both costs 5 and earns 7. Unused capacity is allowed. Each input occurrence can be selected at most once: this is the <strong>0/1 knapsack</strong> contract.</Prose>
    <Prose>Let <Code>K(i,c)</Code> be the largest value using only the first i items with total weight at most c. The item prefix prevents reuse; capacity records the remaining constraint. No items gives value zero at every nonnegative capacity because the empty selection is allowed. For item i−1 with weight w and value v, skip it using K(i−1,c), or, if w≤c, take it using v+K(i−1,c−w). Both branches read the <em>previous item prefix</em>.</Prose>
    <Prose>The same partition proves the recurrence: a legal subset either contains this occurrence or does not. Removing it leaves a legal subset of earlier items within the smaller capacity. Taking an optimal earlier subset gives the best value in that category. Induction over i establishes correctness; capacities are integer indices, and every table row is finite.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.knapsack}><Prose>Each item is a (weight,value) pair. Weights must be positive integers; values are additive numeric scores, with integer examples here. The reconstruction compares a row with the previous row: if the value changed, this implementation took the item; otherwise it skips on ties. Repeated equal items remain distinct occurrences. A negative-value item may be omitted because selecting nothing is legal.</Prose></RunnableExample>
    <Prose>The final call repairs Greedy's whole-item counterexample: weights [10,20,30], values [60,100,120], capacity 50. A density-first whole-item selection takes weights 10 and 20 for value 160; DP takes 20 and 30 for value 220. Allowing fractional items instead yields 240 by taking all of the first two and two-thirds of the last. That is a different feasible set, so neither its larger score nor its greedy proof establishes a whole-item solution.</Prose>
    <H3>Compress storage without erasing time</H3>
    <Prose>The full table takes O((n+1)(C+1)) initialization and updates for n items and capacity C, usually written O(nC) for positive n and C. A value-only calculation needs just the previous row. We can reuse one array if every take candidate still reads the old row. For positive weight w, visit capacities from large to small: when writing c, the smaller source c−w has not yet been updated for this item.</Prose>
    <CapacityGenerationLab />
    <Prose>With a single item (2,3) and capacity 4, descending updates give value 3. In ascending order, capacity 2 becomes 3 first; capacity 4 then reads that new 3 and adds the same item again, yielding 6. Ascending order is wrong for 0/1 knapsack and correct for the corresponding <strong>unbounded</strong> version, where copies of each item may be used repeatedly.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.compression}><Prose>For the unbounded recurrence, taking the item reads the current logical row at c−w: after one copy, more copies of the same kind remain allowed. Since w&gt;0, this source is smaller and already solved during ascending iteration. Direction is a consequence of dependency semantics, not a rule to memorize separately from the problem.</Prose></RunnableExample>
    <Prose>Compressed storage is O(C+1) value entries. The lab additionally stores witnesses and row-generation labels to expose source ownership; those copies are diagnostic overhead. A single mutable parent array can also be overwritten in ways that corrupt reconstruction. Keep the full item/capacity parent structure, preserve immutable decisions, or use another proven reconstruction algorithm before claiming the same memory bound for a returned plan.</Prose>
    <H3>At most is different from exactly</H3>
    <Prose>If the task asks to fill <em>exactly</em> capacity c, initializing every K(0,c) to zero invents feasible positive weights. Only K(0,0)=0 is possible with no items; other capacities need an impossible sentinel. For maximization, negative infinity can represent impossibility when arithmetic is handled consistently. For Boolean reachability, only reachable[0] starts True.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.subsetSum}><Prose>Values are nonnegative integers; the example permits a zero-valued occurrence because it does not change Boolean reachability. Descending sums ensure each positive occurrence is used once. [3,5] cannot form 6, but adding another distinct occurrence of 3 makes it possible. A set of distinct values would lose that distinction.</Prose></RunnableExample>
    <Prose>O(nC) can be excellent for a moderate capacity, but C is a numeric magnitude. Writing a capacity of one billion takes about 30 binary digits; allocating one billion cells does not take 30 steps. A bound polynomial in n and C can be <strong>pseudo-polynomial</strong> rather than polynomial in the encoded input length. Similarly, exponentially many subset states remain exponential even when memoized. State the input parameters before calling an algorithm efficient.</Prose>
    <Checkpoint prompt="Only one item of weight 3 and value 5 exists. What are the answers at capacity 6 for at-most 0/1, at-most unbounded and exactly-filled 0/1 versions?">
      <Prose>At-most 0/1 gives 5, at-most unbounded gives 10, and exactly-filled 0/1 is impossible. All three can use similarly shaped arrays, but their bases and source-row contracts differ. Explain those differences before touching loop bounds.</Prose>
    </Checkpoint>

    <H2>6. Count the right objects</H2>
    <Prose>Coins provide a compact way to see three different dynamic programs. Denominations are positive integers and each kind is reusable. For an exact amount t, ask whether it is possible, how few coins it needs, or how many representations it has. Before counting, decide whether order matters.</Prose>
    <CoinOrderFigure />
    <Prose>For the fewest coins, choose the final coin d. A valid prefix must total t−d; its optimal count plus one is a candidate. Minimize across d≤t whose remainder is reachable. The base is minimum[0]=0; positive unreachable totals remain impossible. Positive denominations strictly decrease the amount in the recursive view, so the dependency graph is acyclic.</Prose>
    <Prose>For <strong>ordered sequences</strong>, sum ordered[t−d] across possible final denominations. Every nonempty sequence has exactly one last denomination, so these categories are disjoint. The empty sequence contributes ordered[0]=1. With [1,3] and amount 4, 1→3 and 3→1 are distinct sequences.</Prose>
    <Prose>For <strong>unordered combinations</strong>, avoid counting those two orders separately. Let H(i,t) count combinations using only the first i denomination kinds. A combination either uses no copy of the new kind, H(i−1,t), or uses at least one; removing one copy leaves H(i,t−d). The current row in the second term permits reuse. Process denominations outside, amounts upward inside. This generates each multiset once.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.coins}><Prose>At amount 4 with [1,3], the tuple (2,3,2) means minimum two coins, three sequences and two combinations. At unreachable amount 3 with only denomination 2, the minimum is None while both counts are zero. At amount zero, the minimum is zero and each counting contract has one empty object. Duplicate denominations are deduplicated because the input describes kinds, not individually labeled coins.</Prose></RunnableExample>
    <Prose>For positive k kinds and target T, the loops use O(kT) arithmetic operations plus denomination preparation, and O(T) entries. Including initialization and empty cases gives O((k+1)(T+1)) work and O(T+1) entries, plus preparation. Counts can grow beyond fixed-width integer limits; Python stores exact integers but additions and storage then cost more bits. Reducing counts modulo M answers a requested modular count, not the exact count or a general reachability question: a positive count can be zero modulo M.</Prose>
    <Prose>Minimum coins also shows the boundary between greedy and DP. For [1,3,4], amount 6, taking the largest coin first uses 4+1+1, but 3+3 uses fewer. DP retains the relevant alternatives rather than assuming a greedy-choice proof. With a denomination system for which a greedy rule is proven correct, a simpler algorithm may be preferable.</Prose>

    <H2>7. A subset can be part of the state</H2>
    <Prose>So far, a prefix length has described which items are available. What if order is itself a decision? Suppose a route starts at A, must visit four labeled vertices exactly once and may finish anywhere. Arriving at C after visiting A,B,C leaves different possible moves from arriving at C after visiting only A,C. A state needs the visited subset and the endpoint.</Prose>
    <H3>Encode a set only after you can name its members</H3>
    <Prose>For a finite universe with indices 0 through n−1, use bit i to indicate whether member i is present. Bit i has numeric weight 2ⁱ. With A=0, B=1, C=2, D=3, the set {'{'}A,C{'}'} is 0101 in binary, or 1+4=5. Conventional binary notation puts bit 0 on the right. The empty mask is 0 and the full mask is (1&lt;&lt;n)−1.</Prose>
    <LessonTable caption="Membership operations on a nonnegative finite-set mask" headers={['Operation', 'Python expression', 'Meaning']} rows={[
      ['One member bit', '1 << i', 'Shift the single 1 left i positions, giving 2**i'],
      ['Test membership', 'bool(mask & (1 << i))', 'AND keeps a 1 only where both operands have 1'],
      ['Add a member', 'mask | (1 << i)', 'OR sets that bit; adding an existing member is harmless'],
      ['Remove a member', 'mask & ~(1 << i)', 'Clear that bit; unlike XOR, this also works when absent'],
      ['Complement within this universe', 'full & ~mask', 'Invert membership and discard bits outside the n-member universe'],
      ['Toggle membership', 'mask ^ (1 << i)', 'XOR flips the bit; it is not unconditional removal'],
    ]} />
    <Prose><Code>&amp;</Code>, <Code>|</Code> and <Code>^</Code> act on integer bits. Python's <Code>and</Code> and <Code>or</Code> perform truth testing and return an operand; they are not set-bit operations. For example, 5&amp;2 is 0, but 5 and 2 is 2. Keep parentheses around shifts and membership expressions so the intended operation is obvious.</Prose>
    <SubsetEndpointLab />
    <RunnableExample example={dynamicProgrammingExamples.masks}><Prose>Python integers do not overflow at a fixed 32- or 64-bit width. Bitwise operations behave as if there were infinitely many sign bits, so ~5 is −6, not the four-bit complement 1010. Masking with full restricts a complement to the chosen finite universe. A negative shift count is an error; for nonnegative i, left shift multiplies by 2ⁱ and right shift uses floor division by 2ⁱ. The browser model uses only tiny masks that fit JavaScript's 32-bit bitwise range.</Prose></RunnableExample>
    <Prose>The example also enumerates every submask of 0101: 0101,0100,0001,0000. Subtracting one clears the lowest set bit and sets lower bits; AND with the original mask removes any positions outside the allowed set. Repeating enumerates the allowed bit patterns in descending order. Stop at zero: subtracting again would restart at the original mask after the AND. With k selected bits there are 2ᵏ submasks; compact encoding does not shrink that count.</Prose>
    <H3>The endpoint is a dimension, not a label</H3>
    <Prose>Let <Code>D(mask,v)</Code> be the cheapest path that starts at A, visits exactly the vertices in mask and ends at v. A path ending at B after A→C→B and one ending at C after A→B→C both have visited {'{'}A,B,C{'}'} and cost 2 in the lab. Yet continuing to D costs 9 from B and 1 from C. Keeping only one number per mask erases a fact that changes the future.</Prose>
    <Prose>The base is D({'{'}A{'}'},A)=0 because no edge has been traveled. Other states start unreachable. From any reachable (mask,v), choose an unused vertex u connected by an edge. Form next_mask by adding u, and offer D(mask,v)+cost(v,u) to D(next_mask,u). Keep the cheapest offered value and its predecessor. This is often called relaxing a transition: improve an answer if a cheaper candidate arrives.</Prose>
    <Prose>Why retain just the cheapest prefix for a <em>complete</em> (mask,v) state? All such prefixes leave the same unused vertices and the same endpoint. Appending any permitted future has the same added costs. A more expensive prefix can never become preferable for this additive objective. If a later constraint depends on arrival time, battery charge or another resource not determined by mask and endpoint, the state needs reconsideration.</Prose>
    <RunnableExample example={dynamicProgrammingExamples.route}><Prose>The matrix gives costs from row vertex to column vertex; None means no edge. Starting vertex 0 is fixed. Each transition adds one unused member, so subset size increases and cycles in the original graph do not make the state graph cyclic. The code's increasing numeric-mask order is valid because adding a previously unset nonnegative bit strictly increases the mask. A by-subset-size order would also work.</Prose></RunnableExample>
    <Prose>Induct on the number of visited vertices. The singleton start is correct. Every longer valid path has a penultimate vertex; removing the last vertex yields one of the considered smaller states. Every transition appends an unused neighbor, preserving a valid visit-once path. Minimizing over all such predecessors therefore produces the best value. Parent reconstruction removes the endpoint's bit each time and returns to A.</Prose>
    <Prose>There are at most n2ⁿ state entries and at most n outgoing candidates per entry, giving O(n²2ⁿ) arithmetic/state operations and O(n2ⁿ) table entries under a bounded-word mask/cost model. This improves on enumerating all visit orders for many sizes but remains exponential. Python arbitrary-precision masks, large costs and full table allocation add real costs; the code is for small n, not an industrial routing solver.</Prose>
    <Prose>Our answer is the minimum reachable D(full,v), a path that may finish anywhere. The traveling-salesperson <em>cycle</em> variant must also pay the edge back to the start and require that edge to exist; simply returning the path score would solve a different task. Time windows, repeated visits and multiple vehicles are additional models. State sufficiency must be proved again as constraints change.</Prose>

    <H2>8. Optimize only after the contract is clear</H2>
    <Prose>A useful cost model is the sum, over evaluated states, of the work needed to generate and combine their transitions. “States × work per state” is a convenient upper bound when that work has a common bound. Charge initialization, key construction/hashing, copied sequences, arithmetic size and output separately when they are material. A cache hit can avoid expansion while still performing lookup/key work.</Prose>
    <H3>Choose a schedule and memory policy</H3>
    <LessonTable caption="Optimization choices preserve different information" headers={['Choice', 'Benefit', 'Condition or cost to retain']} rows={[
      ['Memoization', 'Visits states demanded by the requested answer', 'Complete immutable key/input; cache plus recursion depth; bounded caches may recompute'],
      ['Tabulation', 'Explicit order and predictable storage; avoids recursion', 'May fill unreachable/unused states; prove every read is ready'],
      ['Rolling rows / variables', 'Discards values no future transition needs', 'Name the logical version of every read; preserve diagonal/source before overwrite'],
      ['Dominance summary', 'Retains only candidates that can matter to future choices', 'Prove discarded candidates cannot win; often changes reconstruction needs'],
      ['Precomputed aggregates / range queries', 'Accelerates a large set of transition candidates', 'The recurrence must match the aggregate and update/query order'],
    ]} />
    <Prose>For nonadjacent rewards, a value-only backward loop needs only the next two suffix answers. Compute current = max(next_one, reward + next_two), then shift the two old values together. This uses a constant number of value variables, but does not retain the full witness table and is not constant bit storage for unbounded reward magnitudes. For edit distance, a current cell additionally needs an old diagonal; overwriting it before saving it is a classic compression bug.</Prose>
    <H3>A time optimization needs its own proof</H3>
    <Prose>For a <strong>longest strictly increasing subsequence</strong> (LIS), define ending[i] as the best length ending exactly at input position i. It is 1 plus the maximum ending[j] over earlier j with value[j]&lt;value[i], or 1 when none exists. The answer is max over endpoints, with zero for an empty input. This O(n²) method follows the state definition directly.</Prose>
    <Prose>For length alone, a smaller last value is at least as useful as a larger last value at the <em>same subsequence length</em>: anything that can extend the larger tail can extend the smaller one. Maintain tails[k−1], the smallest achievable tail of a length-k increasing subsequence in the processed prefix. The tails are strictly increasing. For new value x, find the first tail ≥x with lower-bound binary search; replace it with x, or append if no such tail exists.</Prose>
    <Prose>If the first tail ≥x is at position p&gt;0, a subsequence of length p ending at the smaller tails[p−1] can extend to x. For p=0, x starts a length-one sequence. Earlier lengths already have smaller tails and need no update; later lengths cannot gain a valid extension ending at x, because doing so would require an earlier length-(p+1) tail smaller than x, contradicting the first-boundary choice. This preserves the minimum-tail invariant.</Prose>

Equal values replace rather than extend; an upper bound would instead fit a nondecreasing variant. The final tails array is not necessarily an actual subsequence: [3,5,6,2] leaves tails [2,5,6], but 2 occurs after 5 and 6.     <H3>Recognize deeper families without inventing a universal trick</H3>
    <Prose>Other problems need other state shapes. An interval state (left,right) can describe a contiguous region; trying its last split gives transitions to smaller intervals, often evaluated by increasing length. A tree state can summarize each subtree plus a boundary condition such as whether its parent was selected. A digit state can record a position, whether a numeric bound is still tight, and a property of the digits already placed. These are modeling patterns, not formulas that can be pasted without defining the state.</Prose>
    <Prose>Likewise, divide-and-conquer optimization, convex-hull methods or special interval optimizations need additional monotonicity/algebraic inequalities. A correct general recurrence does not imply those conditions. For a transition asking for the largest earlier DP value in a value range, a range-maximum structure can be useful; <a href="/learn/topic/segment-trees-fenwick-trees-range-queries">the next topic</a> develops the data-structure operations. Do not substitute minimum tails when the requested result is a weighted optimum or a count without a new dominance proof.</Prose>
    <Prose>Sometimes DP is the wrong tool: a greedy rule with a valid proof can be simpler, a graph traversal can exploit reachability directly, or most complete states may never repeat. When the state space is too large, changing the formulation, using approximation under a stated guarantee, or accepting a bounded exact search may be necessary. This lesson establishes a design method and representative families, not every specialized recurrence optimization or a guarantee against every future interview problem.</Prose>

    <H2>Interval states: split the last operation</H2>
    <Prose>A useful state does more than name an area of a table: it promises that everything outside that area interacts with it in a known way. We will develop three deeper families using that idea. Pause between these branches if needed; each has a different boundary to identify, and the final independent task still follows them.</Prose>
    <H3>The same transformations can cost different amounts of work</H3>
    <Prose>Suppose a calculation applies a fixed chain of matrix transformations. A matrix is a rectangular array. For the ordinary multiplication of an r×s matrix by an s×t matrix, each of the r·t output entries combines s products, so the algorithm performs r·s·t scalar multiplications. The result has shape r×t. The shared inner dimension s must agree. We need only these shape and cost rules here; matrix entries and advanced linear algebra are not prerequisites for this planning problem.</Prose>
    <Prose>Grouping can change work dramatically. Let A0 have shape 8×2, A1 shape 2×12 and A2 shape 12×3. Computing (A0 A1) A2 costs 8·2·12 + 8·12·3 = 480 multiplications. Computing A0 (A1 A2) costs 2·12·3 + 8·2·3 = 120. Both preserve factor order and produce shape 8×3.</Prose>
    <MatrixShapeFigure />
    <Prose>Exact mathematical matrix multiplication is associative: regrouping gives the same product. It is generally not commutative: rearranging A0,A1,A2 is a different operation. This is a small example of planning a computation before executing it. We optimize the stated multiplication count, not measured runtime, peak memory, additions or numerical error. Real libraries and hardware add other costs; floating-point rounding can also differ between groupings.</Prose>
    <H3>Why the two interval endpoints are enough</H3>
    <Prose>Store dimensions d=[8,2,12,3], so matrix Ai has shape d[i]×d[i+1]. Define <Code>C(i,j)</Code> as the minimum multiplication cost for matrices Ai through A(j−1), in their original order. Here [i,j) is a half-open interval of <em>matrix positions</em>, not a time window. No matter how its interior is grouped, its result always has shape d[i]×d[j]. That fixed shape is the information its future parent calculation needs.</Prose>
    <Prose>One matrix already exists, so C(i,i+1)=0. For more than one, ask which split k is used by the <strong>last multiplication</strong>. Its left product is [i,k), its right product is [k,j), and joining their shapes costs d[i]·d[k]·d[j]. Try each i&lt;k&lt;j:</Prose>
    <Prose><Code>C(i,j) = min_k (C(i,k) + C(k,j) + d[i]·d[k]·d[j])</Code>.</Prose>
    <Prose>There are two parts to the proof. Every legal binary grouping has a last multiplication and therefore one of these splits. Its two child costs cannot be smaller than the optimum of their intervals. In the other direction, joining two optimal child plans at any legal split creates a valid plan for the parent with exactly the candidate cost. Replacing a child by a cheaper grouping leaves its boundary shape unchanged, so it cannot break the parent. Taking the minimum therefore gives exactly the optimum.</Prose>
    <Prose>Both child intervals are shorter than the parent. Initialize one-matrix intervals, then evaluate increasing interval length. A row-by-row loop chosen only because the data is a table may read an unfinished dependency. For every improved minimum, save k as well as the value. On ties, our implementation retains the first split; that is a deterministic policy, not a uniqueness claim.</Prose>

Values are nonnegative integers. Original positions identify objects, even when their values agree. The largest immediate reward is only a candidate decision; the changing neighbors make its future consequences matter.</Prose>
    <Prose>Pad the row with permanent value-1 sentinels. Define <Code>B(l,r)</Code> as the best reward for removing everything strictly between surviving boundaries l and r. An empty interior has value 0. Guess the <strong>last interior balloon k</strong>, not the first. Until k is removed it separates the left and right interiors, and its final neighbors are exactly l and r:</Prose>
    <Prose><Code>B(l,r) = max_k (B(l,k) + B(k,r) + a[l]·a[k]·a[r])</Code>, for l&lt;k&lt;r.</Prose>
    <Prose>Every complete removal order has a last interior object, so the cases are exhaustive. Holding that object alive shields the two child interiors from one another: changing a child's internal removal order cannot alter the boundary values seen by its sibling. Solve both child interiors, then remove k; this realizes each candidate. Increasing the gap r−l is again a valid evaluation order. Reconstruction lists left removals, right removals, then k. The chosen split-tree root must be removed <em>last</em>.</Prose>

    <H2>Tree states: remember the parent boundary</H2>
    <Prose>For this branch, review parent, child, subtree and postorder in <a href="/learn/topic/trees-binary-search-trees">Trees &amp; Binary Search Trees</a>. A tree is a connected undirected graph with no cycle. Choose a root; every other node has exactly one parent on its path to that root. A subtree contains a node and all its descendants. Postorder visits children before their parent. Those structural facts—not a binary-search ordering rule—make the next recurrence possible.</Prose>
    <Prose>Suppose each vertex has a reward and an edge means “these two cannot both be selected.” Choose a legal set with maximum total reward. This is a <strong>weighted independent set</strong>: “independent” here means no selected edge endpoints, not statistical independence. The empty set is allowed, including when all rewards are negative. This models a hierarchical conflict structure; arbitrary conflicts need not form a tree.</Prose>
    <H3>The unconstrained subtree optimum is not enough</H3>
    <Prose>If a subtree root has weight 9 and its two leaf children have weights 4 and 1, its unconstrained optimum is 9. But when its external parent is selected, taking that root is illegal; the subtree can return only 4+1=5. Keeping one number for both questions merges two different legal futures, just like the blocked-session example earlier.</Prose>
    <Prose>Define <Code>F(v,p)</Code> as the best total inside the subtree rooted at v when the external parent is selected (p=1) or not selected (p=0). The parent's weight is outside this answer. For the whole tree, ask F(root,0), because no parent forbids its root. There are two local alternatives:</Prose>
    <LessonTable caption="What each choice asks of the children" headers={['Choice at v', 'Child boundary', 'Value']} rows={[
      ['Skip v', 'Every child has an unselected parent', 'skip(v) = sum F(child,0)'],
      ['Take v', 'Every child has a selected parent', 'take(v) = weight[v] + sum F(child,1)'],
      ['External parent selected', 'v must be skipped', 'F(v,1) = skip(v)'],
      ['External parent not selected', 'Both choices are legal', 'F(v,0) = max(skip(v),take(v))'],
    ]} />
    <Prose>A leaf has no child contributions: skip=0, take=its weight, and its free answer is max(0,weight). Do not return a negative leaf weight automatically when empty selection is legal. The commonly used “include-root/exclude-root” pair describes the same choices; our second table is <em>parent-selected</em>, so it equals the exclude-root answer. Name the convention before translating formulas.</Prose>
    <Prose>Why does this work? Once v's choice is fixed, it gives the only outside constraint each child subtree needs. No edge joins different child subtrees in a tree. Their legal selections can therefore be combined, and their weights added. Every legal set either takes v or skips it; both cases are represented. Starting from the leaf bases, induction on subtree size proves each conditional optimum. If an extra cross-child edge is present, the independence of those subproblems is lost. Traversing a general graph as if it were a tree does not repair that missing state.</Prose>

    <H2>Digit states: count constrained continuations</H2>
    <Prose>Finally, suppose an identifier rule asks for positive integers from 1 through N with no repeated decimal digit. How many are there? Testing all N values works for a small oracle, but a large bound calls for counting groups of valid completions. This rule is a precise combinatorial example, not a recommendation for password security.</Prose>
    <Prose>Align a candidate with the bound's L decimal positions. A shorter number gets zeros on the left for comparison: under a three-digit bound, 7 is written 007. These are padding, not extra digits in the number's ordinary spelling. Every number has exactly one such fixed-width spelling.</Prose>
    <DigitPaddingFigure />
    <H3>Separate equality to the bound from legality</H3>
    <Prose>Read digits from left to right. If the prefix still equals the bound prefix, the next digit may not exceed the bound's next digit. Call this <strong>tight</strong>. Once a smaller digit has been chosen, the prefix is safely below the bound; later digits may range through 0–9. That prefix is loose. A loose prefix can never become tight again just because a later digit happens to match.</Prose>
    <Prose>For N=213, prefix 21 is tight and its final digit is at most 3. Prefix 12 is loose and its final digit can be as large as 9. Both have used the same set {'{'}1,2{'}'}, but 21 has only the two valid completions 210 and 213, whereas 12 has eight: 120,123,124,125,126,127,128,129. Omitting tightness merges counts 2 and 8.</Prose>
    <Prose>Define state <Code>(position,tight,started,used)</Code>. Position names the next slot; tight records prefix equality; started says whether a non-padding digit has occurred; used is the set of actual digits already seen. The earlier mask primer gives a compact representation: bit d represents decimal digit d. Prefix order need not otherwise be remembered for the all-distinct property.</Prose>
    <LessonTable caption="Advance one decimal position" headers={['Situation', 'Action and next state']} rows={[
