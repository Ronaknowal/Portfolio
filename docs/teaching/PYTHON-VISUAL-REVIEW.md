## Visual contracts

- **Reference setup:** question—does assignment copy a list? Initial examples `readings=[18,21]`, with either assignment or shallow copy. Arrows encode reference identity, labelled A/B boxes encode distinct outer lists, slots encode actual values; size does not encode memory. The caption connects to the mutation/rebinding prediction in the following lab. Static figure, so no artificial controls. Columns stack at narrow widths; each SVG has a complete verbal equivalent. The already-retained nested-copy branch explains the outer-copy limit.
- **Saved bound method:** question—does the saved callable follow a reassigned name? State is exactly after `add_to_morning=morning.add; morning=evening` in `bound_method.py`, before the saved call. The method's `__func__` and `__self__` are distinct fields; A/B are identities. Caption predicts `add_to_morning(18)` changing only A. Responsive HTML preserves grouping and reading order. No copying or descriptor-generalization claim.
- **Cursor ownership:** question—does b own an independent next position? Fixed list `[18,21,24]` or `[]`; controls alter whether `iter` is called twice or `b=a`. Each step is the existing alternating `next` request. One source remains visible; arrows track next indices; END is explicitly a non-element signal. Output, feedback and arrows derive from one trace state. No elapsed-time or interpreter-memory claims. All setup/empty combinations and full existing traces checked; controls remain keyboard usable.
- **Decoration:** question—how can a renamed public function still call its original body? Before/after reference maps use the logger's actual mean calculation and concrete `[18,24] → 21.0` result. Nesting represents a retained reference, not copied code or memory layout. Call order is shown separately from definition-time rebinding. Full callable/exception behavior remains in the native example and wrapper-order investigation. HTML recomposes vertically on mobile.
- **Resource route:** question—which path reaches cleanup, and where does execution continue? Presets choose successful body, body failure or failure before acquisition, and false/truthy exit result. Arrows show the chosen possible route; an outlined node plus the explicit current-step text identify the current phase. Skipped nodes are dashed and labelled; resource/exception status reflects the current trace state. Back/reset preserve existing semantics. Layout is not elapsed time; cleanup is assumed successful; abrupt termination and partial acquisition limits remain next to the lab. Short labels and larger SVG type preserve narrow-screen readability; the SVG's accessible description states the complete route and current state.
- **Testing boundary:** question—what did a passing test actually exercise? Exact existing fixtures are mock text `"18\n24\n"` and a real temporary UTF-8 file containing `18\n\n24\n`. Dashed source means substitute; green-tinted stage and explicit label identify the additional real file boundary. Numeric output agrees, boundaries differ. Static paths stack vertically on narrow screens and arrows follow that direction. This does not establish every Unicode/encoding/network/platform behavior; the limit is adjacent.
