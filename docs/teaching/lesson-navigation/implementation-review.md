# Shared opening: independent source review

Reviewed 28 September 2026 against the current shared implementation. Scope: `LessonOpening.jsx`, `LessonGuide.jsx`, `lesson-guide.css`, `lesson-navigation.js`, `TopicContent.jsx`, `content/Headings.jsx`, `content/Prose.jsx`, and `lesson-labs/LessonElements.jsx`, plus their reader/loading/error-boundary consumers. This review made no runtime, topic, manuscript or ledger edits. Browser acceptance belongs to the integration owner's rendered verification.

No blocking runtime defect was found in the inspected code. The reader owns one opening below the title/meta and mounts topic-owned notes there through explicit React portals. The reader remains keyed by stable topic ID; existing asynchronous resource handling discards stale loads. Stable callback refs avoid repeatedly replacing the portal slots. Portalled guidance remains logically inside the lesson error boundary, and the compass is removed after a lesson render failure.

Section links remain native anchors with modifier-click behavior intact. A normal click additionally focuses the linked heading without a second scroll. Collected headings receive `tabIndex=-1`; visible focus and the header scroll offset are supplied by shared CSS. The index separates the authored number from its label, with a single accessible spoken number, and uses no native list markers. Unnumbered sections do not renumber later authored sections. `H2` computes its existing fragment before display punctuation normalization. Existing explicit wrapper anchors remain available even when the collector must disambiguate a heading ID.

The collector runs once for each mounted content function rather than observing every lab mutation. It examines only the active article and does not add eager lesson imports. Its filter excludes all headings inside `details`, including already-open details, as well as lab, aside, navigation and error content. The authoring contract now makes these local disclosure headings explicit; main lesson sections requiring TOC entries should be outside those containers. Future asynchronously inserted main sections would need an explicit refresh contract; none was established by this source review.

The shared CSS provides a two-column section index with a single-column layout below 700px, wrapping labels, 44px link targets and focus outlines. These are source-level observations, not claims that browser geometry or all assistive-technology behavior has been verified. Topic-specific body styles and scientific encodings remain independent of the common navigation styling.

## Authoring preservation implemented

- Updated `LESSON-TEACHING-STANDARD.md` and `docs/engineering/LEARNING-CODE-STANDARD.md` to require the shared opening, explicit guidance registration, a complete index of actual main H2s, stable anchors/authored numbers and topic-specific body representations. `hasIntegratedGuide` is documented as legacy metadata rather than a layout switch.
- Added explicit `opening: [[markdownPrefix, kind]]` options to `scripts/lib/prepared-lesson-renderer.mjs`. Prefixes must select one paragraph and use a supported opening kind. No keyword inference runs in the reader or renderer.
- Added `scripts/lib/lesson-opening-annotations.mjs` and the `preserveOpeningFrom` renderer option. Existing explicit `<Prose opening="…">` annotations are restored using exact static paragraph-text equality after formatting whitespace normalization. The generated inner JSX remains intact. Missing, ambiguous, dynamic or conflicting matches fail visibly.
- Added the source-preservation option to all 38 topic scripts that call the shared prepared renderer. No topic generator was executed. Bespoke generators outside that helper still own preservation of their explicit attributes; the contract now states this requirement.

`node scripts/check-lesson-opening-authoring.mjs` passed 12 focused fixture cases and preserved all 110 current annotations across 73 published topics after the Active Learning follow-up. The cases cover rich inline markup/links, authored section numbers, unannotated prose, changed and duplicate paragraphs, conflicting/overlapping/missing mappings, unsupported kinds, replacements, a new destination and dynamic source guidance. The corpus check removes/restores annotations in memory and does not regenerate the full lessons. Full generation from historical manuscripts was deliberately not claimed or run; a divergent source/manuscript will now fail instead of silently losing guidance. Existing scientific and delivery checks were not reopened.

The follow-up source review confirmed the integration owner's explicit `opening="route"` annotation on Active Learning's existing core-route paragraph and its matching exact-text entry in `scripts/build-active-learning-lesson.py`. It also confirmed that the common 90px scroll margin now applies to article `[id]` targets, so preserved wrapper aliases receive the same fixed-header clearance as collected H2s. No additional source-level concern was found in those two changes; their rendered behavior remains part of integration verification.

[Authoring before/after identities](authoring-source-changes.json) reconstruct the 38 caller edits and shared-renderer edit in memory without overwriting any source. All 37 ledger-bound files (36 callers and the renderer) match every recorded baseline SHA-256 exactly. The remaining two callers have no current ledger binding. The renderer's original mixed line endings were recovered only for this byte comparison; its current file remains unchanged.
