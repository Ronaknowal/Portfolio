## Concrete findings

1. **CV21-1 — a tied minimum was graded as worse (P2).** At I4, use A losses `[.40,.20,.10]`, B `[.30,.20,.10]`, C `[.50,.30,.20]`, factor 3, first comparison 10. B is selected and achieves the minimum final loss .10, but `matchesSurvivor` compared its identity with first-listed argmin A and returned false. Thus “yes” to having the lowest budget-90 loss was rejected, while hindsight regret was zero. Independently reproduced directly from the model.
2. **CV21-2 — the single-winner wording misrepresented multiple finalists (P2).** Nine-candidate preset with factor 2 gives assessed counts 9/5/3; I, H and G all reach budget 90. The prediction asked which candidate reaches the largest budget, accepted only I, and the plot description called every other candidate eliminated. The model's chosen best finalist must be distinguished from all candidates that reached the final stage. Independently reproduced final indices and counts.
3. **CV21-3 — retained history inherited a different output's label (P2).** Apply I3 baseline predicting selected count 1, then change “What to predict” to the protected-row label for row 8. The old result is rendered through the new question/options as “Prediction for row 8: label 1,” though the saved result was a neighbour count, and the actual baseline label for row 8 is 0. Retained history needs its original question and answer labels, including the original inspected row.
4. **CV21-4 — decimal roundoff violated the declared distance tie rule (P2).** From I3 baseline set x(row 0)=.3, x(row 1)=.5, x(row 3)=.1 and y(row 3)=1. Outer fold 1 selects k=1 (inner means .625/.5). Raw subtraction sorts row 3's distance `.19999999999999998` ahead of row 1's `.2`, producing label 1. Both mathematical distances are .2, so the stated smaller-source-ID rule requires row 1 and label 0. All inputs satisfy the supported two-decimal contract. The I1 model already accounts for tie roundoff; I3 did not.
5. **CV21-5 — exact enumeration could not be reconstructed from its displayed summary (P2).** The prepared I2 specification requires all sixteen label patterns and each selected best score. The current table aggregates by number of ones and displays a set of possible best counts, losing their multiplicities for arbitrary candidate patterns. The average is calculated correctly but cannot generally be checked from that table. `enumeration.rows` already holds the required per-pattern labels, winner and correct count, so a closed details table can complete the contract without crowding the summary.

6. **CV21-6 — covariance-grid emphasis was overridden by CSS (P3, owner finding).** The diagonal/off-diagonal rectangles and V/C glyphs had distinct SVG fill attributes, but `.cv-box` and the general SVG text rule overrode them. Source inspection confirms the intended fills could not win the cascade. Semantic variance/covariance modifiers now give the rectangles and glyphs separate effective fills; browser regressions read computed styles for all 5 diagonal and 20 off-diagonal cells.

7. **CV21-7 — crowded trajectory identities and stale preset copy (P2, owner screenshot finding).** The first passing browser run's nine-candidate/factor-2 capture showed overlapping endpoint ID labels, the preset's stale “9, 3, 1” explanation despite actual counts 9/5/3, and long binary tails in some preset loss fields. The owner removed only the colliding candidate text from the SVG, retained individual curve titles, and added a readable nine-row endpoint table with exact last-observed budgets/losses. Factor/start edits now retire preset copy; integer-hundredth construction keeps preset values within their displayed two-decimal contract. Bounded regressions retain the axis labels and require nine named endpoints, exactly three at budget 90, no stale count explanation and no decimal tails.
