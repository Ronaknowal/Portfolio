## Bit manipulation has partial owners, not an absent foundation

The [UNASSIGNED note](topic-notes/UNASSIGNED.md) is still open. Its earlier suggestion that scoped lookup found no substantive bit teaching needs an updated disposition when an owner is assigned:

- [DP section 7](../../src/learn/data/topics/dynamic-programming-states-transitions-optimization.jsx) lines 148–174 already supplies a substantial finite-set mask primer: bit positions, membership/add/remove/toggle, bounded complement, Boolean versus bitwise operations, Python shift/sign semantics, submask enumeration, a linked set/bit-row investigation, a complete native example and subset-plus-endpoint recurrence. Its [destination note](topic-notes/dynamic-programming-states-transitions-optimization.md) correctly distinguishes that completed primer from broader bit-manipulation coverage.
- [Range Queries](../../src/learn/data/topics/segment-trees-fenwick-trees-range-queries.jsx) lines 70–77 derives `i & -i` from the lowest set bit and two's-complement behavior, then explains the actual block/query/update invariant. This is real teaching, not an unexplained bit trick.
- String Matching's exact base-4 DNA code is a scoped representation, not a general bitwise curriculum. Complexity explains encoded input length. Neither closes general integer-bit reasoning.

Still missing from a connected DSA treatment are a proved XOR cancellation/parity reduction and its input promises, clearing/counting set bits, explicit finite-word signed/unsigned interpretation and arithmetic-versus-logical shifting, and varied changed-contract bitwise practice. The current 152 placements do not include a direct general-bitwise problem. XOR examples in later mathematical information theory concern Boolean dependence, not an integer-bit algorithm curriculum.

**Proposed primary home: extend the existing Arrays, Strings & Hash Maps topic with a clearly signposted bitset/bitwise representation branch**, preserving its stable ID and position. A displayed title such as “Arrays, Strings, Bitsets & Hash Maps” would honestly describe the extra coverage; the rename is a proposal, not applied. This is a representation choice alongside sets, frequencies and keys: a finite bitset records membership, while XOR can preserve parity under a stronger multiplicity promise. It can begin with a small binary place-value refresh instead of assuming hardware knowledge. A new Python-basics chapter would overload the programming introduction; burying general XOR reduction inside a long DP recurrence chapter would give it a less natural purpose.

Preserve the DP subset/endpoint example and Fenwick proof as applications, with a local refresh and eventual link to the canonical foundation. Do not remove their useful explanations merely to consolidate terms. The proposed branch should distinguish arbitrary-precision Python integers from an explicitly bounded word and account for integer size; language-specific overflow rules must not be generalized between Python, JavaScript and C/C++. Further prefix-XOR queries belong with Range Queries once the basic algebra is taught; XOR tries can be an explicitly advanced Trie application if later useful. These are proposed dependent follow-ups, not a mandate to add every known trick.

[Official Python integer documentation](https://docs.python.org/3/library/stdtypes.html#bitwise-operations-on-integer-types) was inspected in this pass for infinite sign extension, illegal negative shifts, floor-division right shift and `bit_count`'s absolute-value convention. [LeetCode 136, Single Number](https://leetcode.com/problems/single-number/) was directly inspected: its pair-plus-one promise and linear-time/constant-extra-space requirement make it a useful future cancellation transfer. A future author must prove why its premise matters and supply independent changed-input exercises before linking a larger selection. No new problem is assigned here.
