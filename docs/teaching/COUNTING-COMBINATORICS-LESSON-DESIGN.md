## Scope, preservation and prerequisites

Retain the current title, stable identity and module order. The title accommodates counting mechanisms and their proofs, including carefully signposted deeper applications. Its only required topic prerequisite remains **Sets, Logic, Relations & Proof Techniques**. Refresh finite sets, functions, bijections, equivalence classes, implication and the base/arbitrary-step induction contract where used. Define factorial, summation, binomial coefficient and coefficient notation locally. Python is an optional way to check finite examples, not a prerequisite for reading the arguments. No probability, calculus, group theory, algorithms or generating-function background is silently assumed.

The exact topic inventory was read before design. The topic is planned: there is no existing lesson body, example module, lab or individual blueprint to archive or execute. [Original expanded plan](evidence/counting-original-plan.json) preserves its prior summary, outcomes, five-stage sequence, choice-tree idea, practice, sources and prerequisite. The source remains `src/learn/data/curriculum/cross-domain-expansion.js`; the root agent owns shared registration. Preserve the original intentions while expanding their teaching depth. A plan and a publication marker are not verification.

The learner's central question is **what makes two outcomes different?** Once that is fixed, choose a disjoint partition, a sequence of choices, a reversible encoding, an equal-size group of descriptions, or a recurrence. Formulas come from these constructions. The learner should finish able to build a counting argument, detect unequal multiplicity, explain why an induction reaches every claimed size, and test a new finite case without treating enumeration as the general proof.

## Learning flow and worked objects

The opening uses four named volunteers and two named roles. There are 12 legal assignments if a person cannot fill both roles, but only six two-person committees. Each committee has two role assignments. Changing the experiment to two draws from labels A/B, with repetitions allowed, yields AA, AB, BA, BB; ignoring draw order leaves groups of sizes 1, 2, 1. The difference explains why division by a factorial is a theorem with conditions rather than a rule triggered by the word “unordered.” These are invented, completely specified finite examples.

The resource-allocation thread uses identical test tokens distributed among named stations. Distinct volunteers and identical tokens are deliberately contrasted. A later cyclic test pattern has no distinguished starting phase; reflection still counts as different unless it is itself a rotation. Balanced parentheses provide a concrete syntax application already motivated in Backtracking. Lossless compression supplies a useful impossibility argument, with all encoded bits and decoder information accounted for.

| Reading stage | Mechanism and complete result | Learner's changed action |
| --- | --- | --- |
| 1. Define one outcome before counting | Write the objects, labels, legal choices and equality rule. Enumerate a small role assignment and a deliberately unequal-branch choice tree. Add disjoint cases; multiply successive choice counts only when the number of continuations at each stage is constant over the preceding legal prefixes. Allowed labels may depend on the prefix without invalidating the generalized product rule. | Explain which changed role restriction creates unequal branch sizes and count by summing them. |
| 2. Count descriptions, then group them | Derive factorial and falling factorial, including one empty arrangement. Show a many-to-one map and its fibers. Prove division by a fixed fiber size and inspect the A/B repeat counterexample. This also separates counting from the probability induced by a sampling procedure. | Identify whether every output has the same number of descriptions; supply an actual unequal pair if not. |
| 3. Choose objects and arrange repeats | Derive binomial counts by assigning roles then forgetting order; complement symmetry and Pascal's split. Derive multiset permutations by temporarily labeling equal symbols, and multinomial allocations of distinct items to named groups of prescribed sizes. Summarize order/repetition cases only after the derivations. | Count a changed constrained committee and explain why a superficially similar repeated-item problem uses another map. |
| 4. Allocate identical resources | Construct stars and bars as a bijection, including adjacent/end bars for empty bins. Shift lower bounds before counting; apply upper bounds through disjoint or inclusion–exclusion reasoning. Five tokens among three stations gives 21 unrestricted nonnegative allocations, six strictly positive allocations and 12 allocations if every station has capacity three. | Change a lower bound and a capacity; show the encoding and an infeasible case rather than applying an out-of-domain formula. |
| 5. Count the same object twice | A committee with a chair gives `k C(n,k) = n C(n−1,k−1)`. Derive Pascal and a finite binomial expansion by choosing a term from each factor. Prove a sum identity both by partitioning outcomes and by induction, showing what the induction hypothesis permits. | Produce two explanations for a changed identity and repair an illicit substitution in an induction step. |
| 6. Correct overlaps | Work from actual finite memberships to the two- and three-set formulas. Track one element included in several sets through each signed term. The general alternating sum gives net weight one to an element present in at least one set. Apply to forbidden assignments and a small derangement, defining the empty permutation consistently. | Correct a triple-overlap error and compare the formula with direct set union on changed data. |
| 7. Prove that something must happen | Generalized pigeonhole with a positive number of boxes, ceiling bound and a sharp construction. State the existence conclusion precisely. Prove that an injective code cannot make every length-n bit string shorter: there are `2^n` inputs but only `2^n−1` shorter binary strings, including the empty output. Side information must also be counted. | Change the box capacities and explain what is forced, what is not located, and why lossy decoding escapes the injectivity assumption. |
| 8. Build a recurrence from a reversible split | Tilings of length n by units and dominoes split by first tile; bases at n=0 and n=1 are actual objects. For set partitions, insert the last distinct item either into one of k existing blocks or into its own new block, deriving `S(n,k)=k S(n−1,k)+S(n−1,k−1)`. State all zero/empty cases and contrast unlabeled blocks with labeled boxes. | Construct the smaller object and reverse the split. Check a changed recurrence without guessing it from a short numerical sequence. |
| 9. Make induction reach every claimed case | Use the earlier proof contract on counting identities and recurrence implementations. Strong induction for sums of 4 and 7 covers every integer at least 18 using bases 18–21, then removes/adds 4. Explain why a proof using only base 18 does not cover the other residue classes, even though many omitted numbers are actually representable. | Use 3 and 5 with bases 8–10, construct witnesses and distinguish an unsupported proof path from a false theorem. |
| 10. Count balanced syntax | The unique first matching close splits a nonempty word as `(A)B`. Derive Catalan convolution with `C0=1`, then connect prefix height to a path. Reflect a bad path only up to its first height −1; its image ends at height +2, and the inverse reflects through the first +1. Count the excluded paths and derive `C(2n,n)−C(2n,n−1)=C(2n,n)/(n+1)` for n≥1, with n=0 handled directly. | Find the first violation, construct and undo the reflection, and verify n=4 has 14 balanced words. Explain why arbitrary reflection points do not establish the bijection. |
| 11. Encode choices as coefficients — optional | A station with capacity c contributes `1+x+…+x^c`; multiplying finite polynomials records possible total allocations. Derive convolution as a sum of products of smaller counts. For capacities 2,3,1, the coefficient of `x^3` is six. Define `[x^t]`; this is coefficient extraction, not substitution x=t. If a formal series is mentioned, define coefficientwise equality and do not infer analytic convergence. | Change capacities, compute one coefficient by hand and reconcile it with direct allocation enumeration. |
| 12. Count patterns when starting phase is irrelevant — optional | Four binary sites have 16 labeled patterns but six rotational orbits. Some patterns have fewer than four distinct rotations, so naive division fails. Count fixed patterns under each rotation: 16,2,4,2. Double-count pairs (pattern, fixing rotation); each orbit contributes four such pairs because orbit size times stabilizer size is four. Generalize to a finite cyclic rotation action, defining all terms locally. | Inspect a period-two pattern, change to five or six sites, and distinguish a marked start, rotations and reflections. |
| 13. Synthesize and continue | A constrained selection/allocation problem requires an explicit outcome contract, a derivation and a separately implemented check. Readiness means explaining choices and repairing wrong reasoning, not memorizing formulas. | Complete changed hand and code work, then continue to the route's actual next entry, Single-Variable Calculus: Limits, Derivatives & Integrals. The route controls navigation; no published-topic shortcut. |

## Representation and investigation contracts

The number of representations follows the hurdles above. Share small visual primitives where useful, but do not force every mechanism into a grid with text-only output. Each investigation begins with a visible meaningful state, a prediction prompt, an operation, an observable consequence and a short interpretation. The static reading view must already explain something before a learner touches a control. No numerical plot in this lesson represents measurements or a benchmark; all counts and geometry are exact finite constructions unless explicitly labeled schematic.

### Choice identity and fibers

Draw a branching choice diagram whose leaves are actual ordered descriptions. A linked grouping view shows which leaves become one outcome after order is forgotten. For four labels and two distinct choices, there are 12 descriptions, six groups and two descriptions per group. The repeat preset A/B yields four descriptions and three groups with sizes 1,2,1. Selecting a group highlights its actual preimages; a status line states whether constant-fiber division is justified and why. Include the empty choice, impossible no-repeat length, and deterministic reset. Bounded controls keep enumeration small; show a selected branch/group in detail on phones rather than shrinking hundreds of leaves. Color is paired with labels and connectors.

An adjacent inline unequal-branch tree makes the additive decomposition visible. The learner should see that “choices depend on earlier choices” and “the number of choices varies” are different statements. The group-area layout does not encode probability; a small explicitly fair two-draw table explains the optional probability consequence.

### Stars, bars and bounded allocations

Link an actual allocation tuple, named containers and its star/bar word. Moving a token between containers changes the tuple and the corresponding run lengths; stepping through valid allocations makes the bijection inspectable. Default total five, three containers. Controls add a minimum of one or capacity three and recompute the feasible set. Adjacent bars and end bars remain visible. A state with no feasible allocation is a valid count-zero outcome and does not invent a tuple. Total zero has one all-zero allocation when permitted. The main UI has at least one container; the exported mathematical helper must explicitly handle or reject zero containers consistently. Mobile containers stack without losing the token-to-run correspondence.

### Inclusion–exclusion contribution ledger

Use actual numbered objects and membership marks, not an area-scaled Venn diagram. A selected object exposes its single-set, pair and triple contributions. Start with divisibility by 2,3,4 on 1 through 12: the union count is `6+4+3−2−3−1+1=8`. Object 12 contributes three, then zero after the pair subtractions, then one after the triple term. The learner steps these correction stages and edits a bounded membership board or selects disjoint/empty/overlap presets. Both the exact union roster and the signed total agree. A three-way intersection means membership in all three, never their union. This form teaches why the sign pattern exists.

### Induction coverage and constructive witnesses

Display four base certificates for 18,19,20,21 using token values 4 and 7, followed by arrows adding 4. Select a target and trace a decreasing proof dependency to a supported base; show the recovered token witness. Temporarily hiding a base marks that residue chain **unsupported by this proof**, with a separate independently computed representability result. It must not mark the numbers impossible. Switch to values 3,5 and bases 8,9,10 for a changed transfer. The finite chain visual illustrates the arbitrary symbolic step stated in prose; it is not the proof of all integers. No drag gesture is required to operate the model.

### Balanced-path decomposition and reflection

Each parenthesis is a labeled up/down step with horizontal axis prefix length and vertical axis unmatched-open count. A valid word highlights its unique first-return prefix and the independent subwords A/B; an invalid word highlights the first negative prefix. A reflection operation reverses only the step signs through that first −1, shows the endpoint +2, and an inverse restores the word using the first +1. Counts of all, excluded and balanced words come from actual finite enumeration and the separate formulas. Initial n=3 shows five valid words; n=0 explicitly shows the empty object without a nonexistent first return. Bound n for readable paths, fit the whole small path on mobile, and retain prefix labels and selected-step text. Do not use an arbitrary decorative curve.

### Coefficient construction — optional branch

For three containers, display each finite polynomial as allowed counts, then build the product one factor at a time. Selecting target degree highlights the exact previous coefficients and new factor terms that add to it. Capacities 2,3,1 and target three give contributions three plus three, totaling six. A chosen tuple is the same allocation object used earlier, so the new notation has a visible referent. Zero capacities and out-of-range targets are supported. This is integer convolution; horizontal position means degree, and displayed heights/counts come from the actual coefficients.

### Rotation orbits — optional branch

Draw the binary pattern on a ring with a visible current reference position. Rotate by one site, inspect the distinct images, and highlight the rotations that leave it fixed. The orbit list groups actual labeled strings; the fixed-count table supplies the double-count argument. Default four sites, with period-one/two/four examples available. A marked-start mode changes the definition of an outcome and displays 16 rather than six; it is not an alternative algorithm for the same contract. Controls use buttons and select elements with keyboard access. Reflections are explicitly outside the equivalence relation. For n=0, either provide the separately defined empty-pattern convention or reject it in the bounded ring API; never invoke rotation modulo zero.

### Additional inline explanations

Use a committee-plus-chair pairing to make double counting concrete; tagged repeated symbols to explain a factorial denominator; a small Pascal/lattice-path split with two disjoint predecessors; and an actual input/output capacity sketch for compression. These are compact representations placed before the corresponding abstraction. Their labels define whether items, groups and positions are distinct. A recurrence dependency arrow means mathematical dependence, not elapsed time or an empirical speed claim. This selection may change while writing if a representation fails to improve understanding; record the reason rather than meet a diagram quota.

- Execute every actual program and every promised changed code solution. Reject malformed, noninteger, nonfinite, sparse or out-of-range inputs consistently; do not let array iteration skip invalid holes.
