# Typed decision model: executable research depth

22 September 2026. Scoped extension of the existing project, not publication of its planned companion topic. The original `typed_decision.py` and 600-step result are unchanged. Author verification and independent review are separate.

## Added programs and learner commands

Keep all three Python programs in the same directory. The new scripts import the canonical `typed_decision.py` rather than reimplementing its vocabulary, corpus, target permutation, loss, calibration or decision policy.

```shell
python research_tools.py verify
python research_tools.py trace --output trace.json
python typed_decision.py train --steps 600 --seed 7 --output decision-artifact
python research_tools.py evaluate --artifact decision-artifact --output diagnostics.json
python research_tools.py evaluate --artifact decision-artifact --latency-runs 50 --output timed-diagnostics.json
```

`trace` uses seeded **random** weights and one illustrative SGD update; it is not an inference from the trained artifact. It emits the actual training vocabulary, refund request, token strings/IDs, marker positions, batch padding, token/candidate masks, intermediate shapes, one attention row, logits, loss and parameter update. The separate analytic fixture uses logits `[2, 1, 0]`, target 0, and verifies `softmax(logits) - one_hot(target)` against autograd. This scalar-coordinate update teaches the derivative; it is distinct from a network parameter update.

The canonical refund state is `please help with my refund`: 35 tokens, candidate markers `[8, 15, 22]`. The second batch row has two candidates and the shorter state `refund`. The public `trace-fixture.json` is generated by this command and is the source of the browser trace's expected values.

`evaluate` loads existing weights/config/data, never trains, and never refits temperature. It computes raw/calibrated test and stress diagnostics, semantic-ID confusion matrices, per-case probabilities/unknown-word counts, five equal-width reliability bins, observed risk/coverage/cost and candidate-order/ID-renaming checks. All permutations include the original ordering; actual chosen semantic IDs use the normal first-slot argmax tie rule. Distribution changes are measured after restoring semantic order. Permutation invariance is not assumed. The test labels appear only in diagnostics, not a selection loop.

Reliability means top-choice confidence versus top-choice correctness. Bins include the lower boundary; only the final bin includes its upper boundary. Empty means and zero-coverage risk are `null`, never fabricated zeroes. Policy sweeps assume perfect review at a known cost, zero cost for correct action and wrong-action cost 10. Estimated cost uses model probabilities; realized cost uses held-out labels. Sweeps are diagnostic counterfactuals, not a method of tuning a deployment threshold on test results.

Optional timing measures 50 warm CPU forwards after 10 warmups with one thread and batch size one. It excludes tokenization, loading, serialization, network and queuing. No throughput, GPU, p99 service-latency or implementation-ranking claim follows from it.

## Ordinary library bridge

```shell
python -m pip install "torch>=2.6,<3" "transformers>=4.48,<5"
python pretrained_decision.py verify --output adapter-checks.json
python pretrained_decision.py train --checkpoint ./local-bert-style-encoder --steps 60 --learning-rate 0.00002 --output pretrained-artifact
python pretrained_decision.py predict --artifact pretrained-artifact --input request.json
```

A cached model ID also works. Only `--allow-download` enables an uncached Hub download; add `--revision COMMIT_HASH` to pin an upstream revision. No remote model was downloaded in author verification. A downloaded model can be large and real fine-tuning needs a workload-appropriate device/data plan; the supplied CPU path establishes inspectable mechanics, not economical training of every encoder.

The adapter uses `AutoTokenizer`/`AutoModel`, registers one candidate marker, resizes embeddings, builds explicit CLS/SEP token sequences, and records marker positions by construction. It supports two to eight candidates and rejects excessive length rather than dropping candidates or state evidence. Token padding and candidate padding have separate masks. Unlike the tiny ASCII vocabulary, the tokenizer determines supported language/numeric tokens. Raw input may not contain the reserved candidate marker. This adapter requires a BERT-style bidirectional encoder with CLS/SEP/PAD, not every model supported by AutoModel.

The encoder's contextual hidden states replace the original embedding/attention blocks; marker gathering and the shared LayerNorm/linear scorer retain the same task meaning. Default training updates the encoder and scorer. `--freeze-encoder` disables encoder gradients and dropout, leaving the scorer trainable; newly added marker embeddings are then fixed random embeddings too. Compare this baseline explicitly with full fine-tuning, or design a separately verified partial-unfreezing scheme. For a head-only experiment a learning rate such as `0.003` is a starting configuration to evaluate on development data, not a universal optimal value.

Training reuses candidate shuffling and the constructed 36/18/18 plus three stress examples. It saves the encoder, tokenizer, scorer, decision temperature, format identity, source revision, resolved commit when available, versions and report together. Inference loads all parts locally, validates the format and embedding/tokenizer match, and reuses the canonical cost decision. It is **an implemented train/save/infer route**; meaningful fine-tuning of a real pretrained model remains unexecuted.

Source excerpt boundaries are `# BEGIN` / `# END`: `trace` and `diagnostics` in `research_tools.py`; `batch`, `adapter`, `save_load`, `train` in `pretrained_decision.py`. UI explanations should fetch these canonical programs on demand.

## Actual evidence

- Python 3.12, PyTorch `2.14.0+cpu`; Transformers `4.57.6`, Tokenizers `0.22.2` installed into a task-owned dependency directory. No shared runtime packages modified.
- `research_tools.py verify` and exact native trace generation passed. Evidence: `evidence/typed-decision-depth-checks.json` and public `trace-fixture.json`.
- One new 600-step seed-7 CPU run reproduced every field of the existing `verified-report.json` exactly. This rerun was necessary because earlier temporary weights had already been cleaned; no hyperparameter search was conducted.
- `research_tools.py evaluate` ran on that artifact. Evidence: `evidence/typed-decision-diagnostics.json`; identical learner download `public/learn-projects/typed-decision-model/verified-diagnostics.json`.
- Test confusion rows (true billing/access/delivery) are `[6,0,0]`, `[3,3,0]`, `[3,0,3]`. The 108 test request/order combinations changed chosen semantic IDs in 6 cases; the largest probability change was about `0.998912`. The stress cases changed choice in 8/18 order combinations. Renaming IDs left logits exactly unchanged.
- At wrong-action cost 10 and review cost 1, the raw policy acted on 15/18, made 4 wrong actions, and incurred mean realized cost `43/18`. The calibrated policy acted on all 18, made 6 wrong actions, and incurred `60/18`. This preserves the existing adverse calibration result; confidence is not reliability.
- `pretrained_decision.py verify` passed on a locally constructed random two-layer BERT and WordLevel tokenizer: new marker/resized vocabulary, exact gather positions, variable candidates, padding invariance, encoder/head gradients, optimizer update, exact save/load output, frozen encoder, trainable scorer and rejected invalid inputs. Evidence: `evidence/typed-decision-adapter-checks.json`.
- The retained `evidence/verify-typed-decision-native-depth.py` additionally executed three training steps in both full and frozen modes, calibration, saving, local reload and JSON prediction using a local random one-layer BERT. These are execution checks, not meaningful pretrained-performance experiments. Evidence: `evidence/typed-decision-native-depth.json`, including source hashes.
- The same verifier constructed a random two-layer **ModernBERT** through `AutoModel`, registered/resized the marker, ran a variable-candidate batch and verified finite encoder/head gradients. This checks the relevant architecture's adapter API on CPU, without downloading or fine-tuning pretrained ModernBERT weights.

No pretrained fine-tuning result, Laya reproduction, remote checkpoint, GPU run, live service, RL training or real support-data result is claimed. Browser integration and independent review are recorded by the coordinating task. The independent reviewer separately recomputed the displayed confusion, confidence-bin and policy-cost claims from the retained weights and passed additional native checks. After that all-clear, only the task-owned `scratch/typed-decision-depth-deps` and `scratch/typed-decision-depth-run` directories were removed; retained evidence and source remain. Offline smoke-test temporary checkpoints were automatically removed by their context managers. No shared environment or unrelated scratch files were removed.
