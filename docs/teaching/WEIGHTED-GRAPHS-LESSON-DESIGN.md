## Proposed teaching route

1. Same graph, different objective; weights/units/direction, routes versus repeated walks, source/unreachable and exact integer conventions. Review BFS equal-edge assumption with a three-vertex counterexample.
2. Relax a route, keep tentative upper bounds and recover actual parent-edge identities. Dijkstra physical priority candidates, ticket ties, stale rejection, strict improvement and safe extraction proof. Explain when target early exit is safe and what unprocessed distances mean.
3. Remove nonnegativity: explain the exact failed proof step, edge-budget DP/Bellman–Ford, finite-pass bound, reachable negative-cycle influence and finite witness recovery. Do not call every negative edge a negative cycle or every target in a graph with a cycle unbounded.
4. Optional shortest-path branches: 0/1 deque, all-pairs Floyd–Warshall (and a reasoned reweighting connection if earned), appropriate algorithm/cost choice under actual representation and numeric assumptions.
5. Install a cheapest connecting network. Cut exchange, Kruskal cycle filtering via DSU, Prim crossing frontier, ties/negative edges/disconnected forest, explicit contrast with source shortest paths. Interesting transfer: a minimum spanning tree also certifies pairwise minimum bottleneck routes, while its total-weight objective differs from minimizing every additive route.
6. Order dependencies: indegrees/Kahn with ready-choice nonuniqueness, DFS reverse finish and active-stack cycle witness, blocked residual versus actual cycle. All vertices, including isolated vertices, belong in a returned topological order.
7. Use the order for signed DAG shortest paths and critical-path scheduling. Dependency completion times use max, not a shortest path; unlimited resources are stated before an ASAP-optimality claim.
8. Independent changed-contract exercises, hints/full solutions, curated verified official LeetCode practice and future scope links in actual module order.
