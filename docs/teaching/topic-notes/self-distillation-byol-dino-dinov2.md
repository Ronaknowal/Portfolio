- **Concrete mechanism/example:** for unit patch features in rows of `X`, `XXᵀ` records all pairwise cosine similarities. A shared orthogonal rotation changes feature coordinates but preserves the Gram matrix, whereas changing one feature can alter its row and column. The origin's checked two-feature demonstration gives loss 2 under collapse, and its changed three-feature exercise gives unnormalized squared Frobenius loss 4. Use a fresh case for this destination's practice. Develop how normalized feature matching, common crop geometry, loss reduction and teacher feature-grid alignment determine the actual Gram objective. DINOv3 §4.2 uses an earlier teacher snapshot to anchor dense-feature relationships; its periodically updated Gram teacher is a different state from the ordinary EMA teacher. §4.3 uses higher-resolution teacher features and resizes their grid for alignment. Do not simply label either one “the teacher” throughout a diagram.
- **Practical application:** the DINOv3 report's geospatial canopy-height study maps frozen satellite-image features through a trained dense-prediction head to height targets. It offers a meaningful global-versus-dense evaluation contrast. Introduce target units, geographic/acquisition split and downstream labels before any result. The origin explains the connection but does not reproduce this experiment; a future small openly licensed study or precisely attributed paper result must not be represented as locally executed foundation-model training.

Treat model configuration separately from training objective: DINOv3's ViT recipe uses patch 16, registers and a two-dimensional RoPE construction, while the official release also includes convolutional models. Do not describe every DINO-family checkpoint as an interchangeable patch-14 ViT. Inspect current paper, configuration, code and access/license together before implementation. The origin's actual seven-fit Optdigits experiment trains supervised small models and readouts; it is not evidence of DINO/DINOv2/DINOv3 pretraining.
