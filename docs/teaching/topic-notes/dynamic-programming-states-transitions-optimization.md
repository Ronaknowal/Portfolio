## 2026-09-10 — Teach subset masks before mask-based dynamic programming

- Status: implemented for the finite-subset primer and subset-plus-endpoint state; not resolution of all bit-manipulation ownership.
- Origin: `backtracking-divide-and-conquer`; [individual design](../BACKTRACKING-DIVIDE-LESSON-DESIGN.md) and the [unassigned coverage inbox](UNASSIGNED.md).
- Destination and rationale: this topic can teach how a set of already-chosen elements becomes part of a reusable subproblem key. That gives bitmask encoding a concrete purpose after the current backtracking lesson has made the same set visible as ordinary positions and Python sets. A generic Python-basics insertion would overload first-time programming; an unexplained N-Queens bit trick would hide rather than clarify its constraint invariant.
- Existing coverage inspected: Complexity introduces binary input length and exponential output counting; Python Basics introduces ordinary values/conditions but is not a complete bitwise tutorial. Backtracking's new subset and queen mechanisms deliberately use lists/sets. The narrow live-title search found no dedicated ordinary bit-manipulation owner; no full-catalogue audit is claimed.
- Proposed treatment: before a subset-DP example, teach a finite universe of n indices, bit i as membership, empty/full mask, membership test, add/remove, and subset iteration with a small linked bit-row/set view. Explain bitwise versus Boolean operators, Python integer semantics versus bounded-width representations, and why arbitrary-precision operations have a size cost. Then derive why `(used_subset, endpoint)` or another complete state can merge repeated futures; a mask alone is not always a sufficient key.
- Example benefit: compare two orderings that reach the same chosen subset but a different final vertex. This exposes both useful memoization and the need for an endpoint dimension before the learner sees a compact subset-DP formula.
- Prerequisites/boundaries: indices, finite sets, powers of two, Boolean logic and the backtracking state invariant. Verify actual bit/shift behavior against current official Python documentation and executable tests when changing this primer. The broader selected XOR/count/word foundations now belong to the [Arrays branch](arrays-strings-hash-maps.md), which has completed independent review; this does not imply every specialist bit technique is covered.
- Evidence: scoped local searches and the inspected source locations above; official Python integer/bitwise documentation is the intended implementation reference, not an assertion that a complete mask unit is already authored.
- Resolution: included in the DP lesson's section 7 before the visit-once route recurrence. The linked membership switches/bit row/set and endpoint-dependent futures make the key concrete. Complete Python demonstrates membership/add/remove/toggle, bounded complement, Boolean-versus-bitwise behavior and submask enumeration; source and independent checks distinguish Python integer semantics from tiny browser masks. [Design](../DYNAMIC-PROGRAMMING-LESSON-DESIGN.md), [verification](../DYNAMIC-PROGRAMMING-VERIFICATION.md), [lesson](../../../src/learn/data/topics/dynamic-programming-states-transitions-optimization.jsx). The later Arrays extension now supplies the scoped broader foundations and [independent evidence](../BITWISE-FOUNDATIONS-INDEPENDENT-REVIEW.md); retain this useful local DP application rather than deleting it or reassigning its earlier author's evidence.

## 2026-09-10 — Start from the alternatives greedy cannot discard

- Status: adapted and implemented.
- Origin: `greedy-algorithms-exchange-arguments`; [Greedy design](../GREEDY-EXCHANGE-LESSON-DESIGN.md).
- Destination and rationale: DP is the next module topic and owns state/transition reasoning. The new Greedy lesson teaches exactly why two local rules fail, giving concrete motivation for keeping alternatives rather than introducing an unexplained recurrence.
- Existing local coverage: Greedy implements unweighted interval count and fractional capacity; it explicitly does not claim to solve weighted interval selection or 0/1 knapsack. The counterexamples are computed and independently verified. General DP state construction is not taught by a failed greedy trace alone.
- Proposed examples: (1) A [0,5) value 10 versus B [0,2) value 4 and C [2,5) value 4. Earliest finish keeps value 8 while A gives 10. Define a finish-ordered weighted-interval state, the last compatible predecessor and choose/skip alternatives before writing a recurrence; preserve half-open touching semantics. (2) Weights 10,20,30; values 60,100,120; capacity 50. Fractional optimum 240, whole-item density result 160, true whole optimum 220. Define item-prefix/capacity state and show why a transition consumes an item only once; an ascending in-place capacity loop would silently change reuse semantics.
- Learner benefit: compare the exact old proof's failed exchange with the richer state that retains the lost choice. Show reconstruction, empty/zero boundaries, infeasibility conventions where applicable and storage-compression dependencies. Capacity-based O(nW) work is pseudopolynomial when W is binary encoded; do not label it polynomial in input bit length without qualification.
- Prerequisites: sorted boundaries, include/exclude decisions, complete state keys, induction and the current Greedy counterexamples. The browser's exhaustive small-subset oracle is a check, not the intended scalable DP implementation.
- Evidence: the new Greedy lesson/examples and independent model/native verification; MIT 6.046 interval-scheduling notes and CMU fractional-relaxation notes inspected 10 September 2026. Recheck any implementation-specific complexity and reconstruction policy when authoring.
- Resolution: section 2 now derives finish-ordered weighted scheduling, compatible prefix lengths, skip/take proof and reconstruction; its inline duration lanes retain the exact 8-versus-10 example and the changed value-11 case. Section 5 adds the exact capacity-50 whole-item result 220 and explains fractional 240 versus greedy whole-item 160. The prior item-generation lab already demonstrates the required direction distinction, so no redundant capacity lab was added. Sixteen complete Python fixtures now include weighted scheduling; 300 independently enumerated schedules check values, chronological witnesses, ties, negative values and touching intervals. Official LeetCode 1235 and Princeton's primary weighted-interval material are linked and verified. See the same design/verification/lesson links above.
