# Buffer policy needs a data-loss contract

- Status: open; evaluate at destination authoring.
- Discovered: 10 September 2026 while completing Threads, Concurrency, Locks & Deadlocks.
- Destination: Embedded Processing, FPGA Pipelines and Real-Time Neural Firmware (`embedded-processing-fpga-pipelines-and-real-time-neural-firmware`). Its existing brief already owns producer/consumer buffers, dropped samples and deadline budgets. This note refines that planned investigation; it does not propose another topic.
- Why here: the introductory thread lesson can explain backpressure and contrast an every-sample recorder with a latest-sample display. The actual neural stream's permissible loss, acquisition clock and end-to-end delay require this destination's instrumentation/timing context.
- Proposed treatment: reuse one synthetic sample stream and a deliberately slow consumer. Compare blocking the producer, dropping newest, dropping oldest and coalescing to the latest value. Show occupancy, sample identities, latency and lost samples, not just an average throughput number. Decide which policies can serve a recorder, visualization or closed-loop controller under explicitly stated requirements. If acquisition cannot pause, blocking downstream software is not automatically lossless acquisition.
- Starting evidence: [Python Queue contracts](https://docs.python.org/3/library/queue.html) describe bounded blocking and completion accounting; [OSTEP conditions](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-cv.pdf) supports the producer/consumer mechanism. These do not certify hardware timing. At authoring, obtain current primary documentation for the chosen acquisition interface and buffer/overrun behavior.
- Current bridge: the thread lesson's live-instrument application and bounded validator. It explicitly makes no hard real-time claim. Preserve that boundary.
- Decision needed: include/adapt the comparison within the already planned buffer lab, or explain why the final design covers the same learning hurdle another way. Record sources, assumptions and independent tests here before resolving the note. No destination lesson is authorized by this note alone.
