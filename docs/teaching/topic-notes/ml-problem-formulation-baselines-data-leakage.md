- Idea and learning benefit: learners should distinguish when an event happened, when its value became available, and when a prediction had to be made. A backward match on event time alone can still select a late correction that the deployed model could not have seen.
- Existing coverage: the bespoke plan in `src/learn/data/curriculum/cross-domain-expansion.js`, “ML Problem Formulation, Baselines & Data Leakage,” already includes a data-availability timeline and moving arrivals across the prediction boundary. Introduce a late correction as a second case. Keep deployment/availability semantics in the core explanation; a library-specific implementation may be optional. The existing topic title already fits.
- Explanation/example: reuse the invented calibration scenario. A reading needs a prediction at time 5. A calibration has event time 4 but arrives at time 8. It is recent enough for the original backward match yet unavailable at time 5. Ask which earlier available calibration, if any, should be used. Move arrival time from 8 to 4 without changing event time; require a reasoned prediction before revealing the admissible match. An optional extension gives a later revision to the same event and asks which version was visible at the cutoff.
- Prerequisites and boundaries: teach target, feature and prediction deadline first. Do not equate a database creation timestamp with actual serving availability unless that contract is established. A matching tolerance limits age; it does not by itself encode availability, train/test separation or preprocessing provenance. The Pandas lesson states a simplified immediate-availability assumption and links here.

This is evidence for the distinction, not a claim that all feature stores behave alike. The calibration scenario is an invented teaching example. The origin's simpler matching arithmetic was run under Pandas 3.0.1; the proposed late-arrival exercise and Feast API have not been implemented or runtime-tested here.

## 2026-09-21 — Resolution

Closed. The proposal is implemented and the implementation was independently reviewed.

**The three clocks are taught in order and the note's own fixture is the lesson's.** Section 3 distinguishes when an event happened, when its value became available, and when a prediction had to be made. The note's case — a prediction needed at time 5, a calibration with event time 4 that arrives at time 8 — resolves to the admissible match at value 10, and a preset that moves that arrival from 8 to 4 without changing any event time moves the selected event from 1 to 4 and the value to 20. That is asserted as a property over the whole enterable grid rather than at the single fixture, and it is graded only after a recorded prediction. The optional late-revision extension is the cutoff-7 case. The warning against equating a database creation timestamp with serving availability is in the section prose.

**The accuracy reassessment landed.** The independent review refit the whole study from the served bytes — design matrix rebuilt by hand, average precision summed over distinct thresholds in exact rational arithmetic, both splits' disjointness and stratification checked independently — and found **no numerical disagreement anywhere**.

**One packet claim did not survive and is recorded rather than edited.** The manuscript states that an earlier quantile-regression lesson owns fitting the conditional quantity. No such lesson exists: a search of all 1,499 catalogue entries returns one `/quantile/i` title, a streaming-sketching topic in a different module. Pointing a learner at a lesson that does not exist is worse than saying so, so the page states the position truthfully and routes to *Calibration & Conformal Prediction*, which defines pinball loss, and *Decision Theory*, which carries the identical newsvendor derivation. The frozen manuscript is untouched.

Implementation, independent review ([PROBLEM-FORMULATION-INDEPENDENT-REVIEW.md](../PROBLEM-FORMULATION-INDEPENDENT-REVIEW.md)) and integration are complete, with source hashes and evidence bound in the delivery ledger. This note is closed and authorizes no further work on the pandas topic or any audit beyond the availability contract it named.
