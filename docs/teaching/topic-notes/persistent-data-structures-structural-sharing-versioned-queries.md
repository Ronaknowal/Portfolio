## 2026-09-10 — Historical indexed range answers need version identity

- Status: implemented and author-verified on 2026-09-10; shared integration and user acceptance remain separate.
- Origin: [Segment Trees, Fenwick Trees & Range Queries design](../RANGE-QUERIES-LESSON-DESIGN.md), section 8 of the authored lesson.
- Verified destination: `persistent-data-structures-structural-sharing-versioned-queries`; scoped inventory confirms an existing specialist brief that already owns path copying, shared unchanged subtrees, querying historical roots and branching old versions. No catalogue item or reading-order change was made.
- Current origin coverage: complete mutable segment folds and range add/set/sum lazy trees, but no production historical versions. Bounded teaching snapshots clone arrays and are explicitly distinguished from efficient persistence.
- Proposed treatment: a small point-assignment/range-sum persistent tree, with two old roots remaining queryable after a new update. Draw newly allocated path nodes and identity-shared untouched nodes; return a root per version instead of mutating shared children. Explain partial versus full persistence and old-root ownership before adding optional order-statistic histories.
- Why here: historical identity and lifetime, rather than ordinary sum aggregation, are the new mechanism. The existing destination brief is more appropriate than expanding the already substantial range-query lesson.
- Verification: compare every version and every small interval with copied plain-array histories, branch from a nonlatest root, assert old roots remain unchanged, and count new nodes per point update against tree height. Include non-power-of-two sizes, repeated assignments and empty version policy. A persistent lazy range update would require a separate proof that push never mutates a node still shared by an old version; do not assume the mutable lazy class can simply be reused.
- Source lead: the destination already lists MIT 6.851 persistent data structure lectures. Research the selected implementation and exact guarantees when writing; this note is a teaching handoff, not evidence that the destination is complete.
- Resolution: accepted. The destination now teaches immutable point-assignment/range-sum path copying, exact object identities, branching from any old root, no-op identity reuse, old-version queries and retained-root reachability. It includes the optional prefix-histogram order-statistic extension and a separately proved immutable no-push range-add/sum tree; it does not reuse the mutable set/add push routine.
- Implementation: [lesson](../../../src/learn/data/topics/persistent-data-structures-structural-sharing-versioned-queries.jsx), [native examples](../../../src/learn/data/persistent-structures-examples.js), [visual models](../../../src/learn/data/persistent-structures-models.js), [design](../PERSISTENT-DATA-STRUCTURES-LESSON-DESIGN.md), [verification](../PERSISTENT-DATA-STRUCTURES-VERIFICATION.md). Independent copied-array oracles verify all small intervals and old roots across branches, exact path allocation, non-power-of-two/empty/no-op contracts and lazy carry invariants. The browser uses a true immutable-node arena with distinct root handles; its reachability experiment explicitly does not claim actual garbage collection.
