Program titles and imports were used to locate code, not as proof that it implements a mechanism. Previously executed native evidence is reused only for the stated unchanged programs. “Routes present” means the inspected core has a visible mechanism implementation and an ordinary tool workflow or a justified theory/workflow boundary. It does **not** assert that every named secondary algorithm, input edge, complexity claim, customization exercise and exact library convention has been fully reviewed against the new standard. Rows identify important remaining bounds. “Confirmed gap” names code actually absent from the supplied learner route, not merely absent keywords.

## Focused Feature Scaling repair

The existing lesson accurately explained fitted state and supplied full library/penguin and cross-fit target-encoding programs, but did not let a learner build and match the composed numeric/categorical fit-state mechanism. The new section after section 5 adds the complete `fitted_preparation.py` program, its real output, a fitted-state/API mapping table and a changed-input implementation exercise.

- It uses median imputation, population standard deviation (`ddof=0`), a zero-variance scale of one, sorted categories and explicit unknown-category all-zero behavior. Missing categories occupy a learned reserved category rather than being confused with unseen present values.
- Same training and query rows match SimpleImputer, StandardScaler and OneHotEncoder to 1e-12; fitted arrays match library attributes and remain unchanged under query edits.
- The modified-program practice retains a pre-imputation missing mask, verifies all nine output coordinates, preserves the original six and compares against MissingIndicator with all-feature policy.
- Schema mismatch, all-missing training columns, literal reserved-marker collisions and infinite input are rejected. Overflow raises rather than quietly corrupting fit state. The stated moderate-value reference does not claim to reproduce near-constant precision safeguards, sparse storage, weights or rare-category policies.
- The explanation accounts for numeric transform work and dense one-hot output memory; a vectorized implementation is not called universally optimal. Existing real-data and cross-fit program code/output remain byte-identical.

Native execution: `scratch/lesson-tools/Scripts/python.exe scripts/verify-scaling-examples.py --write` passed all three displayed programs and **37 oracle assertions**. [Native evidence](../evidence/scaling-native.json) binds code/output and verifier. JSX parsed with Babel. Browser, independent review and final production integration remain separately recorded by the integration owner; this report does not convert author checks into those statuses.
