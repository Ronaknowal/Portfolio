## Quality and reuse decisions

“From scratch” starts above an explicit primitive boundary. Using arrays, arithmetic, a heap primitive or a linear solve is appropriate when those operations are prerequisites rather than the mechanism under study. Reimplementing an interpreter, database engine, rasterizer, operating-system kernel or BLAS would obscure the current lesson. A theorem can be taught through a derivation, construction, counterexample and finite witness without inventing a library API for it. Finite enumeration remains separate from a proof over every input.

For applied algorithms, a documentation link or a framework import in a private verifier is not a learner-facing library route. The useful pairing is a complete visible implementation and a normal tool applied to a genuinely matched task, with differences explained. Compare invariants and meaningful results: valid paths/certificates rather than tie-dependent order; subspaces/reconstruction rather than singular-vector signs; partitions modulo labels; posterior functionals with numerical precision rather than identical random draws. Changed practice should require adapting the implementation or API contract and explaining the consequence.

The user's high-quality/optimal criterion is interpreted through a declared objective and cost model. Audit invariants, supported shapes/data, edge/failure cases, asymptotic time and auxiliary/output storage, numerical conditioning/stability, and reasonable implementation choices. A small transparent loop is a reference, not a claim to beat a tuned library. No new benchmark or universal optimality claim was made. In the inspected LU program, pivoting swaps previous multipliers as well as rows, factors are reused for multiple targets, and cubic factorization versus quadratic solves is taught. In Einsum, a non-square triple loop checks the actual contraction and output reordering. In numerical methods, bracket status, cached samples, finite evaluation budgets and arithmetic stagnation are visible, and the error estimator is not presented as an unconditional guarantee. These are concrete examples of strong depth, not certificates for all sibling programs.

Useful reusable owners remain explicit: Python functions/iteration for later programs; NumPy coordinates/vectorization for numerical work; heaps/queues and graph construction for graph algorithms; matrix decomposition for stable linear-algebra primitives; Numerical Methods for finite-difference/quadrature/root contracts; Backpropagation for actual JVP/VJP/autograd use; ODE/Numerical PDE for numerical evolution. A receiving lesson should link and adapt those mechanisms rather than copy an entire prerequisite or silently assume it.

## One bounded repair completed

NumPy's original coordinate explanations and vectorized programs did not provide a learner-visible scalar-loop implementation of the same broadcast/reduction. Added `loopReference` in [numpy-foundations-examples.js](../../../src/learn/data/numpy-foundations-examples.js), rendered under §5 in [the lesson](../../../src/learn/data/topics/numpy-arrays-broadcasting-vectorization.jsx), and extended §10's gain-calibration practice. The complete example compares nested coordinate loops with a reusable `calibrate_sensor_means` function using NumPy broadcasting and `mean(axis=0)`. It states the finite, nonempty rectangular input contract, preserves source arrays, uses tolerances, and explains O(TS) arithmetic/output storage and O(S) means. The ordinary array route is presented as the practical implementation; Python loops expose how coordinates contribute. Extreme finite magnitudes and summation-order rounding remain declared numerical boundaries.

Executed the entire new displayed program in Python 3.12.14 / NumPy 2.3.5 and matched its output. Additional checks use a changed 2×3 table with signed offsets, unchanged input/independent result storage, a one-cell zero case and seven invalid contracts. Body/examples parse with Babel. [Native and source evidence](numpy-repair.json), [reusable verifier](../../../scripts/verify-numpy-implementation-depth.mjs). Shared build, generated metadata, browser integration and independent review belong to the integration owner; this receipt does not claim them.
