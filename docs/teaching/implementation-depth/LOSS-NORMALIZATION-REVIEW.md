## Correctness and implementation quality

The loss functions visibly compute their objectives and input derivatives using NumPy array operations. PyTorch loss/module APIs are confined to the reference route. Mean reductions are reflected in every returned derivative. Stable multiclass CE subtracts row maxima and computes log probabilities without first rounding a probability to zero; its gradient subtracts the correct-class mass without allocating a separate one-hot matrix. Focal loss differentiates its modulation factor and retains both log tails, including correctly and incorrectly classified logits of magnitude 1000. The squared-triplet distance and inactive hinge are distinguished from the default unsquared triplet objective. InfoNCE differentiates through both feature normalization and candidate CE. The affine classifier comparison copies the same parameters, transposes the weight convention explicitly and compares an actual SGD step.

The normalization VJP includes the direct, mean and variance paths. The RMS branch removes only the mean path. Epsilon remains present through the cached normalized values and inverse scale; the rule does not assume unit variance or zero epsilon. GroupNorm's reshape changes collection membership without inventing a different derivative. Affine scale and shift gradients reduce over the positions sharing each parameter, while input normalization reduces its own axes. The explanation explicitly separates current-input training statistics from the evaluation derivative through fixed running statistics.

These are appropriate high-quality implementations for their declared teaching scope: vectorized arithmetic, direct VJPs rather than dense Jacobians, bounded allocations, preserved reduction/shape contracts and relevant failure/numerical boundaries. Dense CE costs O(NC); normalization costs O(M) for M elements; full paired InfoNCE costs O(N²D) arithmetic with O(N²) score storage. The manuscript correctly distinguishes score blocking/recomputation that preserves the objective from negative sampling that changes it, and distinguishes an inspectable NumPy routine from fused production kernels. Neither the source nor this review establishes universal runtime or memory optimality, arbitrary finite-range robustness, GPU/mixed-precision equivalence or performance on unlimited candidate sets.

## Findings resolved by the author

1. **InfoNCE normalization contracts differed near zero.** The scratch implementation normalized every nonzero vector exactly, while the reference used `F.normalize`'s default norm floor. For q = k = `[[1e-14, 0], [0, 1e-14]]`, the scratch loss was 0.006715348489117967 and the original reference loss was 0.692897211809945. The author set explicit `eps=0` in the reference and stated the no-floor, nonzero representable-norm/intermediate contract in both code and prose. The new independent probe checks value and gradient under that matching contract.
2. **Quantile corner behavior needed an explicit convention.** The scratch rule chooses zero at a zero residual. The composed `torch.maximum` reference can select another valid subgradient (−0.2 at quantile 0.7 in the tested runtime). The lesson now explains that gradient parity uses nonzero residuals and that equal corner values need not produce equal updates. No derivative formula was changed merely to conceal the valid convention difference.
3. **BatchNorm evaluation wording omitted epsilon.** Replaced the loose “stored standard deviation” phrasing with the actual divisor `sqrt(running variance + epsilon)`. The training VJP is explicitly inapplicable to fixed-statistic evaluation.
4. **Independent extension answers were immediately visible.** Both new tasks now have separate closed Hint and Worked solution disclosures in the manuscript and generated body. Root's production browser pass owns their rendered behavior.
5. **The earlier snippet verifier had a stale count and wrote outputs before checking.** It still expected three snippets after the additions created five. The author updated the expected count/positions, added numerical checks for new CE and normalization snippets, and stages output writes until the assertions pass. Its current [five-snippet receipt](../evidence/loss-normalization-snippets.json) was inspected; this reviewer did not run the stale version or overwrite its old evidence.
