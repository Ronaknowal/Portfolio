What the file contains
----------------------
731 consecutive calendar days, 1 January 2011 to 31 December 2012, of recorded
Capital Bikeshare rentals in Washington, DC, with the provider's weather and
calendar columns. The lesson uses only the date column and `cnt`, the total
recorded rentals. The unchanged provider description is retained with the
content packet at
docs/teaching/drafts/time-series-validation-forecasting-baselines/source-description.txt

What the target is, and is not
------------------------------
`cnt` is the number of rentals the system RECORDED. It is not unmet demand, not
the number of bicycles a station needed, and not a causal effect of weather. The
file carries no report-arrival timestamps, so this lesson states an explicit
replay assumption: each day's count is known at the end of that day. A
deployment whose counts arrive later needs a different availability rule, and
the lesson's reporting-delay investigation exists to show what changes.

Ownership
---------
This lesson serves its own copy of this file. No other lesson's directory is
read, and this copy must not be read by another lesson: a path that works today
would silently follow someone else's edit tomorrow.

The complete author program is served beside it as forecast-experiments.py. It
writes the packet's calculated-inputs.json and downloads nothing.
