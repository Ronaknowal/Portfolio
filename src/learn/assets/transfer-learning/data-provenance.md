# Data and calculation provenance

The included digits-400.csv is real data from E. Alpaydin and C. Kaynak's UCI Optical Recognition of Handwritten Digits (1998), DOI [10.24432/C50P49](https://doi.org/10.24432/C50P49), [UCI entry](https://archive.ics.uci.edu/dataset/80/optical+recognition+of+handwritten+digits), distributed under CC BY 4.0. Retain attribution when redistributing. It is not MNIST.

This is a byte-identical copy of the Perceptrons packet's licensed extract: SHA-256 a5b50ff0418e2b470140153a399c9200b2bba68468232507fd393ba89c4fc672, 61,444 bytes. The inspected extraction used scikit-learn's 1,797-row load_digits copy of the historical UCI test partition. It selected the first 40 occurrences of each digit and concatenated them by digit. source_id is the original one-based source row; pixel_0 through pixel_63 are row-major 8×8 integer values 0–16; digit is the original label.

This packet uses a distinct source/target partition. Digits 0–4: first 30 per digit train the source model; last 10 are a descriptive source holdout. Digits 5–9: first 8 per digit train target candidates; next 12 validate them; last 20 evaluate only the selected candidate. All 400 source IDs occur exactly once across these five partitions. They are saved in calculated-inputs.json. This is not the official UCI evaluation protocol, a random split, a chronological claim or an unseen-writer assessment. Writer metadata are not available here. Fixed row blocks can differ in difficulty.

Actual author execution used Python 3.12.14, torch 2.14.0+cpu and NumPy 2.3.5 on 12 September 2026, with one PyTorch CPU thread. Three independent source initializations, seeds 1/2/3, train 64→32→16 tanh backbones with a five-output source head for 400 full-batch Adam updates at .01. Each is adapted by six named methods for 300 target updates. Every within-seed comparison preserves the target head, target rows and copied source/original backbone appropriate to that method. Head initialization seed is 100+seed; adapter initialization seed is 200+seed. Learning-rate groups are recorded in the complete program and manuscript; there was no result-driven retuning.

The final seed-1 validation CE selects one method with listed-method-order ties. Seed 2/3 validation sensitivity records do not change that rule. Scratch wins; its exact no-refit checkpoint gets 77/100 target test rows correct with CE .7571012378. Only its test probabilities are retained. Source-head before/after results describe retention and were not used to select the target method. The weak transfer results and large validation/test gap are retained and explained.

The 18 candidate fits, three source traces, sparse sampled target traces, losses/counts, LoRA merging differences and state round trip are actual outputs. No elapsed-time benchmark, full-epoch curve or performance prediction for a different architecture is supplied. The memory examples are explicit byte calculations, not measured allocations.

Small synthetic mechanism fixtures are mathematical inputs separate from the real handwriting experiment. LoRA initial/changed/null gradients, frozen input-gradient transmission and BatchNorm train/eval state changes were executed. The changed practice calculations and byte counts were checked in a bounded author probe. After extending the mechanism fixtures, that function alone was rerun and replaced the JSON mechanism field; unchanged full-fit results were preserved. No additional model search was performed.
